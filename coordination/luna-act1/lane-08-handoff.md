# Lane 08 — skill animation and effect placement

Updated `port/android-native/app/src/main/cpp/source_campaign_fx_v77.cpp` so campaign FX `anchor_position` follows the original `GameObject::GetTargetPosition` selection. Character anchors now borrow the same registered `WorldTargetActorBorrowV1` through the existing `CharacterWorldRuntimeV1`; generic object anchors read the same base fields. Both paths select cached absolute position only when target node `+0x180` and enable byte `+0x80` are set, otherwise they use world position `+0x160`. Missing source fields remain explicit failures. This fixes campaign skill/effect attachments drifting to actor origin when a target node is active.

IDA evidence: `0x3935dc` (`GameObject::GetTargetPosition`) returns `this+0x184` only when `[this+0x180]` and `[this+0x80]` are nonzero; otherwise it returns `this+0x160`. Original assembly shows these loads/branches directly. `0x492aa0` (`AnimatedFX::SyncIrrData`) calls that method at `0x492afc`, then adds the effect's local offset before positioning. The Character registration projection maps `position`, `cached_target_position`, `target_node`, and `target_enabled` to those same source fields; generic object access uses the corresponding canonical base projection. Anchor borrows and pins remain scoped to the synchronous FX service call.

Existing shared wiring is retained: animation-step FX uses the live `PlayerSkillsRuntime` and `CharacterMeshFxOwnerV4`; hit FX routes through `combat_fx_application` with the actual `CombatResult`; FX frames use the submitted camera and current frame time/delta. Source ownership and camera/resource teardown remain with the current player/world owners. No new renderer, manager, or actor authority was added.

Root integration needs no new interface. Keep the existing runtime callback and frame wiring in `model_renderer.cpp` and preserve the source FX manager-before-Scene teardown order. No build, tests, emulator, or runtime verification was performed per lane constraints; this is a source correction, not proof of playable skill/effect behavior. Existing support is limited to the FX resource families handled by `CharacterAuthoredResourceFactoryV6`; unsupported reached families still fail explicitly.
