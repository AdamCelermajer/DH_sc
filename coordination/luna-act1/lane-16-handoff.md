## Actual remaining integration gap: checkpoint reload and death recovery

The source adapter has regular `LevelSavegameRuntimeV1::load()` / INFO+OBJS loading and checkpoint validation, but no operation that selects a checkpoint filename, invalidates/reloads its cache, and restores the normal Level filename. `PlayerSaveLoadOwnerV1` has regular selected-profile loads and `CampaignSaveProfileV45::source_filename_store_v83`, but no scoped checkpoint switch + cache reload + normal filename restoration for the same profile. No active source caller implements `Level::LoadCheckpoint`.

IDA export and original ARM assembly/callers identify the required sequence:

- `Level::LoadCheckpoint` (`0x3f0428`) sets Level+244 guard; if LevelSavegame exists, calls `LevelSavegame::LoadCheckPoint` (`0x46259c`) with the current seed/difficulty/row, then `GameEventManager::ReInit`; it gets actual local Player 0 with active lookup, calls Character `SG_LoadCheckpoint(16)`, calls `SG_Update(1)`, and clears the guard.
- `LevelSavegame::LoadCheckPoint` chooses the `_single`/`_multi` checkpoint filename from online/hosting/PM+719, swaps the same Savegame filename, invalidates its file cache, calls regular `LevelSavegame::Load()` (INFO then OBJS), then restores the regular Level filename.
- Character `SG_LoadCheckpoint` (`0x3bc4bc`) dispatches to `PlayerSavegame::SG_LoadCheckpoint` (`0x465450`). That selects the same online checkpoint policy and selected Save slot, swaps that profile’s filename, invalidates its cache, performs the source SG_Load mask 16, then restores the regular profile filename.
- `PlayerManager::ReviveLocalPlayers` (`0x37565c`) calls current Level `LoadCheckpoint` only on the offline branch, before Character `Revive` and idle state. `_HandleGlobalDeaths` (`0x375af0`) also calls Level `LoadCheckpoint` in its local-host global-death branch. Character `Revive` (`0x3a59ac`) alone is not the checkpoint reload.
