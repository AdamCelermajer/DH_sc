This is a **suspect trace point only**; no runtime evidence yet says a lock is set or stale during the reported sequence, and the source lock owner/admission must be traced before any change. Root’s raw source audit confirms `ReviveLocalPlayers` 0x37565c / `Character::Revive` 0x3a59ac does not blanket-clear controller byte+8 or `v2Controller::s_blocked`; do not add such a clear as an assumed revive rule.
