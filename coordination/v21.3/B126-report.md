### Logic evidence

Reused raw decompilation `.local-inputs/ida-apk-export-2026-10-07/libraries/libDungeonHunter2.so/pseudocode-all.c` and the reviewed DESPAWN2 handoff in B092:

- `Character::HitFor` at `0x3a8bc4` first returns for source `IsDead` (byte 5193). The God_Monster, online/player ownership, and local-player/sound-owner branches decide whether the passed damage changes property36; OneShotKill may then force property36 to zero. Only the resulting `property36 <= 0` branch writes zero and calls `v2Controller::Cmd_Kill`. `Character::Ctrl_Kill` at `0x3ad528` separately returns if `IsDead`; otherwise calls `Character::Kill` at `0x3a5b18`, then raises event 2. Therefore HP reaching zero in the port is insufficient evidence that the original lethal transition ran; duplicate kill requests are also gated.
- `CharAI::OnDied` `0x3d1000` performs callbacks then `AI_SetDead` `0x3d6cdc`, clearing target/attack state and selecting Dead. `SM_SetDeadState` `0x3c58c8` selects the Died variant/stance and enters/forces state 12 or sends event 50008. Injury/interact admission and the source state transition are separate from damage acceptance.
- `CSDead::OnFocus` `0x3c4d50` and `CSDead::OnEvent` `0x3c4c3c` govern corpse timing and physical removal. Event 34 removes the body and starts `Despawn_Delay` (source CharacterDesign 2000 ms); the no-pending-animation focus path starts the same timer immediately. State registration maps Dead(12), event 46 to Despawn(2). `CSDespawn::OnFocus` `0x3c32fc` selects no authored clip in this APK; `OnBlur` `0x3c3794` clears player target and deletes summoned/non-respawnable actors or sends authored respawnable actors toward Limbus. Existing source notes also identify `CanRespawn` `0x3a5248` and `GetRespawnDelay` `0x3a4bac` as additional gates.
- Existing port production path: `CombatSystem::consume_marker` admits only the current attack generation/cycle, a unique authored damage marker, valid live pair and in-range target before resolving damage (`combat_system.cpp`). `ActorCombatRuntime::handle_applied_hit` starts the bound Died pose only on `DamageEvent.target_died` (`actor_combat_runtime.cpp`). Main `despawnTick` admits actual `actor->is_dead()` rather than HP zero; it waits for the retained death pose's `current_ended()`, releases physical body, advances the source delay, then hides/releases or schedules authored respawn (`main.cpp`, `features/despawn/despawn_after_death_v1.cpp`). The B092/B098 fix additionally recognizes a successfully restored source-dead actor and retires it directly; B118 reconciles already-free summoned slots during restore. These restoration-only branches do not run when a newly killed actor has no recorded lethal hit/death state.
