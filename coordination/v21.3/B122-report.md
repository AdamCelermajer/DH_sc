## Finding

There is no single missing-sample explanation for the broad report. The current source has one retained `RuntimeSessionAudioV1` → `RuntimeAudioHostV1` → one recovered V42 mixer/WinMM output. Gameplay audio is constructed only when `--audio` is passed (`main.cpp` around 3600); without it, script sound callbacks deliberately become silent no-ops. The accepted v21.1 launcher passes `--audio` and mounts `audio-assets` through both `startup.args` and `swamp.args`, so omission is a risk for direct diagnostic invocations, not the normal accepted launcher. With audio enabled, exact source calls can be admitted, loaded and submitted through that route, but those are separate facts. The old ledger and the later URI census describe package availability, not caller use; each reported audio gap must be tied to an active source call before it is called a production bug. A decoded sample, command submission, and a WinMM started receipt prove different steps; none alone proves audibility.
