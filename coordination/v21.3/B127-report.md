## Original selection, interaction, and admission logic

IDA export: `.local-inputs/ida-apk-export-2026-10-07/libraries/libDungeonHunter2.so/pseudocode-all.c`.

- `Character::UpdateObjectOfInterest` **0x3abb9c** refreshes every 500 ms. Its caller constructs `TargetList(owner, 1, 0, 1)`, searches within `CharacterDesign/OOI_Distance`, and uses `_sortFrontal`; the list's mask is 89 (`0x59`) at lines around 126080–126180. Thus combat enemy selection and talk-marker OOI admission are both possible consumers, with source ordering/refresh behavior that a one-frame still cannot prove.
- `TargetList::Search` **0x4a2f34** checks candidate existence, not-self, byte+138 enabled, zone state (`IsZonable` virtual+196 plus bytes+750/+752), then `IsInteractive` virtual+136 before the character mask. A quest marker by itself cannot bypass these gates.
- `TargetList::_IsCharacterValid` **0x4a1ab8** applies mask `0x01` only when the candidate is not dead (virtual+52 == `IsDead`) and `AI_IsEnemy(owner,candidate)` succeeds; cross-player checks follow. Mask `0x40` separately admits the candidate when `Character+762` is set. It is not valid to infer combat admission from a blue marker or from brown art.
- `Objective_TalkToNPC::Register` **0x47db34** sets `Character+762` for the NPC whose CharacterTable row matches the objective's oid; `Unregister` **0x47dbc4** clears it. Marker installation/removal is **0x47d8e8/0x47da6c**. `Quest::SetState` **0x480c78** controls available/active/completed objective registration (state 3/6/9 in the existing B088 audit). A blue marker therefore needs its exact marker producer and quest stage identified before it can be treated as proof of TalkToNPC registration.
- `Character::GetInteractionType` **0x3a47e8** distinguishes enemy (8) from friendly NPC (3); `Character::Interact` **0x3a4d78** raises `TalkToNPC` and related events. HUD `Update` **0x41a780** selects `Cmd_UseOOI` when an OOI exists, otherwise `Cmd_Attack(null)`; `UseOOI` **0x3ad614** has no current attack target and idle/moving admission. These callers make the displayed action/context state relevant alongside target-list filtering.
