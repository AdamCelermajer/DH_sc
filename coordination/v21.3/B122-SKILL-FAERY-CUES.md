## Minimal private patch/API proposal for integration

Keep the two cues adjacent to their page-action owners; do not put them in generic state mutation or the audio mixer.

1. **Skills:** add an optional one-shot `after_train_release` hook to `RuntimeSkillsMenuV1` (or the equivalent registered page provider) and bind it in main to `runtimeAudio->play_named_ui_sound("MenuSpending", error)`, logging exact ordinal, UID, token, status and frame. Fire it once after an admitted `HitKind::train` calls `page_.train()`, even when the replacement native-equivalent trainer reports no state mutation: the source callback is void and the SWF runs its post-call cue without testing a return. Do not fire for no hit, no selected skill, a failed source admission probe, wrong page, or an unavailable/locked/capped/no-points control that never reaches the authored add release. Keep the existing selected-row, class, level, point, and cap checks intact. Do not attach to skill-row selection, skill-slot assignment, Stats point allocation, or modal Yes/No.
2. **Faery:** add an optional post-`activate_slot` event hook to the Faery provider/host, bind it in main to `play_named_ui_sound("MenuSelect", error)`, and call it once after the provider passes its same-owner/known-row/FaeryList/unlock checks and invokes the source selection callback. Keep it after the source callback's selection/HUD continuation. Match the source's unconditional post-callback behavior if an admitted callback reaches a refused/failed mutation path; audio failure must not veto selection. Do not fire for a locked-slot release, outside click, stale session/owner, invalid FaeryList, unregistered page, or a release that never invokes the selection callback. A repeat release on an unlocked currently selected Faery remains a new authored release and gets one cue.

These are API recipes only; shared main and integration feature files remain with the lead. The cue helper must preserve the original distinction from plain Play: use the named UI/PlayMenu route, not `play_named_plain`. Do not fabricate default unlocks or skills to make test cases reach the controls.
