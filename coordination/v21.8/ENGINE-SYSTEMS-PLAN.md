## ES-STATUS: monster/character status states
Engine functions: `SetStunState(ms, flag)` (Character::_SetStunState 0x3b9580 -> SM_SetStunState 0x3c5ffc: IsBoss gate, timer id 43, state flag, stun clip from CharAnimTable, event 50012), `SetScareState` (0x3b96b0 -> SM_SetScareState), `SetKnockBackState(bool)` (0x3b7680; great bank selection), `IsBoss` / `IsMiniBoss` (0x3a3158 / 0x3a3144 = CharAI flag word +20 bits 2 / 1), and the outcome tail of `SkillCombatRoll` / F_ApplyResult (0x3b10b4): which outcome bits (0x40 stun, 0x80 push, 0x100 slow) call which state, plus the CHANCE UNITS (decoded stun/push chances exceed 100, e.g. 80+5L, 185+4L: find the compare in the roll code). Port gaps: B165 (stun/knockback state for player skills; JumpKick 0x80 and ViciousStrike 0x40 are rolled and logged but do nothing), `features/combat/b035_session_push_effect_v1` (existing push consumer), monster AI state machine. Users: Vicious, JumpKick, Warcry/Intimidation, Berserk, WhirlingDrift, GrapplingHook, PinShot, Figments, Mirror, Shield, DeathClaw, Contaminate. Integration test skill: ViciousStrike stun and JumpKick push actually change monster state (animation + inability to act for the duration, boss immune).

## ES-RUNTIME: skill script runtime services
(1) External-owner REGISTRY (today a single `external_owner` slot; `main.cpp` assigns the Mage owner to every cast): several owners consulted via `handles(profile)`. (2) General skill timers: `StartSkillTimerCB` / `StopTimerCB` semantics (one-shot + repeating + cancel + expiry callback, keyed by skill/owner; natives `Character::_StartTimer` 0x3b7590, `_StopTimer` 0x3b7064; Lua side in `skills/_commons.luac`); the Mage owner has an ad hoc clock (`RuntimeMageSkillOwnerV1::advance`) that should be generalised, not duplicated. (3) Death-watch / IsDead query on tracked ActorIds (Pestilence poll, Rise). (4) Skill cleanup hook (`RegisterSkillEx` cleanup; find the original caller of OnSkillCleanUp). (5) Delayed callbacks: `OnDelayedSkill`/`delayed_check` landing for projectiles via the executor `launch_skill`. (6) Per-`do_skill`-marker re-entry of Use (volleys: Berserk, MultiHitArrow) with per-volley class token and target policy (coordinator ~1313-1381 has per-marker volleys already). Users: Archer five actives, Necromancer FireSkullRain/Pestilence/Rise, Berserk, Paladin auras, Illusionist Terror/Disciples expiry. Integration test: a timer-driven repeating skill (FireSkullRain-style tick, max 3) runs through the registry with a non-Mage owner.
