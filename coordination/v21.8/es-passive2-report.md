## Real bug found and fixed (CarrionEater)

First live run (case c1): the heal worked on the HUD numbers but the kill reward failed: `Source death reward diagnostic: Live ActorState vital could not be applied to its source property`, `xp=0`, `xpRecipients=0`. Cause: `carrion_kill` wrote `sheets.resolved[HP]` directly; HP is a saved-based property (the death-reward code and the Celest/potion code comments say a direct resolved[] write is recomputed away), so the reward's HP sync from ActorState (`synchronize_live_vital`) could not reconcile. A second attempt that took the HP from the property sheet gave `hp=104.852->166.797` (property was stale: combat damage reaches the live ActorState first). Final code (`features/generic_skills/event_passive_owner_v1.cpp`): heal = `min(max_health, actor health + TempProp1/256)`, published with `PlayableActorWorld::set_current_health` (moves the saved cell with the resolved cell). Added `take_carrion_heals()` so the host logs `Carrion Eater heal frame= rank= hp=a->b heal=` (new line in `main.cpp`). Tests (`event_passive_owner_v1_tests.cpp` section C): heal events record before/heal/after, the HP property follows the actor, and the heal starts from the live actor HP when the property lags by 4.

## Delivery path (why the observer fires)

The observer is installed on the CombatSession and called at the top of `ActorCombatRuntime::handle_applied_hit` for every applied hit (melee markers, source hits, projectiles, misses and hits received), in `main.cpp` queued and dispatched to the bus right after `combatSession->update`. Real run proves the melee-marker path (`attack_mainhand`/`attack_offhand` markers, `Damage frame=... marker=...`). Not run in this report: a Rogue skill hit (source hit path) and a Mage projectile hit; both go through the same `handle_applied_hit`.

## Defender-side passives: what is still missing

Read from the original Lua (`scripts/skills/prince_archer_precision.luac`, `prince_archer_sidestep.luac`, `prince_paladin_shield.luac`, `prince_illusionist_mirror.luac`, `prince_illusionist_petrify.luac`):

- Delivery of "I was hit" events already works: the bus gets every hit with `target == player` (the lizard lines above), and the listener role check (`defender:GetID() == GetID()`) is the same as in the Lua. What is missing is the OUTCOME, per passive:
  - Mirror (Illusionist) / GuardianShield (Paladin) / SideStep (Archer, "deflection"): on being hit, if `attacker:TargetInMeleeRange()` and `GetRand(0,100) < STUN/KNOCKBACK chance` then `attacker:SetStunState(DURATION,true)` or a knockback of the attacker. Needs (a) a stun/knockback state on monster actors in the host (carried from skills-a and act1rogue: JumpKick push `outcomes=0x80` and Vicious stun `0x40` are rolled but have no host state), (b) an attacker-in-melee-range predicate for the passive listener (the CharAI melee-range query exists for the attack path, not exposed to the listener), (c) the per-skill chance/duration from the `SkillTable` TempProps (read through the same `SetTempProps(CLASS_ID, slvl)` evaluation used by CarrionEater).
  - Precision (Archer): attacker side, on a player hit `HasBow()` creates the stat buff Skill_Archer_Precision, removed by a 1 s timer when the bow is gone; the 25/08/2010 note adds a weapon stun chance (needs the same stun state). Needs a `HasBow` predicate for passives (the port has `query_bow` in equipment, not wired to the event owner; IDA `Character::_HasBow` consumers are only `GetAnimStance`) and a 1 s skill timer.
  - Petrify (Illusionist): attacker side, buff on the TARGET (`target:CreateBuff(CLASS, 0, 5, slvl)` lowering Damage_Min_Main_Hand, boss/miniboss floor 30, others 10). Needs timed buffs on monster actors (the timed buff owner is player-oriented) and `IsBoss/IsMiniBoss`.
  - KillingFrenzy's `CanAttackInMelee` gate (every player hit counts today) is still not implemented.
- None of these were attempted here; the task limit was real-hit verification of the event path.
