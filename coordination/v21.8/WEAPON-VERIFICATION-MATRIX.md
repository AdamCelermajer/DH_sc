## 4. Sounds: how a sound id resolves to a WAV (verified rule)

**Rule.** Every sound id in the weapon paths (AnimStep.Sound, ItemTable word5 SwooshSoundFX, the CharSounds
death/hit/impact lists, ProjectileTable impact fields, and the name of an authored `sfx_` clip event) is a
**source id = row index in the 638-row `Arrays::Sounds` stream** `sdd_dungeon_hunter_2_iphone_pyarray.bin` (+ `...names.bin`).
It is not a soundpack uid, not a CharSounds row index and not an index into the legacy 183-row `sounds_pyarray.bin`
array. Each row is `(uid, isEvent)`:

1. `isEvent = 0`: `uid` is a `<sound uid=...>` in `sounds.xml`; the file is `data/sounds/<filename>` exactly as spelled
   (no `_22`/`_44` or near-name substitution).
2. `isEvent = 1`: `uid` is an `<event uid=...>` in `sounds.xml` (type `random`); one member sound uid is chosen with the
   shared gameplay Random, then rule 1 applies.
3. id `< 0`: no sound (`Play3D` returns at `cmp sl,#0; blt`).

Original evidence (libDungeonHunter2.so, sha256 36498eb8...): `VoxSoundManager::Play3D` 0x36b5d8 computes `row = Sounds + 12*id`,
reads uid `[row+4]` and flag `[row+8]`; flag 1 branches to `PlayEvent` 0x36b420, else `PlaySoundPackSound` 0x36a7c0 (disassembly:
`port/engine-audio/reference/event-families-v38/0036b5d8.asm`, `0036b420.asm`). Callers: `CharAnimator::_SetAnimStep` 0x3ca79c
passes `step+0x2c` (AnimStep.Sound) to Play3D at 0x3ca8e0; `_PlayItemSwooshSFX` 0x3c94b8 passes `Item+0x14` (word5) at 0x3c953c.
The stream/name/uid/event binding is the one proven by `port/engine-audio/reference/source-bindings-v38/` (Unicorn-executed original
readers); this script re-parses the stream and cross-checks all 638 rows against that `ledger.json`: 638 agree, 0 differ.
Live IDA/REA was not available in this session (rea reports no configured provider for ELF/ARM); the evidence above is the
committed original-instruction disassembly and proofs for the same binary hash, re-read, not a fresh decompile.

**Namespace correction.** Earlier versions of this matrix looked the ids up as soundpack uids and concluded that
478-482 were ambient music (soundpack uid 478-482 are music rows). That was the wrong table. Source ids 478-482 are
`sfx_mage_staff_elemental_{earth,fire,ice,lightning,wind}` -> uid 31,29,30,33,32 -> all `sfx_mage_staff_elemental_thunder_22.wav`
(the authored XML points all five at the same clip; the element-specific WAVs `sfx_mage_staff_elemental_{earth,fire,ice,wind}.wav`
exist in the package but no XML row references them).

**Swing selection (AnimStep with the Swoosh flag), `_SetAnimStep` 0x3ca884-0x3cab20 / `audio_animation_swoosh_v38`:** without the Swoosh
flag the step sound plays. With the flag, the main-hand item word5 plays first (if not -1), then the off-hand item word5
(only if the main one was -1); the step's own Sound is then ALSO played when the sound-fallback flag is set. The flag is
re-assigned by the off-hand FX query when the main item has no FX (word6 = -1 on every weapon), so for all weapon items the step
sound always plays, and a staff/wand plays its element sound plus the step sound (the staff step sound is -1, so just the element sound).
Port: `runtime_attack_sound_v1.cpp` reproduces this literally; `runtime_audio_host_v1.cpp:151,166` resolves the id with
`bindings().row(id)`; the event/uid selection is `audio_gameplay_runtime_v42.cpp:15-30`.
