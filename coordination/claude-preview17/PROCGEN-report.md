Branch `p17/procgen` (worktree `DH_wt/p17procgen`, build `DH_wt/build-p17procgen`), started from `p17/transitions` at 6647a745. Not pushed.
Commits: 5859416d (generator import, wrapper, isolated test), 455b0499 (EXE wiring, seed in the profile, floor placement), 0959762e (Swamp to witch cave exit enabled, authored-read fix), 97d89faf (coverage tool), a4b0b510 (menu start takes the profile seed).

## Result in one paragraph

Procedural levels run in the Windows EXE through the same loaders as fixed maps. A `.rule.xml` is generated per session by the canonical generator (`port/level-loader` procedural_*_v1, now compiled into `dh-foundation`), the generated Level document is served at the rule's own path, and the existing geometry, declaration, collision, camera, music and transition code consumes it. The per-difficulty level seed is kept in the character save (schema v5), so a revisit or a reload regenerates the same layout. The Swamp to witch cave exit is enabled and the round trip works in one process (Swamp, witch cave, Swamp, witch cave again, same seed and signature on the revisit). A second procedural level (El Earth, and Swamp to Swamp 2 as a transition) is proven too. Coverage over the 37 procedural maps: **32 generate on every seed (64 of 64)**, 2 generate on some seeds (017: 20/64, 018: 58/64), 1 never generates (027: 0/64, falls back to its authored backup), and 2 are rejected (121, 122: legacy rule format, no backup). **34 of 37 load through the fixed-map loaders** (geometry and declarations), and **35 of 37 render in the EXE** at seed 1234 (30 frames, exit 0); 121 and 122 stop with a named error. ctest: all pass except the allowed `session_skill_binding`.

## Investigation (evidence)

IDA (`.local-inputs/ida-apk-export-2026-10-07/libraries/libDungeonHunter2.so/pseudocode-all.c`):
- `Level::_LoadProcess` 003f6990, stage 7: `Random::s_seed = Level+220`; if the level is a random level (`Level+232`, the LevelList `IsRandom` byte, set in `Level::Level` 003f3128) it calls `Level::GenerateRandomLevel(stream, seed)`. On success `AssignSteamToLoadDataFile(stream)` loads the streamed document as the level data. On failure the level name becomes `x<NN>_<name>_BACKUP.mlx` (first byte of the rule name set to `x`): the authored fallback map. The `x*_backup.mlx` files in `data/scene` (30 files) are these fallbacks.
- `Level::GenerateRandomLevel` 003f07f8: new `rnd::RandomGenerator`, `LoadRuleFile` (00489508, rule name under `data/scene/`), `Generate(seed)` (00488134), `SaveModularLevelToStream` (00488b84). The stream root is `<Level>` with the utf-8 header and the comment "This file was generated by the Dungeon Hunter random generator". The port emits the same root and header.
- Seed source: `Application::LoadLevel` 0032bdc8 reads the savegame seed for the current difficulty (`PlayerSavegame` +92 + 4*difficulty). If it is zero (or `DontUsePlayerSeed`) it takes the realtime timer and writes it back. The same value goes to `GSLevel` and `Level` (`+220`, `+224`). `Level::Unload` 003f0690 reseeds the game RNG from realtime. So the level layout depends on the rule and this per-difficulty savegame seed only.
- Rule format: `RootRule` tree of `ForceBlock`/`Path`/`EndPath` nodes over `<list random="true">` entries (`rnd::Rule::NewRule` 0048de44 compares tags case-insensitively).
- Fallback names: 30 authored `x<NN>_<name>_backup.mlx` files exist in `data/scene`. The IDA name rule matches 29 of them. `007_crypt_01` does not: its file is `x07_crypt_backup.mlx`, while the rule gives `x07_crypt_01_BACKUP.mlx` (the coverage table shows "missing" for 007; its generation succeeds on all 64 seeds, so the fallback is not needed there).

Canonical generator (port/level-loader):
- The tracked tree had only the `procedural_*_v1.hpp` headers (an older snapshot). The `.cpp` implementations (≈1,700 lines, with the layout generator verified in the canonical reports against original ARM runs) exist only as untracked files in the `generic-level-loader` checkout (`C:/Users/adamc/.codex/worktrees/generic-level-loader/DH_sc/port/level-loader`), not in any git commit. I copied the newer header/source set into this branch and say so here, so the provenance is reviewable.
- Compile status before my changes: the core (random, file list, sources, blocks, connections, lists, rules, instances, layout) compiled; the sources and modules stages used probe hooks (`reached`, `native_buffer`) and a duplicated definition, and XML emission needs `canonical_property_map_v1.hpp` (absent). Not imported: `procedural_generator_stream_v66`, `procedural_xml_emission_v66`, `procedural_process_scratch_v69`, `procedural_map_sources_v1` (the last uses the zip-bound `FixedSourcesV1`).

## Implementation

1. `port/level-loader/procedural_*_v1.{hpp,cpp}` (imported set above) and `procedural_asset_source_v1.{hpp,cpp}` (new). The zip-only input (`ZipAssetPackV1`) is replaced by `ProceduralAssetSourceV1`, a byte-reader interface with the same key normalisation (`ZipAssetPackV1::key`). Probe hooks removed; the reader error names the URI.
2. `port/windows-foundation/features/procedural/procedural_level_v1.{hpp,cpp}` (new): `generate_level(assets, rule, seed)` runs sources, blocks, connections, lists, rules, layout(seed), module projection, then writes a `<Level>` document: a `LevelConfig` GameObject carrying the rule root attributes (music, fog, camera planes, light sets), and one `Module` GameObject per tile with `dae`, `xrefobject`, `xrefmax`, `scale`, `mgp`, `mvp`, `position` (grid * unit, z = tile height), the same shape as a fixed `.mlx`. A tile without MVX geometry is counted and reported (`unplaced`). Also `procedural_backup_uri` (IDA name rule), `layout_signature` (FNV-1a of the document), `session_seed`, `record_session_seed`, `fresh_seed`.
3. `AssetCatalog` (asset_catalog.{hpp,cpp}): `set_virtual_file` shadows a relative path in `resolve` and `read` (never written to disk; `resolve` returns the absolute path under the root so `lexically_relative` keeps the uri). `read_authored`/`resolve_authored` read the disk file ignoring the overlay (the generator's rule and MGX/MVX source). `actor_definitions.cpp` sizes documents from their bytes (a virtual document has no file on disk).
4. `main.cpp` (P17 PROCGEN anchors):
   - before the level load: a `.rule.xml` level is generated with the session seed (forced `--procedural-seed N`, else the profile seed for the current difficulty, else fresh), installed as the virtual level file. On failure `options.level` becomes the authored `x<NN>_..._backup.mlx`. Log: `Procedural level generated rule=... seed=... tiles=... modules=... unplaced=... signature=...` or `Procedural level generation failed ... fallback=...`.
   - the seed is recorded in the profile before the first save (`record_session_seed`).
   - transition: the procedural refusal is removed. A procedural target takes the profile seed (generated once, then kept) before the transition save; log `Transition procedural seed target=... seed=...`.
   - `Collision triangles=... floors=... colliders=...` log line after the collision load.
   - placement: `ActorMovement::snap_to_floor` after the motor is placed (startup and arrival): see Gaps for the reason.
5. Character save schema v5 (`character_state.hpp`, `save_store.cpp`): append-only tail, one u32 seed per difficulty (`procedural_seed_by_difficulty`). v1 to v4 files load with zero seeds. v4 layout tests (`tests/schema_v4_tests.cpp`) and the schema-2 migration fixture (`tests/save_tests.cpp`) updated for the 12-byte tail; the "unknown schema" case moved from 5 to 6.
6. `ActorMovement::snap_to_floor` (actor_movement.{hpp,cpp}): places the feet on the floor under the authored XY (search 2000 both ways) and sets `grounded` through the existing `supported()`. Reason: the generated witch cave entry (z 37.06) lies about 50 below its floor (z 87 to 122 in the start tile), beyond the step limit, so the hero was not grounded and did not move. Fixed-map placements land on the same z as before (Swamp start z 255; walk result 311.085, 72.27, 255 before and after).
7. `features/procedural/procedural_level_v1_tests.cpp` (ctest `procedural_level_v1`): rule recognition, backup name, determinism (same seed identical document and counts), seed sensitivity, virtual file read, manifest decode of the generated document, session seed rules, seed round trip through save/load, missing rule failure.
8. `features/procedural/procedural_coverage.cpp` (diagnostic target, not ctest): per rule, N seeds, first document loaded through `load_level_with_module_zones` and `load_actor_definitions`, first SpawnPoint, backup presence.

Tests: `build-p17procgen`: `procedural_level_v1` passes; full ctest passes except `session_skill_binding` (the allowed failure). `window_lifecycle` failed once under `-j 6` and passed alone (window test under load, not related).

## Gaps (explicit)

1. Original layout fidelity not re-verified here: the canonical report claims 70 original runs match; I did not re-run the canonical probes or an original oracle. Only determinism, load and render are proven.
2. 027 never generates (64/64). Cause not isolated (candidate: the `objectives` list with `replacement="false"` and the single `monument_icycavern_we` root block). The original may also fall back; not verified.
3. 017 and 018 fail on some seeds with `generation produced no tiles`: the fallback to the backup map is used for those seeds (IDA stage 7). Whether the original fails on the same seeds is not verified.
4. The witch cave's `AnimatedDecor` water caustics and other module decor are not instantiated (`Unsupported class AnimatedDecor ... ported_elsewhere`); the floors look different from the reference.
5. Skybox not drawn for generated levels (same as fixed maps).
6. Level notices: `Excluded exported module/navigation/collision helper instances` appears for generated and fixed levels alike.
7. Floor placement is an approximation: `snap_to_floor` takes the nearest floor within 2000 units under the authored XY; the original's `SetInitialPosition` behaviour is not verified.
8. Seeds: the first seed of a new profile is `fresh_seed()` (wall clock and counter); the original uses the realtime timer. Equivalent in role, not in value.
9. Menu start of a procedural level: the seed now comes from the profile (`frontendStarted`), but the menu flow itself was not exercised in a run.
10. Transition confirm is still the `--transition-confirm` test aid (TRANSITIONS gap 1); condition stubs still treat `IsAfter_*` as active (TRANSITIONS gap 2). Swamp 2 is reached through the merchant exit with the stub.
11. Per-level world state is not carried across a transition (TRANSITIONS gap 3): the witch cave's monsters and containers are regenerated on each visit (containers and monsters are re-created, not restored).
12. Container objects instantiate (5 in the witch cave, 32 in El Earth), but their population is not verified against the original (the P16 container gaps still apply).
13. Act numbers are inferred from file ids (unverified, as in LEVELS-report). El Earth is the second level (elemental temple band), the act is inferred.
14. Visual anomaly: one round-trip capture (frame 100, witch cave session after the player-to test aid) shows the hero in a different outfit than the knight in the other captures; not investigated.
15. A `New Quest` banner shows in the Swamp return session (frame 160): the quest runtime's bind announcement; TRANSITIONS suppresses it only on arrival. Not changed here.
16. Save format: schema v5 files are not readable by v4 builds (append-only tail; v4 reads reject the new version).
17. The procedural preparation stages are the canonical ones, but the Windows side does not use the XML emission and derived-document stages (zip-bound or missing dependencies).
