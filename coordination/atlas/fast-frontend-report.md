# Fast atlas frontend report

## Investigation and evidence

This is an internal data-browser improvement, with no original gameplay visual counterpart. The consumer is the existing Atlas explorer in `tools/atlas/templates/explorer.html`. Before editing, I inspected its search sidebar, category list, entity tabs, resource cards, typed relationship rows, source/audio controls, and collapsed raw-record disclosure. Those visible structures define the UI behavior to preserve. The current page implementation also showed the bottleneck directly: `load()` decoded the embedded gzip graph, `initialize()` built maps for every node and edge, and `matches()` rescanned and sorted all nodes for each search update. The reported size is 227,000 nodes and about 64 MB compressed / 400 MB expanded; I did not run a browser measurement in this worker.

Backend coordination confirmed these response contracts: `/api/meta` has `counts` and `category_order`; `/api/search` returns paged summaries; `/api/entity` returns `node`, `profile`, packet-local `nodes` and `edges` plus incoming/outgoing lists and a bounded `resource_closure`; `/api/closure` returns `{nodes, edges, total, truncated}`. Search omits References unless the `References` category is selected. The entity packet also includes bounded `resource_attribution` (`kind`, `record`, and `truncated_items`) when a matching profile or file record exists. Profile records separate declared owners from owner candidates and retain source-table-only statuses; file records retain authored/candidate paths, decoder-only refs, mapping confidence, and orphan reasons. The UI preserves that wrapper and renders the same attribution card in Overview and Source, with status/reason, owner counts, bounded relationship/path rows, typed-ID links only when that exact ID is in the packet, platform/mapping/runtime caveats, and collapsed raw record JSON. The entity packet also includes `entity_native` when a matching record exists. Its native schema has entity associations, linked scripts, linked native functions, per-address binding/handler/signature, IDA path and line, a bounded snippet, and separate native-contract and port statuses. The backend now exposes bounded `/api/native` pages (up to 24 scripts and functions per request) and `/api/native-source` references to indexed address evidence; script records can include a graph entity ID and an asset-backed source URL.

## Expected behavior and implementation

HTTP startup fetches only index metadata and the first 50 search summaries. Search waits 150 ms, uses the search API, and cancels prior requests. Entity navigation fetches one packet and replaces the active packet maps; a 12-entry LRU cache bounds retained entity packets. Search results render one page of at most 50 rows with a next-page control. Entity changes cancel stale entity and closure requests. Resource cards consume the bounded `resource_closure` when available; direct and one-hop relationship rendering retains typed links, edge status/reason, incoming/outgoing views, source links, audio playback, gaps, and collapsed raw records. Raw reference rows remain available by selecting their category. The conditional Native / IDA tab renders linked script cards, source links and copyable paths, the explicit no-script reason, native function cards, address/binding/handler/signature details, separate contract and port labels, expandable snippets, and bounded continuation controls for further script/function pages. The three shortcuts issue ordinary API searches, so Mud Lord, BashDown, and Potion0 are not found only as incidental text.

Standalone `file:` mode keeps the gzip payload fallback for the separate offline artifact. HTTP mode never decodes the embedded payload. The app owner plans to put the embedded artifact in `offline.html` and keep the served index small.

## Verification plan and results

The focused browser check for the integration owner is: load the HTTP explorer and verify requests are limited to meta plus one 50-row search; search a non-Mud-Lord entity, rapidly change the query and confirm stale results do not replace the latest; paginate; open a result and follow a typed link to a non-shortcut entity; inspect incoming/outgoing, resource cards, gaps, source/audio, and raw-record disclosure; opt into References; and verify loading, empty, entity-not-found, and server-error states. Open a source resource with `resource_attribution` in both Overview and Source; verify declared versus candidate owner counts, source-table-only/decoder-only/orphan explanations, exact-ID links and collapsed raw details. Also open an entity with `entity_native` metadata; verify script cards and source links, the no-script reason case, native function/address cards, expandable snippets, `native-source` buttons, and continuation paging through all available functions. Exercise native endpoint error and retry paths. Test `file:` mode against the standalone artifact separately.

`node --check` passed on the inline JavaScript, and `git diff --check` passed. This worker did not use a browser, inspect the live backend endpoint, or measure HTTP transfer/latency; integrated visual verification and actual request-size/timing measurements remain with the root browser check.

## Limits and handoff

The UI reads `resource_attribution` from the entity packet and `entity_native` from the node, entity packet, or profile and requests remaining native records from `/api/native?id=&script_offset=&function_offset=&limit=`. Source links use server-provided asset or native-source URLs; an unavailable URL still leaves the exact recorded path/address copyable. Native page records are retained in a four-entity cache, while the main entity packet cache remains capped at 12. Search pages render at most 50 results. No game-behavior claims are made by this UI work.

Shortcut handling now opens only a unique exact gameplay match (actor, skill, or item) from returned rows, and invalidates pending shortcut opens when the user types or changes category. Offline search uses the same gameplay-first ordering for exact known names and includes display names in its searchable text. Result, entity breadcrumb/subline, and resource labels omit null row indices; the header identifies the original source relationship index.

Native script readiness objects now render as compact port-coverage ratios and partial/missing/unknown counts. Native source objects render their indexed name, table, and row index instead of [object Object].
