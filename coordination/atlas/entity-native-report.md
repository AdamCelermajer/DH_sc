# Entity, Lua, and native evidence atlas

## Scope and evidence

This is a static source and asset attribution tool, not a gameplay feature. Its visible invariant is that a user can begin at an actor, skill, item, level, or joined profile and follow authored Lua call sites to the native function ledger and available IDA evidence without confusing association with runtime execution.

- **Visual evidence:** Not applicable to the index implementation itself. Its visible consumer is the Atlas entity detail/Native panel; verify that the panel labels source associations and native evidence without claiming runtime behavior.
- **Logic/source evidence:** Canonical `data/actors.json`, `data/levels.json`, `data/entity-profiles.json`, `data/scripts.json`, `data/calls.json`, and `data/functions.json`; Android IDA pseudocode under `.local-inputs/ida-apk-export-2026-10-07/libraries/libDungeonHunter2.so/`. The index preserves call source site/line/excerpt, function ledger ID, handler/binding/address, pseudocode location/line/snippet when available, native-contract status, and port status as distinct fields.
- **Attribution confidence:** An incoming owner edge is counted as declared only when its reference and target are `RESOLVED` with `PROVEN` confidence. Other incoming edges and unresolved resource paths remain candidates with their individual status/confidence and source `reason`, `reason_code`, and `candidate_note`. A resource path is counted as confirmed missing only when its reference is `UNRESOLVED` with `FILE_MISSING` and no exact physical/logical path match exists in the indexed source/cache asset inventory; this is a source gap, not an ownership claim. Other candidate paths without bytes state why their mapping remains unproven. Packed iPad `.dat` assets retain physical transport path, logical media URI, byte/hash data, and package mapping confidence; a `LIKELY` logical mapping is a candidate association, never a proven owner/runtime path. Android/recovered `audio-cache` and both available platform caches remain in scope.
- **Expected behavior:** Cover every actor, skill, item, level, and joined profile. Preserve typed script association (actor AI closure, level config `scriptFile`, skill `Script` field, profile script closure). A script call is a source-level possibility; runtime caller/state gates remain unknown unless separately evidenced. Keep Android native addresses distinct from port readiness and do not imply an iOS native map.
- **Uncertainties:** Dynamic call targets, actual runtime path/admission, shared helper execution, missing IDA addresses/decompilations, and platform differences remain explicit gaps. Resource table membership and decoder joins are not declared gameplay owners. File presence does not prove loading, rendering, or playback.
- **Focused verification:** Run the generator with an isolated output directory. Then run `entity_native_checks.run(ctx)` and inspect counts, dangling IDs, retained handler/address count, every supported resource profile/file attribution, missing/empty bytes, orphan entries, platform-unknown entries, and the Witch, Knight, Bow, and Mud Lord records. In the Atlas UI, open those four entities and verify their source Lua snippets, IDA evidence labels, and separate port readiness. Runtime playability is outside this static check.

## Coverage record

The canonical atlas source ledgers currently contain 448 actors, 190 level records, 127 skills, 1,322 items, 6,404 joined profiles, 219 Lua scripts, 7,982 calls, and 288 native function rows. The available media inventory currently contains 3,433 physical BDAE/audio files plus 2,901 iPad-packed BDAE logical paths, for 6,334 unique media file records. These are verified source-ledger baseline counts; regeneration can change them.

The current resource-reference source ledger has 83 unresolved resource-path edges marked `FILE_MISSING`; each is checked against indexed physical and logical asset paths before appearing in `missing_resource_paths`. Candidate paths whose source bytes are absent for another or unknown reason remain separately categorized with their source gap note. Generated counts distinguish confirmed missing paths from candidate paths without a source match.

The latest generated counts and the complete lookup records are stored in [entity-native.json](data/entity-native.json), [entity-native counts](counts/entity-native.json), and [resource-attributions.json](data/resource-attributions.json). The native index records address, source path, line, and snippet coverage per function. The resource index records exact and candidate owner/path associations, packed logical media, missing bytes, orphans, platform source labels, and runtime limits per row.
