# Swamp / Darkwood / Witch actor asset audit

Read-only dependency audit for the v20 self-contained stage at `.local-inputs/v20/asset-stage/assets`. This supports integration/runtime verification; it does not close the actor or cinematic feature.

## Resolution contract

`port/windows-foundation/features/spawn/actor_profile_derivation_v1.cpp` derives `ModelFile` from the original `CharacterTable`, then follows `AnimTable` state sequence IDs, redirects, and `AnimDict` leaves for `Template`, `Idle`, `Walk`, `Run`, `Attack`, `Died`, `Limbus`, and `Despawn` only when authored. `content_paths.cpp` normalizes case-insensitively, removes `iphone`/`ps3`/`debug`/`old` path components, resolves `.dae`/`.xml` to `.bdae`, honors `original-cache/` paths and searches the documented actor and texture fallback namespaces. Therefore a file's absence at the first spelled path is not itself a stage miss.

## Findings

- **Witch (exact source-table probe):** B068's `witch-profile.txt` identifies CharacterTable row 435, model `data/3D/characters/witch/witch.bdae`, template `.../witch_template_anim.bdae`, and attack/despawn/death/idle/template/walk clips. Every required model and clip resolves in the current stage. The model is directly at `assets/data/3d/characters/witch/witch.bdae`; the finite package record `coordination/v20/P17-package-assets.json` lines 1137–38 maps source `.local-inputs/assets-extra/android/data/3d/characters/witch/witch.bdae` to destination `assets/data/3d/characters/witch/witch.bdae` (81,980 bytes in stage).
- **Swamp declarations:** B068 `declarations.tsv` has 267 total authored definitions and 29 distinct `charpropsname` bindings. The bound actor-profile rows resolve all model, template, and state-clip URIs through the runtime resolver. They include Prisonier/Prisonier2 and the Swamp merchant NPCs (shared prisoner model), Swamp moth, normal/big lizardman, swamp troll, and SwampKing. The actor files commonly resolve under `original-cache/data/3d/characters/...`, which is a valid resolver root in the stage. No direct model or clip miss was found for these profile-backed rows.
- **Darkwood exact source-table derivation:** `definitions.exe` decoded the authored `003_darkwood.mlx` plus placed MGP/MVP actor documents: 30 distinct `charpropsname` IDs. I parsed the staged original CharacterTable, model dictionary, animation names/sequences/redirects and AnimDict using the field/record layouts in `data.cpp`, `animation_tables.cpp`, and `actor_profile_derivation_v1.cpp`; the Witch row/model/clip family agrees with B068's compiled exact probe. All 30 Darkwood IDs have valid original table rows and valid model/AnimTable indices. Of those IDs, 27 are absent from staged `actor-profiles-v2.xml`, so the current profile document does not cover all authored Darkwood actors.
