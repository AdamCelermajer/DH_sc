## Expected behavior and minimal reusable implementation

When a source `Script_PlayEffect` command executes with its source boolean argument false, dispatch the exact source set ID, position, and resolved object anchor once through `CharacterMeshFxOwnerV4::play_set`; when the argument is true, skip it. Surface asset/play failures as a cue result while leaving campaign command advancement to the existing caller policy. Allow repeated source calls: `Door_Teleport` intentionally plays the same set both before and after actor relocation; `Swamp_Intro` plays source rows 119 and 120 at its cage waypoint around authored shake/open animation changes. Preserve those calls and authored timing without adding a custom glow or map-specific geometry. The generic adapter accepts valid source EffectsTables rows, so it serves other scripted objects and actors. Door triggers continue to enforce their own source state/admission gates.

Implementation: `source_script_fx_adapter_v1.hpp/.cpp` accepts an explicit callback so the adapter remains independent of a new manager or level bank. The production callback must be bound by the integration owner to `RuntimeEffectsFactoryV1::manager().play_set(set, position, nullptr, anchor, nullptr, error)` for the current active session. That existing manager resolves the active borrowed EffectsTables row, original source-library bank, and original file/texture assets. The adapter returns `skipped`, `played`, or `failed`, clears stale diagnostics, validates the decoded position and callback, preserves source call order, and never caches or deduplicates cues. The manifest pins rows 132, 119, and 120, their source step fields, and the exact source/staged asset dependencies by size and SHA-256; it also lists the distinct cage model/material dependencies and separate fire-door family.

`source_fx_anchor_registry_v1.hpp/.cpp` adds the reusable typed query path for source actors and non-actor GameObjects. Both key kinds use disjoint opaque manager identities; actor keys retain the full real `CombatSession::ActorId`, while level-object keys retain the active `SourceWorldObjects` identity, source name/module, and world generation. The external provider resamples each anchor operation. Optional lifecycle values fail closed when their manager-backed source predicate is unavailable. The operation names are not generic lifecycle aliases: `anchor_dead` must use Character virtual +52 / byte +5193 (`Character::IsDead`, `0x3a2ed4`); the typed `deleted` field backs manager `anchor_disabled` from byte +0x81 and must not use the separate GameObject Enable +0x8a field; `anchor_stationary` only controls render synchronization and false preserves per-update resampling. Duplicate `(name,module)` registrations and duplicate ActorId registrations fail; `resolve_actor_identity()` supplies the same opaque key to non-script callers. Issued identities remain reserved across world clears, stale and unknown nonzero manager identities fail closed, and no raw ActorId fallback is allowed while this resolver is bound. Production must migrate every manager-facing actor anchor (campaign scripts, level-up, swing/combat/spawn callers) before enabling it. The caller still owns object enumeration and provider lifetime; no map object or transform is guessed by this component.
