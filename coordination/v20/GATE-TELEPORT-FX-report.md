## Logic and asset evidence

- Existing evidence in `coordination/v20/EVIDENCE-review.md:92` identifies `assets/data/3d/modules/swamp/mgp/bossroom_witch_.mgp` and `_prim_TriggerZone_doorport`, authored with `script=Door_Teleport`, `is_door_closed=_prim_BlueDoor`, and `triggercount=-1`. `TriggerZone::InitPost` at `0x39c0a8` resolves the named door through the same ObjectManager lookup. `TriggerZone::IsDoorClosedActivated` at `0x39b27c` returns true for door states 1 (opened) and 3 (opening); `TriggerZone::Update` at `0x39b458` returns on true before `CanActivate`, timer/enabled checks, touch count, and script/marker dispatch. Thus this zone can enter normal admission only while the door is closed/closing. This gate does not itself establish passage.
- The retained v20 source decode for `Door_Teleport` reports this ordered command sequence: `PlayEffect` on `LocalPlayer` with set 132 and zero local offset; play sound ordinal 604; wait; set `LocalPlayer` position to `_prim_Waypoint_doorport`; wait; play set 132 again. The movement command is the relocation boundary. The pre/post effects are two distinct authored cues and must not be deduplicated. The sequence spans the unsupported-floor boundary in the source room; it is not ordinary collision traversal.
- IDA pseudocode: `Script_PlayEffect::Init` (`0x4598b4`) registers its effect set with `VisualFXManager::RegisterFXSetToLoad`. `Script_PlayEffect::Execute` (`0x45fa9c`) performs no effect when its boolean execution argument is true; otherwise it resolves the named object, converts the three authored integer coordinates to the source Point3D, and calls `VisualFXManager::PlayAnimFXSet` with the effect ID, position, object anchor, and null extra data. The implementation must preserve this raw skip argument and must not invent a persistent glow.
- Original `AnimatedFX::Update` at `0x492f68` (pseudocode `288795`) defines the existing manager anchor queries: `anchor_dead` calls the object's virtual +52; `anchor_disabled` reads raw byte +129 (the deletion flag), not `Enable` at +138; byte +132 gates only Irrlicht synchronization for `anchor_stationary`. `ObjectBase::Delete` at `0x33ddb4` sets +130 to 2 and +129 to 1. Thus retained non-deleted actors/waypoints have source-disabled=false; do not map campaign `SetEnable` to this FX query. `Character::IsDead` (`0x3a2ed4`) supplies the character virtual +52 result via byte +5193, independent of HP. The existing portable `character_fx_state_v1.cpp:49` returns non-stationary and resamples the sync output, which is equivalent to the manager's normal per-update sync policy; static waypoint authored transform can likewise provide `stationary=false` when it represents the source object's normal live update behavior. These manager-specific meanings govern providers; the labels alone are misleading.

The typed provider below now supplies this seam; main's active-level registrations and live callbacks remain integration work.

## Expected behavior and minimal reusable implementation

When a source `Script_PlayEffect` command executes with its source boolean argument false, dispatch the exact source set ID, position, and resolved object anchor once through `CharacterMeshFxOwnerV4::play_set`; when the argument is true, skip it. Surface asset/play failures as a cue result while leaving campaign command advancement to the existing caller policy. Allow repeated source calls: `Door_Teleport` intentionally plays the same set both before and after the actor relocation. The generic adapter accepts any valid source EffectsTables row, so it can serve other scripted objects and actors without special geometry, map colors, or a fabricated glow. The door trigger continues to enforce its own source state/admission gates.

Implementation: `source_script_fx_adapter_v1.hpp/.cpp` accepts an explicit callback so the adapter remains independent of a new manager or level bank. The production callback must be bound by the integration owner to `RuntimeEffectsFactoryV1::manager().play_set(set, position, nullptr, anchor, nullptr, error)` for the current active session. That existing manager is the component that resolves the active borrowed EffectsTables row, original source-library bank, and original file/texture assets. The adapter returns `skipped`, `played`, or `failed`, clears stale diagnostics, validates the decoded position and callback, preserves source call order, and never caches or deduplicates cues. `GATE-TELEPORT-FX-assets.json` pins set 132, its exact one-step table fields, and the three source/staged files by size and SHA-256.

`source_fx_anchor_registry_v1.hpp/.cpp` adds the reusable typed query path for source actors and non-actor GameObjects. Both key kinds use disjoint opaque manager identities; actor keys retain the full real `CombatSession::ActorId`, while level-object keys retain the active `SourceWorldObjects` identity, source name/module, and world generation. The external provider resamples each anchor operation. Optional lifecycle values fail closed when their manager-backed source predicate is unavailable. The operation names are not generic lifecycle aliases: `anchor_dead` must use Character virtual +52 / byte +5193 (`Character::IsDead`, `0x3a2ed4`); `anchor_disabled` means deletion byte +129 and must not use the separate Enable +138 field; `anchor_stationary` only controls render synchronization, with non-stationary resampling matching the existing renderer contract. Duplicate `(name,module)` registrations and duplicate ActorId registrations fail; `resolve_actor_identity()` supplies the same opaque key to non-script callers. Issued identities remain reserved across world clears, stale and unknown nonzero manager identities fail closed, and no raw ActorId fallback is allowed while this resolver is bound. Production must migrate every manager-facing actor anchor (campaign scripts, level-up, swing/combat/spawn callers) before enabling it. The caller still owns object enumeration and provider lifetime; no map object or transform is guessed by this component.
