## Source-root scope derivation — investigation and pre-code test

### Investigation evidence

`SourceRootScopes` is an internal provider used by the current-level consumers of source module identity, physical floor motion and headings. The existing `port/windows-foundation/reports/source-root-scopes.json` defines its scope as an offline composition of the LevelConfig and Module constructor chain; it binds module records to the current `SourceWorldObjects` and explicitly does not claim a completed original `Level::Init`. The visible invariant is that the active level's source module identities and placements drive its floor/body movement and module-bound gameplay triggers.

The level-transition source route is recovered in `coordination/claude-preview17/TRANSITIONS2-report.md`: `TriggerZoneExitLevel::Update` at `0x39c33c` shows the authored target level and entry, and `NativeGoToZone` at `0x4422b8` saves the players and calls `Application::LoadLevel`. Its runtime run records a Swamp→Darkwood→Swamp round trip and a separate Swamp→procedural Witch Cave route. The generated Witch Cave run records seven source module scopes for `data/scene/002_swamp_witchcave.rule.xml`; the transition integration report identifies this root URI as necessary when constructing source scopes for a generated level.

Current `main.cpp` evidence: the session source-world binder calls `SourceRootScopes::build(assets, options.sourceRootScopes, population.definitions(), ...)`. `options.sourceRootScopes` is a launch argument and remains unchanged when the transition loop assigns `options.level = transition.target_file`. Thus a static Swamp URI is reused against target-level declarations. The Preview 16 package's `startup.args` and `swamp.args` both contain `--source-root-scopes original-cache/data/scene/001_swamp.mlx`; the P17 procedural menu run had to pass the rule URI explicitly, and its report documents the Swamp-root mismatch (`matches 0 declaration hosts`).

Existing level coverage also records that the current source-root owner can stop on unsupported source services for some levels (`coordination/claude-preview16/LEVEL-COVERAGE.md`, Darkwood `LoadTemplate` assertion). This is a separate provider gap. Correct URI selection must not be reported as proof that the full original Level constructor has been ported.
