## IDA / recovered logic

The IDA export `.local-inputs/ida-apk-export-2026-10-07/libraries/libDungeonHunter2.so` is APK v1.0.2, while videos are v1.0.3; version differences remain possible.

- `PlayerManager::Update` 0x378fb4 calls `_CheckLocalDeaths` 0x376100 and `_CheckGlobalDeaths` 0x375eb4. Local gate: current Level exists/type 38; local player has a Character; its virtual +52 dead predicate is true; manager phase +433 is positive. `_HandleLocalDeaths` is 0x375fe8.
- `_HandleLocalDeaths` offline: if `menu_FadeToBlackScreen` is not visible, push it once and mute FX. Online: use state +1809 and the local death timer/HUD; expiry hides the timer and calls `ReviveLocalPlayers(...,0)` without offline checkpoint reload.
- `NativeReviveAllPlayers` 0x43b1e4 requires current Level type 38. Online it sets manager +1816 and returns. Offline it pops `menu_FadeToBlackScreen`, pushes `menu_FadeFromBlackScreen`, then calls `ReviveLocalPlayers(...,0)`. The SWF registers it through MenuManager's native registration path.
- `NativeScreenIsBlack` 0x439fa4 does not inspect pixels; online it advances manager +1812 from 1 to 2. `NativePlayPreviousMusic` 0x43ad58 calls `RestartMusic(0)`.
- Offline `ReviveLocalPlayers` 0x37565c restores FX volume, calls `Level::LoadCheckpoint`, clears Character buffs, restores non-origin revive coordinates, calls `Character::Revive(...,1)`, sets Idle, ensures `CharacterDesign.MinimumPotionsOnDeath`, then stops current music and starts Level music with a 1000 ms fade. The SWF's later previous-music call is distinct and must remain distinct.
- `Character::Revive` 0x3a59ac initializes HP/MP via `_InitHpMp`, marks alive, initializes its physical object, floor-corrects position offline and updates skills.
- `Level::LoadCheckpoint` 0x3f0428 loads the current Level checkpoint, reinitializes GameEventManager, then invokes `Character::SG_LoadCheckpoint(...,16)` / `SG_Update(...,1)`. `PlayerSavegame::_Load` 0x464f4c shows bit16 loads only QEST; LVLS, SKIL, FAES/CFEE, PROP, GEAR and FTVL are not reloaded by this branch. Thus this restores checkpoint world/quest state, not the whole profile.
- Separate `Application::GoToMainMenu` 0x32c1f4 quick-saves Level and local player, resets MenuManager, switches to Flash menu and removes players; it is not the Continue/revive callback.
- Online-only `_CheckGlobalDeaths` 0x375eb4 requires all connected players to be assigned and dead before `CMsgGlobalDeath`. `_HandleGlobalDeaths` 0x375af0 pushes fade/mutes FX, coordinates peers, host-loads checkpoint/restores host position, forces world update, waits 2000ms, then fades and calls `ReviveLocalPlayers(...,1)`. This is separate from offline local Continue.
- `Character::CanRespawn` 0x3a5248 and `GetRespawnDelay` 0x3a4bac derive Character/group respawn eligibility and delay from a flag/property11; they are not gates for the player local-death flow.

## Expected behavior, implementation and verification

Offline local death must preserve the Level/character/dead/phase gates. The Continue button hides itself and starts the parent timeline once; only the later authored callback starts offline fade-out/checkpoint/revival. Duplicate clicks/callbacks must not replay effects. Save ownership and exact HP/MP remain with source providers. Online timer and global-death routes remain separate and cannot run offline checkpoint loading from the local timer branch. Missing original art/layout evidence stays explicit.

Implementation: `death_flow_v1.{hpp,cpp}` wraps existing `death_restart_v1`, separates Continue click from frame-88 revive, guards duplicates, and preserves the second music callback. Focused tests before coding: invalid death gates; exact Hide-then-play order; duplicate Continue and callback; callback rejected before Continue; provider failure; online route exclusion; existing restart tests for checkpoint/world/profile effects and failure prefixes. Production executable, visual UI and isolated-save verification remain integration-owner gates.

Focused implementation tests pass via `run_death_flow_v1_tests.ps1`; existing `run_death_restart_v1_tests.ps1` also passes. Normal production wiring, frozen-executable runtime and rendered visual verification remain pending with the integration owner.
