- Logic: NativeSkillsTrainSkill 0x43d548 resolves player and invokes IncSkill(position,probe); the probe returns a bool without spending. IncSkill 0x3bcc58 checks property157>0, IsSkillAvailable 0x3bca50, unlocked-difficulty rank cap, CanIncrementSkill 0x3bc9ec. These use Character::GetCharSkill 0x3bc784 for the class position's table row, with required Level at +32; CanIncrement compares saved rank <= character level - required Level. Commit debits one point, increments one saved rank, updates skills, recalculates properties and potion capacity. Authored SWF `port/engine-ui/reference/character-menu-flow-v1/authored-actions.txt` 0x2104c-0x210a0 sets btn_add visibility from the probe on selection, 0x21b7e onwards invokes the non-probe transaction and refreshes rank/point UI.
- Root-cause candidate requiring regression: `runtime_skill_session_training_v1.cpp` skill_available/can_increment use class position directly as a global SkillTable index. The portable progression precheck already resolves SkillList[position], so the source kernel can disagree and hide/reject an admissible row.
- Expected/minimal fix: resolve the same validated live property28 SkillList position before reading required Level in both source provider gates; keep saved ranks indexed by class position. No invented learning rules or unconditional button. B102 short-click dependency is actual commit 8b5bfcee (117c2b34 is equipment code), inspected and imported as cf6d0fc9.
