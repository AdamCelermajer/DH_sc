# B101 — IDA reverse engineering of the Door class and the fire-door model (helper report, saved by root)

Source: a helper session of the Opus B101/B105 session, finished after Claude had asked it to stop; its final report is saved here verbatim in substance. Everything is "read in code" unless marked **[inferred]**. Scratch scripts: `C:/Users/adamc/Desktop/workspace/DH_wt/fixfx_work/ida2/` (`strs.py`, `hx.py`, `vt.py`, `passes.py`, pseudocode extracts `door.c`, `ac.c`, `ps.c`, `ips.c`, `rs.c`). Model: `.local-inputs/assets-extra/android/data/3d/gameobjects/go_door_fire_red.bdae`.

**Headline:** the wall of fire is entirely the MODEL: a skinned flame mesh (`_mesh_fire-node`, material Standard_202 = fx_doorfire.tga, constant diffuse, additive) plus ONE embedded Particle Cloud emitter (`GL_PCloud01-node`, material Standard_20 = FX_smoke_03.tga, animated diffuse colour). Game code adds no FX, decals or lights. Two of the earlier "known facts" were NOT confirmed: (a) the sampler-value-as-image-index reading is an inference; (b) a normal `Open()` most likely never reaches the looping IdleOpened clip (point E).
One instance-record hex dump (around 0x5830 / 0x5b20) was rejected mid-run and not re-run.

## 1. Door class (`Door`, derives Zone -> GameObject)
**A. Construction/properties/model.** `Door::Door` 0x3e8274/0x3e8324 -> `Zone::Zone(a1,a2,0,1)`; state +936=0, busy +940=0, opened +932=0, door_collision +933=1, two NetStructDoor. `Door::DeclareProperties` 0x3e8990: `data` (string +900), `opened` (+932), `door_collision` (+933); base `GameObject::DeclareProperties` 0x38cee8: `dae` (+656), `lightset` (default "PlayerLight", +632), `idle_sound` (+856); `ObjectBase::DeclareProperties` 0x33f014: `activate_cond`/`deactivate_cond`.
`Door::InitPost` 0x3e7da8: looks up `data` in `Arrays::Doors::m_memberNames` -> index +928; if `members[i]+20 != -1` copies the model path into `dae` (GameObjectDict::members[idx].+8); calls `Zone::InitPost`; if `GameObject::MeetCondition`: registers callbacks via AnimController vslot +44 (`SetCallbacks` 0x474d10 -> `SetCallbacksOnAll` 0x474cac) with `Door::__Callback`/`Door::__EventCallback`, then `VisualObject::ApplyMeshBox`, an optional PODecor PhysicalObject when `door_collision`, and LoadSound for `members[i]+16` (open) and `+12` (close); otherwise vslot +0x40 (`GameObject::SetVisible` 0x38b0f0).
`Structs::Door::read` 0x4fe050: name, int +12 (close sound), int +16 (open sound), int +20 (GameObjectDict model index). Model load: `GameObject::SetVisualObject` 0x394d34 -> `VisualObject::VisualObject` 0x472a0c -> `AssetManager::loadSceneNode`; searches `_colbox_`, CalcMeshBox, `new AnimController(root,0)` + `SetAnimController` (VisualObject+56).
Level data (`merchantcamp_ruins_swe_00.mgp`): `_prim_Swamp2Door_FIRE`: gametype Door, `data="Red_Door"`, `opened="0"`, `activate_cond="IsBefore_Gothicus2Survivors"`, `idle_sound="sfx_magical_wall_loop"`, rotation (0,0,-90). `_prim_SwampDoor_FIRE`: `data="Swamp_Door_Ruins_FIRE"`, same idle sound. The Doors table file is not in the extracted data (`Red_Door` -> go_door_fire_red mapping unverified).

**B. AnimController vtable** (`_ZTV14AnimController` 0x969058): +32 `PlayClip(const char*, bool loop, int, uint)` 0x4749f4; +44 `SetCallbacks`. `PlayClip` looks up the clip by name, sets the current clip, timeline vslot +64 (loop) and +72 (1.0f), `RootSceneNode::NewAnim` => speed always 1.0. `StopClip` 0x474988 sets speed 0. `SetScale` 0x474920 never called by Door. **[inferred]** clip lookup is case-insensitive ("IdleClosed"/"IdleOpened"/"Open"/"Close" in code vs lowercase in bdae).

**C. Clip per state** (+936: 0 closed, 1 opened, 2 closing, 3 opening):
- `Door::Closed` 0x3e7598: state=0; if a2==0 `PlayClip("IdleClosed", loop=1,0,0)`; `PhysicalObject::enableFilter`; `FlagFloorAsDeadEnd(...,1)`; byte +883=0.
- `Door::Opened` 0x3e7788: state=1; if a2==0 `PlayClip("IdleOpened", loop=1)` (decompiler drops args; asm 0x3e7794/0x3e77fc: R2=1, R3=0); `disableFilter`; `FlagFloorAsDeadEnd(...,0)`; +883=1.
- `Door::Open` 0x3e786c: requires state 0 and not busy; snaps to `Opened(0)` if no visual, a2 (immediate) set, or `IsZonable()` (vslot +0xC4 -> 1) && `+750` && `!+752`; else state=3, busy=1, `PlayClip("Open", loop=0)`, 3D sound `Doors.members[i]+16`. +750 = zoning enabled (`GameObject::EnableZoning` 0x38c790), +752 = zone entered (`ZoneEntered` 0x38c710 / `ZoneExited` 0x38c69c): a door outside the active zone snaps.
- `Door::Close` 0x3e763c mirrors Open: requires state 1, state=2, `PlayClip("Close",0)`, sound +12.
- `Door::__Callback` 0x3e8568 (timeline end): busy=0, byte +133=1; `Closed(0)` if state==2, `Opened(0)` if state==3.
- `Door::__EventCallback` 0x3e8450 (collada events): "opened" -> `Opened(a2=1)`, "closed" -> `Closed(a2=1)` (a2=1: no idle clip started).

**D. Triggers.** Lua `Open`/`Close` (`Door::createBindings` 0x3e74c8 -> `_Open` 0x3e79a8 / `_Close` 0x3e777c, a2=0). Campaign commands `Script_OpenDoor::Execute` 0x45d75c, `Script_CloseDoor::Execute` 0x45d650 (GetObjectByName, require type +244==2). Initial state: `Door::InitFinal` 0x3e7c1c -> `Opened(0)` if `opened` else `Closed(0)`; `Deserialize` 0x3e7a6c same from saved state; net sync `InterpretIncomingNetStruct` 0x3e7828. `TriggerZone::IsDoorClosedActivated` 0x39b27c treats states 1 and 3 as true; `GameObject::_IsDoor` 0x38e9d8 = type==2. The fire door exists only while `activate_cond` passes.

**E. Does the animation loop while idle?** Idle clips loop (loop=1). `Door::Update` 0x3e7560 only does the idle sound, `VisualObject::Sync`, `RequireOnlineUpdate`; it never touches animation/emitters/materials. The bdae event track (header 0x1b84) has 3 events `closed`, `opened`, `closed` (u16 times 0, 0x5b, 0x104 at 0x1b9c). **[inferred]** at 30 fps: 0 ms, ~3033 ms (inside open 2666-4000), ~8667 ms (inside close 8000-9333). Consequence: during a normal Open the "opened" event sets state=1 at ~3033 ms; at clip end `__Callback` sees state 1 and does nothing, so IdleOpened is NOT started and the non-looping "Open" clip holds its last frame (~4000 ms). Close holds at ~9333 ms. IdleOpened/IdleClosed loop only after init/load/snap/net paths.

**F. Emitters/material animation vs state.** **[inferred]** Door code never references particle systems, emitter enables, time resets or materials; everything is driven by the model's own animation tracks on the single root timeline (`PlayClip` -> `RootSceneNode::NewAnim`). In this bdae the tracks are: emitter birth rate, Standard_20 diffuse colour, translations of `_bone_01..03`, `_bone_collisionbox`, `_bone_fx_doorfire`.

## 2. FX tables / spawned effects
No door/fire FX entries in the binary strings (only `AUTO_DOT_01_FIRE`/`dot_fire` status effects); `__irrlicht_Diffuse_color` is the only `__irrlicht_` string. Door/GameObject have no FX property; the mgp door entries have none; `data/3d/fx` has no door assets. => the wall of fire is purely the model (skinned mesh + embedded GL_PCloud01 emitter) and the idle sound loop.

## 3. Rendering
**Material bindings** (instance_material records; trailing index = material library index): 0x5860 `#Standard_202` idx 2 on `_mesh_fire-node` (flame mesh); 0x5b54 `#Standard_20` idx 1 on `GL_PCloud01-node` (particles); 0x59b0 `#ColorMaterial_00E59BB8` idx 0 on `_colbox_fire`.
**Parameters** (stride 24: name, -, type, count, &count, &value): Standard_20 (0x4d3c): diffuse default (0,0,0,1); sampler value at 0x4fd8 = 0 -> FX_smoke_03.tga **[inferred: value = image index]**. Standard_202 (0x4fdc): diffuse (0.361,0.071,0.004,1) = (92,18,1), no animation track; sampler value at 0x5278 = 1 -> fx_doorfire.tga. Both: `__irrlicht_Additive=1`, `Backface_Culling=1`, `Frontface_Culling=0`, `Render_Priority=128` (not referenced by name in the binary; the real GL state is in the pass render state).
**Pass render state:** `createMaterialRendererForProfile<GLES2>` 0x6361e8 copies the pass SRenderState via `renderpass::SRenderState` ctor 0x5d7a10, applied by `detail::apply` 0x5b71d8, `applyRenderStateBlend` 0x5af3f8, `applyRenderStateNonGrouped` 0x5b70cc. Mapping: source word +12 bit19 blend enable, bit20 cull enable, bit22 depth test, bit23 depth mask; byte0 = src/dst factor nibbles. Decoded (`ida2/passes.py`): Standard_20/202 (all 4 techniques): blend ON factors (1,1), cull ON (face 0), depth test ON func 3, depth write OFF, FS defines `TEXTURED` + `ADDITIVEBLEND`; ColorMaterial: blend off (1,0), cull on, depth test on, depth write on. Additive passes bind `DiffuseColor`, `Sampler0`, `TextureMatrix0` (= `diffuse-sampler-matrix`). **[inferred]** factor 1 = GL_ONE (ONE,ONE additive), cull face 0 = GL_BACK, depth func 3 = LEQUAL. `ProfileCOMMON_emul` GLSL source is not in the extracted data: what `ADDITIVEBLEND` does inside the shader is unknown.
**Texture animation:** engine has a texture-transform channel (`animation_track::CTextureTransformEx`, channel 0x100, looked up by `CParticleSystemSceneNode::init` 0x64fd60 as "TextureTransformTrack"). NONE in this bdae (7 channels: birth_rate, Standard_20 `diffuse-color` (type 0x56), 5 bone translations). No UV scroll anywhere.
**Diffuse colour:** flame mesh = constant material uniform (Standard_202), not animated. Particles: `CParticleSystemSceneNode::init` 0x64fd60 takes the material animation (type 86 by param name, else 0x19, else `__irrlicht_Diffuse_color`) as "DiffuseColorTrack"; `PColorModel::applyPColor` 0x64e830 samples it PER PARTICLE (`getValue` writes particle colour at +24): mapping type 1: time = (age * AnimLength / life) * AnimScaleMultiplier + AnimOffset; otherwise time = age + offset. `initPColor` 0x64bf00 sets per-particle offset and length (field order per `PColorModel` ctor 0x654690). `CParticleSystemSceneNode::render` 0x6572b8 forces material diffuse to white while a colour track exists (colour = per-particle vertex colour). **Review correction:** raw type86 keys peak at 133.333–400 ms with RGBA (243,47,1,255), then fade through 466.667/533.333/600 ms to black at666.667 ms. Mapping1, AnimLength0.6667, life1.667 maps this plateau to particle ages approximately0.333–1.0 s. The earlier 500 ms/~75%-life peak inference was incorrect; current sampling uses the actual curve. Without a track `onAnimate` 0x64dac0 passes the material colour.
**Bind shape:** software skin `prepareCache` 0x66fe34 computes `node * invbind(skin+4, 64 B per bone) * bindshape(skin+16)`. In the bdae the skin struct at 0x5428 has bindshape at 0x5438 = identity with translation (180.70, 46.975, 397.15) (non-identity), 4 joints (+116 = 4), inverse binds at 0x54c4; the first inverse bind is translation (435.38,0,0) (inverse of `_bone_fx_doorfire`), the next (228.52,-146.56,...) (inverse of `_bone_01`).

## 4. Lighting
No dynamic light from the door: bdae light count 0, coronas 0; Door code creates none; the mgp has no light object near the doors. The door uses the GameObject `lightset` (default "PlayerLight", `VisualObject::ApplyLightSet` 0x471214). The materials carry `msl_*` spot/point light uniforms for the LIGHTING technique variants; which technique is selected at runtime was not determined. Any orange floor glow in the original is additive fire on geometry or level lighting, not a door light.

## Consistency with the main B101 finding
The Opus session found the port builds the emission box with the wrong axes (uses RadiusLength/Width/Height as X/Y/Z; original X=Width, Y=Height, Z=RadiusLength) and applies the colour animation to the whole material instead of per particle. This helper's decode confirms both mechanisms and adds: additive blend (ONE,ONE), depth write off, no UV scroll, per-particle colour over the first 667 ms of the curve, emitter parented to the animated `_bone_fx_doorfire`.
