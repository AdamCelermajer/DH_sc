# CORE P17 door collision — v20

Owner: `/root/v20_door_collision`; reviewer: `/root/v20_evidence_review`; integration owner: `/root/v20_integration`.

## Investigation and expected behavior

**Visual evidence (direct observation).** Reference is the supplied Dungeon Hunter 2 v1.0.3 Part 1 video at 640x360. Extracted original frames at 7:59 (`.local-inputs/v20/door-evidence/t479.png`), 8:01 (`t481.png`), and 8:03 (`t483.png`), plus 2-second contact sheets spanning 7:57–8:07 (`adjacent.png`) and 8:09–8:19 (`adjacent2.png`). The hero fights the Bogwomp Chief by a fixed stone arch; the frames show the boss taking hits and then disappearing with XP text. The camera shifts and the hero continues in the area. The arch does not visibly animate or open in these frames, and no traversal across its threshold is shown. This sequence confirms a static doorway in the environment only; it does not prove a door collision rule or an opening transition. Those are not inferred from the footage.

**Logic evidence (IDA and recovered owners).** In `.local-inputs/ida-apk-export-2026-10-07/libraries/libDungeonHunter2.so/pseudocode-all.c`:

- `Door::InitPost` (`003e7da8`, around lines 168276–168340) gates initialization on `CheckSpawnProbability < probability`, resolves the `Arrays::Doors` row and visual, calls `Zone::InitPost` and `MeetCondition`, registers animation callbacks, then calls `VisualObject::ApplyMeshBox`. If source byte `this+933` (`door_collision`) is true, it constructs a physical body with `(world,this,1,0,0,0,0,2,0xffff,1)` and assigns it via `GameObject::SetPhysicalObject(..., false)`.
- `Door::DeclareProperties` (`003e8990`, pseudocode near 168748–168794) exposes `opened` and `door_collision`; `Door` construction (`003e8274`) defaults `door_collision` to true.
- `PhysicalObject` polygon construction (`0046f2f0`, polygon branch) uses the same owner's absolute AABB XY extents and position, scales by 0.01, and builds a static rectangular body with category 2 and mask `0xffff`. `MP_NoCollisions` changes its group to -666. The shape uses the source `ApplyMeshBox` output; a render-bounds substitute is not justified.
- `Door::Open` (`003e786c`) admits only state 0 and `!busy`; `Door::Close` (`003e763c`) admits only state 1 and `!busy`. With skip or no visual they immediately call `Opened`/`Closed`; otherwise they enter state 3/2 and play the authored clip. The current physical filter is retained during the transition.
- `Door::__EventCallback` (`003e8450`) calls `Opened` on marker `opened` and `Closed` on marker `closed`; `Door::__Callback` (`003e8568`) completes the transition at clip end if no marker applied the end state. `Door::Opened` (`003e7788`) disables the body filter and clears floor-dead-end bit 1; `Door::Closed` (`003e7598`) enables the filter and sets that bit. `Door::InitFinal` (`003e7c1c`) applies the authored initial open/closed state after its spawn and condition gates. `PFWorld::FlagFloorAsDeadEnd` (`005252ec`) mutates `PFFloor+32` bit 1. `PFObject::CanPathOn` (`00524230`) reads `PFFloor+36`, so that flag alone does not establish blocking in the current Windows motion path.
- Existing recovered equivalents are `CanonicalDoorV27::init_post/source_transition_v91` and `CanonicalDecorPhysicalConnectionV49::create_door_physical` → `CanonicalPodDecorBodyV49::construct_door/assign`; filter mutation is reusable via `native_physical_filter_v1`. `construct_door` consumes the post-`ApplyMeshBox` absolute AABB and position, constructs a native static rectangle, and preserves assignment/lifetime order. The Windows `DoorRuntimeV1` currently has no consumer for these bindings; its `collision_closed()` is only a state accessor and incorrectly treats closing from open as blocked before the source callback.

**Expected behavior.** Each present Door with `door_collision=true` has one native body built from the source visual's `ApplyMeshBox` bounds and authored placement. A closed door blocks colliding actors. Open/close commands obey state and busy admission; the filter stays in its prior state while an animation plays, then disables/enables at the authored marker or clip end. Skip/missing visual applies the end state immediately. An absent door retires its body; restoring a state reconciles the filter without replaying animation or sound. `door_collision=false` creates no body. The reusable implementation exposes stable-ID, value-only physical bindings; main pairs them with the same `DoorViewV1` visual and `DoorInstanceV1` transform and reconciles through the recovered canonical body/filter owner. It will not invent collision dimensions from renderer geometry.

**Uncertainties.** The sampled video does not show this arch opening or a closed-door crossing. The exact source visual/door data identity at this arch has not been resolved from the video alone. Source `ApplyMeshBox` delegates `CalcMeshBox`; exact union behavior can depend on the model's marker/skinned/static geometry and current pose. The v20 owner must use the recovered visual/mesh-box service on the same Door visual; any model that cannot produce that source AABB must fail explicitly rather than guess. Source collision behavior for the `door_collision=0` declarations is clear from the property gate, but those map-specific declarations do not establish the behavior of all level doors.

## Implementation, isolated tests, and integrated verification

Implemented in the feature owner: source `door_collision` parsing (default true), a latched physical-filter value, and stable-ID physical binding snapshots. The filter value changes only when the existing runtime reaches its source end-state path; opening/closing clips retain the prior value. Added `door_collision_v1` to reconcile create/retire/filter changes idempotently and to clip actor swept-circle motion against a caller-supplied exact source AABB, projecting the remaining motion onto contact tangents. The gate takes actor radius/filter facts and the source MoveActor collision policy. It fails on missing active AABBs, duplicate IDs, nonfinite geometry or invalid actor inputs. The native world/body and AABB source remain owned by integration through the existing canonical visual/body path.

Isolated verification: compiled `door_collision_v1.cpp` and its host test with the Windows LLVM-Mingw toolchain and ran the executable with that toolchain on `PATH`; reconciliation and movement branches pass. Compiled `door_runtime_v1.cpp` to an object successfully; one pre-existing unused-function warning remains. This does not verify main/CMake wiring, source AABB supply, or gameplay movement.

Integrated runtime verification is pending. The required shared root-motion hook and hidden `quiet_run.ps1` before/after test remain owned by the integration pass.
