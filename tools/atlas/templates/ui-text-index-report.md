# Original UI and text index

## Investigation evidence

This is static indexing infrastructure; it has no new gameplay or animated visual behavior to compare with footage. Its supported invariant is that exact source IDs and authored UI strings stay discoverable without inventing runtime names.

The source HUD consumer is explicit. `port/engine-ui/reference/hud-player-infos/manager/NOTES.md` records original `InfoHUDManager::FastUpdate` at `0x41e064`: after target admission, it obtains the target's name ID, resolves it through StringManager, and writes `enemy.enemy_name.text` (`InfoHUDManager` cache offset `+0x3cc`). The HUD's authored path is independently bound in `port/engine-ui/hud_manager.cpp:22`, and `port/engine-ui/enemy_status_hud_v1.cpp` retains the same integer-string service and authored name text operation. The atlas therefore maps `character_properties#group0.Name` IDs to exact localization rows for actor lookup, while the runtime target gates remain outside this static alias. This gives every indexed mob a human-readable authored name, including `SwampKing` → “Mud Lord”; table IDs and localization UIDs are both preserved.

Faery table fields are deliberately treated separately. The recovered row schema in `port/game-data/faery_tables.cpp` is `Description, Elemental, ModelFile, Name, SpellScript, SpellType, Type`, with signed text IDs in `Name` and `Description`. Original Faery menu actions in `port/engine-ui/reference/character-menu-flow-v1/authored-actions.txt` select authored `GAMEPLAYMENUS_FAERY_*`, `_DESC`, and `_SPELL` symbols through `NativeGetStringFromSymbol` (also summarized in `coordination/claude-preview14/FAERY-survey.md`, section B4). That evidence does not establish that the table's `Name` or `Description` IDs drive the original menu text. The index preserves all faery table rows and all locale/symbol rows, but does not forge those UID-to-display aliases. Player custom names likewise remain separate from default CharacterProperties names; no runtime-name behavior is claimed.

`HudTextV1::id` (`port/engine-ui/hud_text_v1.cpp:53-56`) decodes packed IDs with `StringConfig` shifts and masks; `HudTextV1::integer_string` (`:104-106`) exposes lookup to callers. `Localization::index` and `Localization::id` (`port/engine-ui/localization.cpp:132-134`) use the same sheet/ordinal model. `common_text_pyarray.bin` supplies the authored 9-pack by 37-sheet filenames, and `common_text_pycst.bin` supplies the exact ID masks/shifts. Each locale file is a bounded count followed by length-prefixed strings, as implemented by `HudTextV1::preload_impl` (`port/engine-ui/hud_text_v1.cpp:37-49`). English and symbols are joined only by decoded sheet and ordinal. SWF symbol IDs are namespaced by owning movie; `ExportAssets` and `SymbolClass` aliases preserve every CharacterID association, including duplicate export names.

## Expected behavior and implementation

`build(ctx, assets, tables)` returns typed nodes, typed edges, aliases, coverage, and explicit gaps. It inventories indexed SWFs, font resources, textures, every locale/symbol resource row, and relevant source table rows. SkillTable `SkillName`/`SkillDescription`, Item `Name`, and eligible actor `CharacterProperties.Name` IDs gain human aliases only after exact packed-ID decoding and same-ordinal symbol/English lookup. Table row identifiers remain separately searchable. Faery rows are retained without unsupported display-ID links. The `0xffffffff` value remains the known absent-text sentinel. IDs with missing sheets or rows remain gaps without guessed aliases.

Every locale and symbol row gets a stable ID scoped by its exact resource URI and ordinal, including empty and unreferenced rows. Where paired rows exist, nodes retain the exact symbol and English text. Equal text, row numbers, and numeric UIDs in different files never merge namespaces.

The bounded SWF reader accepts FWS and CWS, checks declared lengths and tag boundaries, and counts tags and definitions. It associates character definitions, font metadata references, placed characters, and exports with file-scoped node IDs. A missing referenced CharacterID remains a gap. Original files are read in place; the module emits no decoded assets or generated atlas output.

Authored SWF script carriers are separate browseable source nodes. `DoAction` and `DoInitAction` nodes retain the source movie SHA, tag ordinal, decoded SWF offsets, timeline frame and owner CharacterID where available, byte count, and action-block SHA. A bounded AVM1 record walker reports opcode byte counts and names for known opcodes; it does not execute bytecode or infer game/AVM semantics. `DoABC` and `DoABCDefine` are opaque bytecode nodes; only a bounded DoABC name field is surfaced. DefineButton/DefineButton2 actions and PlaceObject2/3 ClipActions remain opaque carrier nodes with explicit gaps because their nested action boundaries are not decoded. The original SWF parser's tag-length and timeline checks gate all nodes.

For AVM1 source search, the bounded walker also retains exact type-0 strings from `ActionPush`, string entries from `ActionConstantPool`, and declaration names from `DefineFunction`/`DefineFunction2`. These become scoped aliases back to their containing action-block node. It counts but does not decode other operand payloads, resolve constant-pool indices, or infer which literal is a native call or visible label. Function bodies are embedded as action records within the enclosing block; their declared byte lengths are bounds-checked while the opcode walk continues through their source bytes.

The iPad package resources are decoded through `package_index.read_resource` in memory after matching the embedded package map. All seven validated SWFs use a distinct `ios7/` URI namespace and retain package path/version, package-container SHA, decoded-resource SHA, and map evidence. Two resources also match Android-cache SWFs byte-for-byte; the other five are indexed under their own iPad source SHA rather than being excluded for differing from Android. The map's `LIKELY` runtime-path status is retained and no native executable behavior or ID mapping is inferred across platforms.

## Verification

The focused checks were: resolve known skill and item IDs to exact symbol and English rows; resolve every CharacterProperties `Name` row, including the source `SwampKing` → “Mud Lord” mapping; preserve Faery rows without asserting unsupported Name/Description menu aliases; index every source locale/symbol row; retain the `-1` absent-text sentinel; prove same-named SWF exports remain distinct by movie and CharacterID; exercise valid FWS/CWS plus malformed/truncated length rejection; and verify AVM1 valid, truncated, and missing-End action blocks plus opaque carriers.

The isolated build parsed 30 Android-cache SWFs plus all seven mapped iPad package SWFs, and 333 localization/symbol resources with all 41,546 rows. It emitted 69,230 nodes, 47,034 edges, and 58,705 aliases. Coverage includes 10,445 AVM1 action blocks / 370,902 action records, all with bounded opcode inventories; 46,143 aliases expose authored AVM1 strings or function names; 348 action blocks contain `NativeGetStringFromSymbol` literals. The parser found 342 opaque PlaceObject2 ClipActions carriers, each with an explicit gap. The indexed SWFs contained no DoABC/DoABCDefine tags. All seven iPad resources passed package FWS length/tag validation and were read in memory under their own source identities; the two byte-identical Android matches are `dqmenusapple.swf` and `dqmenus2.swf`.

Exact text examples include Acrobat (`1245433` → `GAMEPLAYMENUS_SKILL04_NAME_ROGUE` → “Reflex”), Archer_LeatherArmor01 (`1573927` → `ITEMS_LEATHER_ARMOR_11` → “Marksman Armor”), and SwampKing (`1507570`, sheet 23 ordinal 242 → `INGAME_SWAMPKING_NAME` → English authored “Mud Lord”). The `AAA_DONT_DELETE` item row retained its absent-text sentinel without an alias. A cached CWS movie and its in-memory FWS form parsed successfully; truncated and wrong-declared-length FWS/CWS fixtures were rejected. Synthetic AVM1 checks accepted a valid End-terminated block and rejected a truncated long-action record and missing End marker; function body sizes, ConstantPool/Push strings, and function declaration names passed positive and malformed-input checks. All 10,445 source action blocks produced an opcode inventory, and all emitted edge and alias source IDs resolved to typed nodes. Two same-file CharacterID references and 342 ClipActions carriers remain explicit gaps.

This is an isolated source-index check. It does not verify a live game session, rendered menu, original device, or final browser graph integration. Runtime name gates and player custom-name selection remain the runtime consumer's responsibility.

## Uncertainties and remaining gaps

- Four entries present in `text-index.json` are PyData binaries rather than locale strings; the index decodes the 333 authored locale/symbol resources and reads PyData only for exact StringManager sheet metadata/constants.
- The two SWF CharacterID references lacking a same-file definition remain explicit gaps. The parser does not infer cross-movie resolution or external asset use from matching names.
- Button actions and ClipActions are identified as opaque carriers; their condition/event records are not parsed into executable blocks. The current indexed SWFs contain no DoABC/DoABCDefine tags, so AVM2 name/body inventory has no source examples to validate.
- Five of the seven iPad SWFs differ from the Android cache. Their mapped embedded resource names and source/package hashes are retained, but the index does not claim those iPad files share Android runtime selection or native behavior.
- Static SWF tag inventory does not establish which movie variant or font/texture the runtime selects for a device, language, or screen.
- Faery table `Name`/`Description` numeric IDs are retained in table data but intentionally have no original-menu display alias until a matching native consumer is proven.
- No source iPhone executable is assumed. Platform/version differences in the original iPad package remain outside this Android-authority index.
