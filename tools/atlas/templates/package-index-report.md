# iOS package index report

## Scope and outcome

This helper inventories every file under the extracted `dungeonhunter2iPad.app/data` directory and attaches iOS package version, source-relative path, raw SHA-256, detected format, and conservative decode metadata. `inventory(ctx)` returns the full rows; `enrich(ctx, assets)` returns matching metadata updates for the caller's asset schema; `read_resource(ctx, asset, member=None)` returns supported bytes in memory; and `validate(ctx)` checks the embedded path map, pack counts, failure cases, and staged WAV receipts. It does not write or unpack original data.

The package map supplies logical-path aliases, marked `LIKELY`. The mapping is checked against both the embedded `file00000-plantext.dat` and retained `index_map.tsv`. Paired files in the retained Android `original-cache` were a useful provenance check: 543 mapped counterparts were present; among 376 same-size pairs, 321 became byte-identical after subtracting `[1,2,3,4]` from only the first four iOS bytes, 54 showed the same four-byte relationship with later content differences, and one pair had another difference. The remaining 167 available pairs had different sizes. This is direct evidence of the header transform in those source pairs, not evidence of iOS runtime admission or a universal transform for every extension.

`read_resource` applies that first-four-byte offset only when a type-specific validator accepts the result. BDAE requires the `BRES fe ff 00 00` header; the ZIP requires a readable central directory; XML must parse completely with ElementTree; Lua must be valid UTF-8 text with a recognized Lua source prefix/token or a coherent Lua 5.1 bytecode header; and SWF must be uncompressed `FWS`, declare its exact file size, and have bounded tags ending in a valid End tag. XML parsing is gated for `.xml`, `.lightset_xml`, `.mlx`, `.mgp`, `.mvp`, `.mgx`, and `.mvx`; an extension alone never accepts a payload. The bounded names-only reader handles `_pyarraynames.bin` and `_pystructnames.bin` count/length groups, but assigns no IDs and makes no claim about group meanings. Ordinary `.bin` tables such as `*_pyarray.bin` remain raw. A successful offset recipe is marked LIKELY unless the decoded bytes exactly match an available Android source SHA-256, in which case it is CROSSCHECKED. The `sounds.zip` recipe also has 239 member hash checks against the staged iOS manifest. An unmapped pack remains unmapped.

## Investigation evidence

There is no direct visual counterpart for this indexing infrastructure. Its original consumer invariant is that a package resource can be found by its logical path, with its build identity and bytes intact; a resource only enters a decoder after its format is identified.

The existing package investigation at `coordination/claude-preview15/IPA-report.md` records an iPad-only package (`CFBundleIdentifier=com.gameloft.dungeonhunter2iPad`, `CFBundleVersion=1.0.0`, `UIDeviceFamily=[2]`) and 6,145 logical paths mapped to `data/fileNNNNNN.dat`. It reports 6,140 logical names shared with the Android cache list and five iOS-only logical names. Its pack comparison found 321 same-size resources differing only in the four-byte obfuscated header, 41 BDAE files with additional build-specific `-fxNNNNNNNN` IDs, 14 same-size content differences, and 167 different-size resources. It identifies the iOS texture payloads as PVRTC, menu SWFs as a different format/version, and localization tables as a different build. These differences are retained with iOS provenance and are not evidence to replace Android canonical rows.


New raw probes show the same four-byte offset in additional typed resources: `data/3d/modules/rules_test.xml` begins `3d 41 7b 71` and becomes `<?xm`; `data/scripts/ai/assassin1_settings.luac` begins `2e 2f 23 46` and becomes `-- B`; and `data/menus/dqhud.swf` begins `47 59 56 0c` and becomes `FWS 08`. XML parsing accepted 24 of 39 mapped XML files; 15 remain raw because parsing failed. Lua validation accepted 217 of 219 scripts; two remain raw because their bodies are not valid UTF-8 and they do not have a recognized Lua bytecode header. All seven iOS SWFs passed file-size and tag-boundary checks. The earlier IPA report called the raw SWF header's `0x0c` a version byte; after the validated offset it is SWF version 8. The version-8 result is inferred from the decoded header and SWF structure, not recovered iOS loader code.

The same complete-document XML gate accepts the decoded bodies of all 400 `.mlx`, 628/629 `.mgp`, 596/598 `.mvp`, 250 `.mgx`, 253 `.mvx`, and 40 `.lightset_xml` mapped resources. Together with the 24/39 `.xml` files, that is 2,191 fully parsed XML documents; three `.mgp`/`.mvp` resources and 15 `.xml` resources remain raw after parse failure. These are format-valid XML resources, not proof that every file is consumed by the original runtime. For example, `data/scene/001_swamp.rule.xml` begins with the offset header `3d 41 7b 71` and the adjusted bytes parse as XML. The validator also accepts direct plaintext XML when it is encountered; all currently mapped XML-family members in this package required the offset adjustment.

The names-only grammar accepted all 35 `_pyarraynames.bin` streams (71 groups, 8,863 strings) and 31 of 34 `_pystructnames.bin` streams (343 groups, 11,705 strings). The remaining three struct-name members are zero-byte files, which are retained as empty raw resources rather than synthesized as parsed groups. This grammar uses bounded little-endian counts and length-prefixed Latin-1 strings, checks exact end-of-file consumption, and returns names grouped in their serialized order. It is supported by the existing source reader grammar in `tools/atlas/table_sites.py:11-30`; it does not recover iOS native IDs, relate names to array rows, or prove the native runtime's group semantics. The `.bin` inventory therefore reports 66 parsed names streams and 149 unresolved/opaque payloads, including all 35 `*_pyarray.bin` payloads.

The report's package section identifies `data/sounds/sounds.zip` as `file000787.dat`, containing 511 members. `scripts/patchzip.py` demonstrated a patched first local header; this helper reproduces the validated first-four-byte offset in memory and leaves the rest unchanged. The report identifies 239 staged WAVs and 14 VOX banks absent from the Android staged set, along with three BDAE assets. The validator recomputes all 239 staged WAV hashes from the in-memory package ZIP and compares both size and SHA-256 against `assets-extra/ios/MANIFEST.json`. The decoded BDAE hashes and byte counts for `level_up.bdae`, `minimapcameras.bdae`, and `minimapcamerashud.bdae` also match their staged iOS receipts.

The current reconstructed consumers confirm why path and byte identity matter: `port/windows-foundation/asset_catalog.cpp:72-104` resolves and reads authored assets by a relative path, and `port/engine-resources/resources.cpp:159` validates BRES input before parsing. These source locations establish consumer expectations in this reconstruction; they do not prove how the original iOS loader admitted mapped resources. The iPad Mach-O is reported stripped and has no recovered package-loader function or symbols, so map confidence remains LIKELY.

## Expected behavior and implementation

Keep every package file discoverable by its physical iOS path and hash. Attach the embedded map's logical URI as a version-scoped alias. When an Android resource is absent, a caller may inspect the matching iOS resource with its encoding and iPad 1.0.0 provenance visible; any known content delta stays explicit. Do not promote an iOS alias to proof of Android equivalence or let it silently replace an Android source.

`read_resource` reads only into memory. It supports directly signed loose XML and fonts, plus validated first-four-byte repairs for BDAE, ZIP, XML-family resources, Lua source/bytecode, names-only streams, and uncompressed SWF. `read_name_groups(ctx, asset)` is an opt-in helper for the two names-stream suffixes; it returns only validated strings by group. The reader rejects invalid XML/Lua/SWF structure, malformed names-stream bounds, opaque binary tables, fabricated or absent ZIP members, forged aliases, and traversal paths. It does not emit extracted payloads.

## Verification

`validate(ctx)` passed with the original inputs available. It found 6,157 files under app/data, 6,146 numbered pack files, and 6,145 unique mapped logical paths. `file000000.dat` is the only unmapped numbered pack and remains without a guessed name. XML parsing accepted 2,191 documents across the seven suffixes listed above; the per-suffix totals and three empty names streams remain explicit in the returned validation metadata. All 239 planned WAVs had exactly one matching ZIP member and matched the staged iOS manifest's size and SHA-256; the three decoded BDAEs also matched staged iOS size and hash receipts. A corrupt XML body, invalid Lua UTF-8 body, truncated SWF, wrong ZIP signature, and out-of-bounds names-stream count were rejected by the corresponding validators. Unknown pack paths, forged aliases, a mismatched map transcription, malformed traversal paths, and parent traversal reads were rejected. The embedded map and TSV transcription matched exactly.

This is static source inventory and isolated byte validation. It does not verify a running game, iPhone package, or original iOS loader. No original input files were changed.

## Remaining evidence gaps

- No iPhone binary or device-specific package was found; the inspected artifact is an iPad build.
- No source-level iOS loader or admission gate was recovered. The embedded map proves an internal package association, not which mapped assets the original runtime requested.
- iOS-only content, BDAE `-fx` identifiers, PVRTC textures, SWFs, and different-size locale data need asset-specific review before any equivalence claim.
- Generalized XOR/key recovery is intentionally unsupported. The first-four-byte offset is decoded only for the listed types after their format-specific validators pass; tables and other opaque formats stay raw.
