# Source frame and input prerequisites

The isolated Android build now substitutes existing original input-v1 character/object and frame-v1 sprite/root/button translation units. Their vendor baselines remain untouched. It links the existing constructor/setter history, frame schedule/connection, drag, input geometry/policy/connection, and event dispatch/core modules.

OriginalUiSession owns a FrameOwner with shared SwfInputHistory and SwfFrameConnection. Its graph_start service binds both to the exact player before any shared/root character is constructed. The movie retains the owner through native_owner, while the frame/history sidecars retain only weak core identities. Failed-load cleanup destroys the movie before releasing this receiver and its font provider. This integration also covers the session's health/player HUD movies.

The existing root overlay routes root::advance(float) to original scheduling with source catch-up flag false; it does not run the stock mouse prefix. As of v25, MainActivity touch is routed to SwfInputConnection with a direct owned main-menu native event stage. The native MenuManager/HUD/menu event owners, exact viewport, and source callback services are still needed for functional navigation. Linking the input code alone is not input functionality.

Build v18 failed on missing inverse-point/assignment-policy dependencies. Build v19 added the actual existing geometry/policy modules and succeeded. Its main text checks and complete cinematic/audio/lifecycle checks passed at three sizes. Build v20 adds receiver release after movie destruction and a test assertion for pre-construction binding. Exact APK/test hashes are in checkpoints and validation manifests. The new loading test compares actual app frames and retains screenshots at three sizes; it does not verify native loading progress or transition into gameplay.

Additional original ARM investigation: MenuBase::CanHandleEvent (0x41f3fc), MenuManager::CanHandleEvent (0x42cc48), and MenuFX::State::CanHandleEvent (0x41f3ec) return true. That does not justify replacing native_event with a successful no-op: MenuManager::OnEvent (0x42d060, size 0x8c) forwards to HUDControls and the current native menu, and can write a source global for kind 6. MenuBase::OnEvent (0x423214, size 0x108) handles drag/drop, focus and PostOnEvent/dead-zone consumption. MenuMainMenu::OnEvent (0x42bb48, size 0x174) also has a kind-6 branch. The v25 contribution adds the bounded native MenuBase/main-menu event stage. The full MenuManager/HUDControls chain still needs its real owners before complete navigation can be claimed.

Visual inspection of loading-tests-v20/loading-1080x2400-b.png shows a small rotated/cropped texture fragment at the upper-right edge. Motion PASS must not be used as correct loading appearance evidence. Export deliveries include iPhone_Table_DH2 256x256, MenusGraphics_droid 1024x1024 and splash_final_droid 2048x1024. Trace the loading shape bitmap fill/UV/atlas and native loading background before claiming visual fidelity.

## Direct main event stage v25

The retained SwfMovie now owns a SwfInputConnection outside Impl/native_owner, avoiding a strong lease cycle. It binds the exact authored main clip and pre-construction history, scopes cursor/update operations in the existing facade Scope, and uses SwfFrameConnection for source root advance. It does not run the stock mouse prefix. Native receiver acceptance is the actual MenuBase CanHandleEvent=true body. `MenuNativeEventV1` projects the MenuBase/main event stage with genuine constructor-null drag owner, constructor-empty dead-zone vector and initial BSS rollover=false. Reached unavailable focus/drag/language/online/browser/consumption services fail explicitly. Non-empty dead-zone/debug-switch integration is not verified.

As of v28, the connection uses original LoadMainMenu flags 0x84. Bit 4 selects root hit testing; bit 128 transfers focus during held-pointer movement. The exact main clip remains the input context for collection and native forwarding. All real `menu_`-named characters are hidden before main and background activation, matching the source PostLoad/RegisterState visibility stage. This does not register native states or execute their Create callbacks. Without that visibility stage, root hits reached inactive btn_right/btn_Continue controls. The source evidence and ELF hash are in menu-stack-source-v27/menu-stack-source.json.

The main input API accepts whole milliseconds. MenuFrameClock carries sub-millisecond elapsed time between render frames instead of dropping it on every call, while retaining the existing 100 ms gap limit. Its compiled conservation/cap/reset audit ran on the dedicated emulator. Loading keeps its existing float-seconds advancement path.

This is deliberately documented as the direct main event stage: MenuManager::OnEvent forwarding through HUDControls is not implemented. That source routine retrieves a real local player and forwards to the current native menu; it cannot be replaced with a no-op. NativePushMenu/NativePopMenu and MultiMenuManager stack/lifecycle handling also remain unbound. Tapping Options now executes its authored onRelease and sound; its destination menu is not shown.

Touch coordinates are local to the GLES surface. Input and display use the same centered authored canvas rectangle, and update it after resize. Hit testing uses actual movie characters and matrices, not hardcoded button zones. Android cancellation disables the cursor while clearing its button, resets focus and restores the cursor; onPause cancels before suspending the GL thread. Source pending-click animation completion is advanced every front frame.

`input-tests-v25/input-validation.json` ties PASS to the exact APK. Real shell tap/swipe events deliver Options focus/press/release/clicked and authored sound at 1920x1080, 2400x1080 and 2184x1968 surfaces. Margin taps and drag/releases outside do not confirm. The retained process survives live resize with correct hit coordinates. Backgrounding a held touch cancels without confirmation, and a new post-resume tap works. The test closes its injected DOWN pointer with UP after Android cancels app delivery, matching lifting a finger; omitting UP causes an injector stream failure, not an app navigation result. Per-case screenshots and logs are retained. The separate visible emulator finishes on the main menu.
