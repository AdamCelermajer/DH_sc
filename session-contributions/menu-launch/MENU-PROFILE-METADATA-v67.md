v67 menu profile metadata loader

load_menu_profile_metadata_v1 reads the genuine campaign section container using PlayerProfileIndexV1 and the existing native PlayerSavegameV1 readers in source order PNAM, PLVL, PCLS, PDFL, LNAM, LEPT, LUSP, QEST. A temporary display receipt carries slot/name/class row/level/current difficulty/unlocked difficulty/date/location/entry/raw spawn flags and both act arrays. It creates no live Player/Character, inventory or world owner. Parameterized-source level1 is preserved separately from the blank native owner's level0.

Present malformed sections fail; missing sections retain initialized native/global defaults. Actual source comparison discovered that the parameterized constructor leaves some fields (including absent LNAM date) uninitialized. The original test backing is explicitly zero-filled per independent case, and those zero values are backing facts rather than source constructor literal claims. The first test reused backing and carried an earlier date into a subsequent case; correcting this probe isolation removed that false mismatch. Complete present sections use actual source reader stores. Native initialized absent-field values are documented as the bounded receipt policy.

PDFL requires the canonical CurrentDifficulty store callback and preserves reached external effects. QEST, when present, requires an explicit canonical quest provider and never silently uses LNAM acts. The provider receives both act arrays with their LNAM values and must return actual regular/rewound-volatile QEST results. Source quest construction and conditions/objectives remain external. Original corpus borrows two Quest initializations and contains no QEST; separate native provider-gating tests use a synthetic payload to verify delegation/rejection only.

128 original sparse/complete metadata profiles compare successfully with native receipt decoding on emulator5580, using genuine CharacterTable names. Tests cover seven independent sections, missing combinations, Unicode names, signed limits, current-difficulty delivery, all location/act/entry arrays, raw spawn bytes, malformed present sections, QEST provider gating and atomic output. Android build passes. This API is not yet wired to filesystem/profile projection in the visible menu; no live occupied-slot proof. v67 checkpoint is build-only; installed/visually tested menu remains v66. Main checkout and emulator5554 untouched. Full menu/game/media/resolution objective remains active.
