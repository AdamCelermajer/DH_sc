# Generic actor draw submission V38

Status: actual first-chest rigid and skinned primitive transport verified; backend rendering, original pass registration and positive Character visuals remain pending.

submit_generic_actor_draw_v38 streams per-instance/per-primitive inputs inside the V37 checked consume scope. It borrows the actual retained instance/world matrix, actual BRES vertex/primitive/index streams and ranges, node/root visibility, native skin palette/positions and original retained material records/binding indices. There are no XML actor clones, authored placement tables, reconstructed GL buffers, new animation updates or activation decisions. Every input reference expires when the callback returns; independently retained resources remain a required main-owned producer for asynchronous persistence.

The real original-cache SWAMP proof produces three primitive submissions from the first chest's two instances: one rigid primitive and two native skinned primitives. Cached authored placement/rotation/scale references and exact primitive topology/index width/minimum/maximum ranges are preserved. Root visibility hides both instances, node visibility hides its genuine descendants, and source-owned visibility restoration succeeds. The genuine fresh Character NULL Visual produces no draw. Missing endpoints and backend rejection preserve the prior result. This is a chest's reached native InitPost prefix before its missing MeetCondition service, not full chest or Level activation. The result field named static_primitives counts rigid geometry, not GameObject.static84 lifecycle state.

Skin coordinate pitfall: retained scene joint worlds already include owner placement/rotation/scale. Software-skin prepareCache at 0x66fe34 computes joint-world*inverse-bind at 0x66fefc, then bind-shape at 0x66ff10; existing native palette/positions implement that. Retained skinned positions are world-space. The backend must apply cached instance world once to raw rigid vertices and must not apply it again to native world-space skin positions. Unweighted vertices retain the original software-skin zero result; the backend's actual rigid-vertex policy is separate. This adapter does not normalize/re-skin vertices or invent that policy.

Primitive/range pitfall: raw engine/collada topology, index width and min/max range remain intact. The adapter does not force triangles, expand fans/quads, collapse primitive ranges or downcast all indices to uint16. Source attribute type/components/stride and raw indices remain readable through the existing checked assets APIs. Backend feature support must be checked there.

Material pitfall: the existing Scene loader preserves ordered instance material indices but discards original binding symbol/name fields. V38 transports both the raw primitive material symbol and the intact binding table. It resolves only a unique matching material ID among that instance's actual bindings. One of the three chest primitive symbols remains unresolved: it is explicitly counted and delivered as unresolved, without a global first material, assumed primitive ordinal or made-up default. Main must provide genuine binding/pass classification or the consumer must reject it. Material effect/technique/alpha/additive/backface/texture-matrix fields remain the actual scene records.

Original pipeline evidence is saved under reference/generic-actor-draw-v38. Original SceneManager::drawAll is 0x359338; CSceneManager::registerNodeForRendering is 0x58f348; collada CMeshSceneNode::render is 0x646730; IVideoDriver::drawMeshBuffer is 0x35ebd0. The last function forwards retained vertex/primitive stream structures to the driver's virtual call. These bounded disassemblies establish distinct original source stages, not a claim that V38 reconstructs the complete render path. Root attachment alone does not establish source pass registration, sorting, lighting, collision-marker exclusion or draw-cadence behavior. The adapter transports all actual visible native instances; it does not hide nodes because their names look like collision markers.
