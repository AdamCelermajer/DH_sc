# Generic renderer root consumer handoff V42

This is a read-only root source review plus an engine-owned consumer ABI proposal. It does not implement a GL backend, enroll a render pass, change shared code or prove GPU output. Exact anchors/line numbers and current file hashes are in reference/generic-renderer-root-consumer-v42/root-takeover-sites.json; they are a snapshot because the main session is actively editing root systems.

The replacement boundary is data/ownership, not a second gameplay world. Loader supplies SAME retained Level/manager/module/resource/floor graph and actor Visual draw inputs. Main supplies current GS/GL/camera/pass/program/texture owners plus canonical class behaviors. Existing targeting, skills, animation execution, audio and FX remain main-owned.

Module path: obtain GenericRendererInputV36 from the actual RetainedLevelModuleGraphV1/root registry, validate live ownership, and capture current module frames. Each frame pins immutable BRES; each draw mesh contains the genuine source instance/geometry, post-optimization cached world and ordered material-slot sequence. Floors/exits/helper removal remains the existing actual Module preparation; the consumer cannot rebuild matrices or fabricate navigation. Feed these inputs into main's graphics cache keyed by stable source resource identity/content and actual GL generation. Cache pose/frame metadata separately from immutable geometry.

Actor path: enumerate the actual canonical registry keys, lend main's SAME class-owned Visual lookup, and invoke V38 inside V37 consume. V37 reports genuine NULL unpublished Visuals; it does not create class-default inspection actors. V38 carries raw primitive/index/attribute descriptors, cached world, source render-enabled/visibility fields, actual skin palette/positions and V39 material-slot binding. Parent's adopted helper C1 suppression changes actual fields; the consumer adds no name filtering. Visual.release clears actor bytes despite a shared_ptr lease, so upload/copy synchronously to engine-owned GL buffers and material metadata or obtain a genuine separate resource pin before queuing. Never queue raw source actor spans across that scope. GL recreation rebuilds graphics ownership from the same retained actors; it must not repeat C1/defaults/RNG/InitPost/save restoration.

Transform rule: module/rigid raw positions use viewProjection*cachedWorld exactly once. Native skinned positions already include owner/root/helper/world transforms and therefore use viewProjection alone; applying DACT or actor/module placement again doubles translation/scale. The existing root retained-NPC branch2888..2890 already states and follows this rule. The older object-group paths2846..2850 use a different group-local placement model and cannot consume native world-space skin inputs unchanged. Main owns pose update order; the consumer never starts idle clips, samples animation again or advances a clock. V38 currently has no actual pose revision producer, so stable no-change upload avoidance needs main's real revision token, not an invented time/hash heuristic.

Observed graphics sink: Draw2822 always issues GL_TRIANGLES/GL_UNSIGNED_SHORT using packed float position/UV/color. World preparation2608 rejects other topology, nontriangle counts and vertices>65536, and repacks indices to uint16 at2620. Generic input preserves all source topology/index width/min/max ranges. Main must expose exact backend capabilities/conversion support; reject incompatible input rather than truncate indices or assume engine_type equals GLenum. The source assets primitive mapping is an engine enum, not an OpenGL enum. Selected programs may require normal/tangent/multiple UV/joint attributes beyond the current packed layout; use the actual material vertex-attribute-map/provider rather than dropping those streams.

Material rule: source instance binding slot maps to the corresponding mesh slot (V39). Root's symbol-equality guard2610 is incorrect for442 authored assignments found in the corpus and must be replaced. Generic materials retain actual effect/technique/texture/color/alpha/culling parameters. Root's general model draw path uses one program plus special alpha-blue technique handling2813..2816; existing EffectProgramConnectionV4 and shader/program/texture owners offer real authored FX providers but their domain is not proof of a universal level-material backend. Main must lend the actual selected program, mesh virtual38 mode and material-technique flags. V40 projections preserve numeric passes4/8/7 and required camera/node registration; actual queue enrollment, sorting, lighting/fog and draw execution are still engine services. Attachment/ForceRegister or positive source flag is not a GPU receipt.

Texture rule: upload942..964 currently caches by name, reads flattened APK textures or OriginalCacheAssetsV1 data/3d/textures path, decodes RGBA, sets linear/repeat and uploads. Empty image creates a1x1 white texture; nonempty missing resource throws. Generalization must preserve missing versus no-image, actual source sampler/mipmap/wrap/format policy, canonical resource URI/catalog identity and GL-context lifetime. Scene.Material currently exposes a basename; OriginalCacheAssetsV1 can mount/read/directory full original resources, but source BRES image/material resolution must supply canonical binding rather than first-basename/global fallback. Raw buffer addresses alone are unsafe cache identities after release/reuse.

Frame ownership: bind to the SAME actual current GS Level and actual camera view-projection frame. Validate source graph identity/lifetime and backend context generation. Source preparation complete,195 constructors, positive visibility or graphics buffers do not set gameplay readiness/loading phase38. Main's real lifecycle decides update/activation; loader inspection may use a separately explicit inspection frame but must not masquerade as native gameplay. Source culling/onRegister/material pass endpoints must remain required until supplied. Registration can enroll no passes; on_register_delivered alone is not a visible draw.

The proposed header declares the minimum frame/module/actor/end callbacks and intentionally provides no GPU implementation. Root integration can replace only geometry/resource/list construction and input consumption while preserving existing canonical gameplay/audio/FX/target owners. Needed incoming producers remain explicit: genuine Character template/Faery/player model plus Visual/animation owner, actual per-node pass/mesh-mode/technique flags, material attribute/program/image bindings, source frame/current-Level/camera and independent actor resource/pose lifetime if queuing beyond consume.
