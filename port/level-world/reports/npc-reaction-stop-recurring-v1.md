# NPC immediate stop and recurring effects

Source `CharAnimator::ANIM_Stop` 0x3c9924 writes depth0, returns if visual absent, calls actual controller `StopClip(true,0)`, then closes byte48 and raises22 only if it was open. `BlendedAnimSetController::StopClip` 0x476780 selects the current child animator, retrieves its actual timeline, calls `AnimatorBlender::SetScale(0)` 0x3666d8 across every child timeline, and jumps the selected timeline to its end. No completion notification is synthesized. The existing retained observer supplies actual CharAI/AIS/FSM delivery, including synchronous reentry.

Additive APIs: `AnimationScheduler::reset_depth_v1()` and `BlendedPlayback::stop_immediate_v1(bool visual_present,error)`. Existing deferred StopLoop and other APIs keep their behavior. The renderer handoff now uses this method directly on `m.animation->playback()`.

New `NpcRecurringEffectsV1` composes original `dh2_character_timer_effect` over the same NPC property view, source network/remote/dead fields, state, actual CharAI aggro words, sole world combat bridge, shared CF and Debug. Source event0x33 is regen and0x34 is DoT (decimal51/52; not timer IDs). Calculation enters `dh2_character_dot_calculate_result` because outer timer Debug already ran; application calls `CharacterWorldSkillCombatV6::apply(self,self)` and retains all mandatory Hit/status/text/sound/AI/kill callbacks. No health subtraction, duplicate TimerStore, or alternate actor is introduced.

Integration: include `npc_recurring_effects_v1.hpp` before `renderer_npc_reactions_v2.inc`; construct one recurring owner per same MonsterScriptHandle once the actual CharAI HasAggro/aggroed fields are available; pass its pointer in `RendererNpcReactionInputsV2.recurring`. The existing timer scan routes0x33/34 here, retains failures, and continues scanning. Missing actual aggro backing is a required producer failure, never assumed false. Other timers retain the existing explicit callback. Actual NPC slow buff owner and full dead-state receiver remain required where reached.

Focused fixture `tests/character_animation_stop_v1.cpp` exercises the real BlendedPlayback owner with explicit timeline field fixtures: absent visual, both scale writes, selected end jump, once-only22, callback reentry and invalid slot. It is not authored-cache or live gameplay proof. Link against the APK after these owner changes are compiled. New recurring TU plus this fixture and modified playback TU pass strict ARM64 syntax (runtime pending root runner).
