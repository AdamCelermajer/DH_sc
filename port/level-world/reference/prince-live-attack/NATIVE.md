# Native melee and controller attack coordinators

`character_ai_attack.hpp/.cpp` reconstruct the caller choreography of original `CharAI::AI_DoMeleeAttack` at `0x3d01ac` and `v2Controller::Cmd_Attack` at `0x405b04`. The ten-function manifest, original ELF hash, and earlier 1,216 original-only probe records remain unchanged. This new proof compares fresh executions of the actual original callers with an optimized ARM64 build, using matching explicit backend services.

The frozen new corpus is `attack-fixtures.bin` (SHA256 `5b96e8dedd9e33320453c913d01e3df49be988c5fefa2defff007599f7b0ad9b`). Its 2,458 cases contain the prior 1,216 fixture inputs, 154 melee callback mutation/reentry fixtures, 256 speculative restoration fixtures, 64 command callback mutation/reentry fixtures, and 768 seeded mixed cases. ARM32 and O2 ARM64 match all 15,800 ordered services and callback-visible twelve-word state projections. The actual original packet allocation/enqueue block additionally passes 331 checks of opcode0, requested target low16-bit ID and owner byte ID. Native networking is an explicit service; these packet checks do not claim a native network implementation.

The source-bound isolated ASan/UBSan replay passes the same 2,458 cases and 15,800 services, with 821 controller cases, 30 actually executed nested callbacks, eight entry guards and two invalid provider checks. There are zero mismatches or sanitizer findings. Reports are `reports/character-ai-attack-arm64-differential.json` and `reports/character-ai-attack-host-audit.json`; each binds its inputs and production/test source hashes.

## Live ABI and services

`AttackState64` is a mutable projection, not an original object-layout replacement. It represents AI owner+4, target+40, last-target+44, continued+78, last+79, index+74, finisher+7a, seeking+4a, and owner flags+528, heading-active+1b5 and object-of-interest pointer+14a4/signed type byte+14a8. An adapter must refresh projected owner fields if a synchronous service changes the owner. The index/last/finisher sentinels remain untouched unless a fixture callback explicitly changes them. No constructor or attack-entry blanket reset is added.

`AttackServices16::invoke` receives a typed request and mutable live state/controller. Queries are the actual owner dead/ranged/player, SM_IsAttacking, current-target CanAttack, target dead, and current-target melee range services. IsAttacking's genuine predicate is0/1. `attack_range_redirect` carries the original requested target and mode; a ranged character is never treated as automatically accepted melee.

`attack_list_create` receives owner, two exposed literal arguments1/1 and returns a fresh empty `AttackTargetList24*`; the omitted constructor sort/type argument is always0 in these source branches. The view contains borrowed ordered identities, total count and cursor. `attack_list_reset_sort`, `attack_list_search`, `attack_list_pop` and destruction are real backend boundaries. Search's arguments are the two original float bit patterns. The provider must own collection/filtering/sorting, buffers and lifetime, including any reentrant mutations. Native source chooses the first live record, preserves an existing target on empty search, and guards malformed count/alignment or nonprogressing pop without fabricating a result.

`attack_set_target` carries the original boolean mode and requested identity. `attack_sync_last_target` is a distinct ordered service. The test backend writes target/candidate and copies last-target, matching the earlier service fixture. Full AI_SetTarget notifications/sight effects are not reconstructed here. `attack_set_attack_state` carries live target and false; its backend must perform the original `SM_SetAttackState` route to event `0xc354`. It is not a direct accepted FSM mutation.

Diagnostic services expose the exact original `Send` return-site addresses. Initial/retained/fallback returns are ignored; after acquisition a nonzero result plus IsPlayer causes ordered list pops. String/log internals are coalesced backend services. The tests execute actual list constructor, sort clone and SyncLastTarget but supply search/log/destruction providers.

The branch selecting narrow versus full-angle search is taken from heading-active immediately after constructor. A subsequent CanAttack/target-dead callback changing heading does not retake that branch. For a narrow search the service supplies signed integer `CharacterDesign/Attack_FrontalAngle`, source ASR1 occurs before conversion, and float multiplication uses word `0x3c8efa35`. The cache value90 remains one fixture; negative/odd/extreme integers also verify arithmetic-shift behavior. Full search uses word `0x40c90fdb`.

## Speculative command restoration and reentry

Controller forced bypasses global block/locked, while the three independent online/enable/Character gates determine speculative work. `Cmd_Attack` retains target, last-target and continued before its true-mode melee call. Its send decision follows changed target/continued, then the unchanged-path IsAttacking/continued checks. Restoration is exactly SetTarget(old-last,true), SyncLastTarget, SetTarget(old-target,true), followed by old continued. It never restores unrelated index/last/finisher/seeking callback effects.

`attack_network_send` is the ordered source queue/allocation/packet/enqueue block. Its service must obtain real requested-target and owner IDs and handle any synchronous backend reentry; the coordinator does not invent packet bytes or network acceptance. Afterwards `attack_controllable_dispatch` always runs for an allowed command. A Character adapter executes its real virtual+38 route through thunk `0x3ad874` and Ctrl_Attack `0x3ad87c`, thus invoking native melee with mode=false. Offline still performs this ordinary call. Controller state may be absent only where its Character branch is not entered; the controllable backend owns its own identity/lifetime.

The corpus tests mutation at query/log/list/state boundaries and actual nested speculative melee calls while preserving the active emulated stack/register context. It tests the coordinator's service-entry semantics; it does not prove hidden notification reentry inside unreconstructed services. Provider status2 means malformed backend state after effects; it is not an atomic rollback. Status1 is malformed native entry before service effects.
