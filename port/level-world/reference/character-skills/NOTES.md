Empty scripts append null slots. Captured list count is reread after callbacks. Path restoration targets the freshly queried active AIS. The second Debug prefix and live virtual InitVCB finish setup.

`UpdateAllSkills` at `0x3d8894` queries state6 then state7, returning early for either. Each vector's count is captured; base is reread after callbacks. Spell count is captured after skill iteration. `OnSkillUpdate` at `0x3dabd0` constructs ReturnValues, reads instance Character+3e4, skips a null receiver, calls Get("SetSkill", retained arguments), skips OnSkillUpdate on source Lua error, erases all result entries, rereads the active receiver, then calls OnSkillUpdate with no arguments and destroys ReturnValues. The second receiver has no original null guard. Native destructive vector shrink/null second receiver are explicit unsupported safety boundaries rather than an invented successful branch.

`_SkillCleanUp` `0x3d8ae0` and `_SpellCleanUp` `0x3d8a98` invoke `OnSkillCleanUp` `0x3daafc` with the same SetSkill/Get/error/return-cleanup choreography. They do not delete instances or clear vectors. The native owned facade destructor releases its own memory; it does not claim the entire original CharAI destruction lifecycle.

## Production ownership and required providers

Add `game-data/faery_tables.cpp`, `level-world/character_skills.cpp`, `character_skills_owner.cpp` and `character_skills_session.cpp` to their existing parent-controlled libraries. `CharacterSkillOwner` pins SkillTables and FaeryTables, owns stable nullable vectors/instances/script bytes/arguments and path snapshots; it is nonmoving. `CharacterSkillSessionServices` borrows the actual CharacterScriptSession, shared Debug PreloadServices and live NativeFsm24; all must outlive it and every call. Declare Session/debug/FSM before the adapter and SkillOwner, or explicitly destroy owners first.

The adapter queries active identity fresh, uses actual ScriptOwner copy/assign path, Session load_file/init_vcb, fresh alias/global lookup and typed discarded-result calls. All returned Values (including table `_this` lookup effects) are genuinely projected and destroyed by the root call API before continuation; no result-count cap or unbound return vector is manufactured. Source Lua errors remain distinct from native-required failure, including caught required failures. Generic VM busy protections remain: a busy native callback cannot initiate OnSkillUpdate through this adapter. Original service-level reentry remains supported in the pure kernel; fully scoped Lua skill callback reentry would require a separately proved source capability.

Source setup/update must be delivered in original InitScriptProcess ordering after deferred publication: vitals, configure skills/spells, update all skills, OnInitPost, OnInitFinal. This module does not publish AIS, choose startup state, run InitPost, or fill missing skill/game providers. Missing Debug, script/path/VCB/FSM services fail after their genuine delivered prefix. Path restoration is not invented on a failed prefix.
