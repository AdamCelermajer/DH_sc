## Exact registration and debug gate

Each set call performs `DebugSwitches.load(0x337888)` then `GetModule("AnimatedFX",0x337ec8)` before signed ID bounds. Module off or invalid set ID returns. It captures the selected row and loops while signed count is positive. Only step Redir==1 recursively registers a set; every other integer registers a dictionary effect. After each nested call it rereads the captured row's count and step pointer. No source cycle/once-only guard exists.

Each leaf similarly performs load→GetModule before dictionary ID bounds, then load again→GetSwitch(`isTracingPreCached_FX`,0x337a88), ignoring the returned tracing boolean. It then calls original `VectorSet<int>::push_back_unique(0x49437c)` on manager+0x10. Queue order follows first encounter; repeats preserve one stored ID and still perform source debug calls.

`GetModule` uses the independent map header at singleton+0x18 (switch map is at+0). A hit returns byte node+0x28 immediately. A miss performs singleton load→GetSwitch(`isTracingDebugSwitches`)→insert module value1. It does **not** use a false switch default as module permission. `probe.py` executes the original miss/hit body with explicit string/map-storage fixtures, including exact lookup/insertion/debug-call order. Native `DebugModules` owns this independent map and borrows the genuine existing missing-file `DebugSwitches` owner/file service. An actual existing savegame remains explicitly rejected by the earlier backend; this module cannot publish pretend parsed module flags.

## Minimal native startup service

`visual_fx_preload.hpp/.cpp` provides `dh2_fx_register_set`/`dh2_fx_register_effect` with native-width table pointers, ordered queue storage and required synchronous debug services. It preserves captured-row rereads and synchronous registration reentry. Caller storage is stable and remains valid across all callbacks. It returns1 for complete source returns (including module off/invalid IDs), -1 for atomic malformed caller rejection, -2 for a required service failure with its completed prefix retained, and -3 for explicit queue/depth exhaustion.4096-row limits and depth128 are bounded native caller contracts, not recovered original guards. Queue/table aliasing, concurrent mutation and storage destruction are excluded.

For a genuine missing-file startup, retain one shared `DebugSwitches` owner with real app-files `DebugFileServices24`; create `DebugModules` borrowing it, then bind `PreloadServices16{modules,dh2_fx_debug_preload_service}`. Retain a caller-owned queue and actual decoded effects table for the level/manager lifetime. Do not manufacture true module permission or call an accepted no-op FX callback. The isolated host proof invokes the real DebugSwitches DSO and actual filesystem `fopen`/ENOENT/close services:200 FX77 registrations produce queue[283], one missing-file open, and real tracing-map insertions; an existing file fails without queuing an FX.

The helper owns no full VisualFXManager. It implements neither `BuildLibraries` nor `Play/Grab/Drop/Update`; callers must not route those operations to it as successes. Its caller-supplied table is a projection of already decoded source rows, not a new production cache decoder.

## Library and factory phases that remain required

Original manager constructor `0x4932c4` initializes56 bytes: precache byte+4=0, pending-return list+8/+0xc self, queue vector+0x10/+0x14/+0x18 empty, set vector+0x1c/+0x20/+0x24 empty, dictionary vector+0x28/+0x2c/+0x30 empty.

`PreCacheLibraries(0x495a88)` runs the same debug-module gate; its `_PreCacheAnimDict(0x4933d8)` only writes manager+4=1. `BuildLibraries(0x496bd8)` gates then `_BuildAnimLibrary(0x496ba4)`: if the dictionary is nonempty it returns; otherwise sets precache1, builds dictionary metadata first (`0x495364`) then set metadata (`0x496954`). Dictionary metadata is created for **all284** dictionary resources, with borrowed source path pointers, empty free-instance vector and active-instance list. Set metadata is created for **all276** sets. Step ID-1 is skipped; type0 produces a leaf token, every nonzero Redir produces a nested-set token. This differs deliberately from registration's recursion condition Redir==1. ForceCache source sets register each token through its corresponding registration path. None of these captured bodies calls `AnimatedFX::Load` or a rendering factory; current helpers do not yet implement that metadata ownership.

Actual lazy allocation first occurs in `_GetAnimFX(0x494ad4)`, reached by Play/Grab callers. It indexes the24-byte dictionary metadata row. A free instance is popped and its visual scale reset to1. Otherwise it counts active instances and returns null when count>5; source permits creating a sixth instance. It allocates84-byte `AnimatedFX`, calls constructor `0x492374(id)`, then `Load(0x49296c,path,"",1,-1,true)` and inserts the instance into the active list. There is no caller status branch after Load; do not invent a bool-success contract.

Load stores borrowed source path/name pointers, speed and loop fields, allocates172-byte `VisualObject`, and calls `VisualObject::C1(0x472a0c,nullParent,path,name)`. That constructor invokes `AssetManager::GetAssetManager(0x50a564)`→`loadSceneNode(0x50a504)`→`SceneManager::LoadScene(0x3596f8)`, including genuine Application core/scene/asset ownership. The empty-name source branch invokes resource-library load`0x61bbd4`, names/refcounts the root, synchronizes/refreshes its bounding box, searches modular/collision nodes, registers scene state and installs a real `AnimController`. The new port scene reader alone does not implement this factory lifecycle.

Load then calls the AnimController virtual+0x2c (`SetCallbacks`, vtable`0x969058`, implementation`0x474d10`) with actual `AnimatedFX::_CBLoop(0x4928a4)` and this AnimatedFX context, null authored-event callback/context; virtual+0x28 is source `SetScale(0x474920)` with speed and slot0. SelfIllum calls recursive `SetNodeToSelfIlluminated(0x50e398)`, including node virtual+0x88. Required material/scene side effects cannot be replaced by accepted no-ops.

`_CBLoop` routes synchronously to `_HandleLoopEnd(0x4927a4)`: loop countdown/state effects, optional set-token completion, callback through AnimatedFX+4 with AnimatedFX and set-data+0x50, then clears callback and synchronously resamples its actual animator/root. Keep resource strings/manager metadata/callback receiver alive through playback and teardown.
