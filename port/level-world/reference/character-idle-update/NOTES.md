# Complete CSIdle frame body

Original ELF SHA256: `36498eb8180ffb74759e6305e9596db999f18583d460f3b8534abcb6022f5e80`. `original-functions.json` and `reference/original-functions.asm` capture twelve complete bodies/producers. The relevant virtual `CSIdle::OnUpdate` is **0x3c0e80**, a16-byte argument-shifting tail branch, not0x3c2e58 (Limbus Focus). It calls **CSIdle::IdleCommonUpdate0x3c0b78**,776bytes. The latter ignores state ID and machine arguments; it does not implement seeking or monster acquisition.

## Exact gates and source order

1. Read Character/GameObject heading-active byte **+0x1b5**. Nonzero calls `Character::RaiseEvent`0x3a4d5c with event0,payloadNULL, then returns. This helper branches to full CharAI::RaiseAIEvent for event0; the existing dispatcher maps it to registered FSM event50001/0xc351 subject to actual controller/AI policy. Do not replace it with a direct state assignment or force a successful transition.
2. Otherwise call Character virtual+0x28 (IsPlayer). False returns. **A genuine Crypt monster with no heading has no remaining IdleCommonUpdate work.** There is no additional script tick, target query, Stop, body write or animation selection in this branch.
3. For players, call GetOnline0x7fd794, read returned owner byte5, and return if nonzero. The complete global/network owner remains a service boundary; this byte is not a guessed general pause flag.
4. Query exact `CharacterDesign/PlayerInterPenetration_Delay` from current application constants. Compare its raw uint32 word unsigned against Character+0x55c; return when delay is greater.
5. Capture application PlayerManager+0x40 and call GetNumPlayers0x36d7a8. Its signed result<=0 returns. This helper has further online/multiplayer branches and is a required provider here; the core does not fabricate its player count.
6. Iterate the captured count, index0 upward. Call GetPlayer0x36e744 with(index,false), then read Player+0x660 Character pointer. Null/self skips. Read candidate `SM_GetState`0x3c01ac on Character+0x4fc; it returns-1 for null current StateInfo. Only signed ID3 continues. Compare the captured delay unsigned against candidate+0x55c; a younger candidate skips.
7. Query current application `CharacterDesign/PlayerInterPenetration_Dist` anew for each qualifying candidate. Convert its **signed int32** word directly to float32; there is no fixed-point or physics coordinate conversion.
8. Capture self-minus-other XYZ differences from current GameObject position+0x160. Evaluate separate float32 products and additions `(dx*dx+dy*dy)+dz*dz`, then test **Dist*Dist > square AND square > +0**. Equal distance, coincident actors, unordered NaN or overflow-to-infinity comparison failures skip.
9. Compute `length=sqrtf(square)`; `factor=((Dist-length)*0.75f)/length`; capture factor*dx/dy/dz. Read current self Y,Z,X and call self's current controller+0x378 `Cmd_MoveTo(Point)`0x4054e4 with self+displacement. Then reread candidate Y,Z,X and its controller after that synchronous call; call candidate controller with candidate-displacement. Continue through the captured count. Do not recalculate the displacement after the first callback, force Stop or alter the current state directly.

Negative distance constants follow the original square/computation; no absolute-value or positive clamp is added. Nonfinite input positions follow source arithmetic/comparisons. Native caller contracts require valid stable projections; they do not promise original behavior for invalid memory.

## Producer aliases and required backends

Character embeds FSM at+0x4fc, so **Character+0x55c == FSM+0x60**. Original FSM Update0x3c628c captures old elapsed, obtains application dt and writes wrapping elapsed once at0x3c62c4 before current behavior dispatch. `_GetStateTime`0x3b6d6c reads Character+0x55c. Reuse owned `State.elapsed_ms` after the outer update; Idle adds no dt. Existing `dh2_character_native_fsm_bounded_tail` calls source `dh2_character_state_update` with dt0.

Heading-active is the source GameObject field written by `SetHeadingDirection`0x393be8 at0x393c60. Existing `navigation::HeadingState.active` supplies this producer; synchronize it from the actor's genuine authoritative heading state before Idle. It is not interchangeable with AIS seeking/sticky or a prototype movement flag. The initial heading byte belongs to GameObject construction/heading ownership, not Idle Focus. Idle Focus's separate suppression byte+0x538 and flags0x2380 are documented in the monster-bank notes.

`source-constants.json` verifies original3999-byte design_pycst.bin SHA256 `db014f9832c1d9e60c62272a2ee67d15568d003c191ae32bbce070cb49056931`, equal to the bundled source asset: Delay1500 and Dist150. These are evidence, not hardcoded production defaults. Live providers should use genuine `CharacterGameDesign::Borrow::design()->lookup` with the exact group/key and preserve dynamic lookup order.

The player branch needs genuine online/PlayerManager ownership and synchronous point controller dispatch. Captured Cmd_MoveTo0x4054e4 applies forced byte9 override, global debug byte gate and locked byte8, then invokes controllable virtual+0x2c. The existing object-target `character_controller_commands` overload is not the point overload; calling it with an invented object would lose semantics. The core deliberately emits the exact required point service instead of claiming that deeper backend is complete. Event0 can use existing full `dh2_character_ai_event` with the actual receiver, active AIS, controller flags and owned state machine. A failed/missing provider remains a delivered-prefix failure.

For Crypt integration, the smallest truthful provider uses actual `dh2_character_target_query(is_player)` with current property/type ownership and handles heading-active event0 through the genuine Character/AI route. Other player-only services must fail explicitly if unexpectedly requested until their providers are attached. The State Services callback ABI is void; an integrating adapter must retain Idle's failure status and propagate it from its enclosing frame provider, rather than silently accepting it.

## Native ABI and lifetime

New `character_idle_update.hpp/.cpp` exports `dh2_character_idle_update(IdleCharacter40*,IdleUpdateServices16*)`. The40-byte mutable projection contains source identity/controller,positionXYZ,state-time,heading-active and reserved0. Callback requests are32bytes; response16bytes. The response for player_count carries captured manager identity and signed count; player_character returns a nullable stable Character projection for GetPlayer(index,false)+Player660. State response is signed ID bits; constant response is exact signed32 bits. Native identities retain64bits.

Callbacks are synchronous. The root Character projection/identity binding, service context, captured manager and every returned candidate remain alive through the whole call. Candidate projections must be canonical for source Character identities; equal identity is treated as self. Callback reentry may change positions, controller owners or elapsed and issue other genuine state transitions; the wrapper preserves the source captured/reread distinction. It never restores or overwrites state after those effects.

Return1 means completed source void body including gated returns;-1 rejects malformed initial projection/service atomically;-2 stops at a failed provider or malformed returned candidate after the delivered prefix. The original trusts its pointer allocations; native memory/alignment/reserved contracts are bounded port guards, not original new policy. There is no hidden Step, dt advancement, script callback, default manager count or accepted missing service.
