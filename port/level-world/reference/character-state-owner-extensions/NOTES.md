# Native composition of PreSpawn and original empty methods

This adapter connects already reconstructed behavior to the owned state machine.
It is new native architecture, not a claim of a newly recovered original wrapper.
The original kernel proofs remain unchanged.

Install `dh2_character_state_owner_extensions_method` as the remaining-method
callback of `StateOwnerBehaviorContext40`. Install
`dh2_character_state_owner_extensions_update` as the other-update callback of
`StateOwnerFrameContext56`. Retain the extension context, PreSpawn projection,
animation rows and service providers throughout synchronous callbacks. The
PreSpawn projection must reference the same actual state and Character identity
as the owner; mismatches fail before effects.

The adapter delivers full PreSpawn Focus/Blur/OnEvent through the proven body.
It delivers eighteen remaining-family methods only when the original method
inventory proves the body is empty. It validates both the current owner metadata
and original function identity. Other methods retain the required caller service;
absence is a failure, not an accepted empty implementation.

The actual main CMake test composes initial PreSpawn Focus, a nested interactive
event during animation selection, one wrapping-elapsed frame, and PreSpawn Blur
followed by genuine Idle Focus. A failed Revive provider leaves the already
delivered Blur prefix intact and prevents transition/notification. It also
checks all eighteen empty methods, forty-three remaining nonempty failure
prefixes, and sixty-five metadata/owner guards, including falsified PreSpawn
function metadata. The three implemented nonempty PreSpawn methods are covered
by the composition cases rather than counted as missing bodies.

`reports/character-spawn-owner-enemy-hit-main-linked-host-audit.json` binds all
thirty-four actual main-CMake suites, compilation records, source/input hashes,
loaded DSOs and pre/post binary hashes. This test contributes 548 checks with
zero ASan/UBSan/leak diagnostics. The binder also verifies that the PreSpawn and
empty-method sources and fixture hashes still match their original/O2 proofs.

Animation index/set, body removal, enable/collision/Revive operations, profiling,
Character notification and the rejected Spawn predicate are explicit host scene
providers. The test does not prove their full production implementations, an
original whole-chain instruction replay, live Android FSM scheduling, or full
enemy AI. The same owner and recovered bodies execute; scene backends remain
required for live integration.
