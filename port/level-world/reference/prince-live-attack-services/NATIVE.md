## Services and producer contract

The API reuses the existing `CombatProperties896`, `CombatInventory16` and `CombatItemRecord164` read-only projections. Property words must be the resolved Character payload, not an inferred class or weapon type. Item scalar rows retain all41 original words; they can be copied from the genuine native `data::ItemTable::rows[].record` producer. The inventory must represent the actual selected equipment set and main-hand reference/instance ID. It is not replaced by a supplied capability boolean. The AI radius array must follow the actual decoded `data::AiTables::rows[].melee_radius` order; it is a contiguous float projection of those producer fields, not a newly chosen reach policy.

`dh2_attack_equipment_melee_radius` returns the original0/1 predicate and retains its caller integer when a ranged weapon is present. Unarmed/melee returns1 and writes0 or Item Param5. `dh2_attack_range_parameters` returns the original0/1 availability and retains all three outputs when unavailable. The property32 shortcut selects signed ASR8 values from properties30/31 and the original projectile word. The equipment branch reads Param4/5/6. Only used equipment spans are dereferenced, and the property shortcut accepts null equipment/table storage.

`dh2_attack_melee_radius` succeeds with return0, initializes the equipment contribution0, uses the actual ranged-type predicate to decide whether Param5 contributes, then converts that signed integer and adds the selected AI float. Cached property index1 selects valid IDs, otherwise8. It does not substitute the physics-body radius or multiply movement speed. The fixture executes the original AIProps reader for all76 actual rows and uses all1,322 real ItemTable record outputs; it does not execute native inventory construction/equipping.

The distance exports take already-selected original GetTargetPosition inputs. `dh2_attack_melee_distance` belongs only to the original resolved Character/type0/interaction8 branch; it evaluates strict `(rOwner+rTarget)^2 > ((dx²+dy²)+dz²)`. `dh2_attack_ranged_distance` belongs after true owner ranged-parameter availability; it evaluates inclusive bounds after wrapping32-bit integer squares and signed conversion to float. Every intermediate difference/product/addition has explicit single-precision rounding, preserving source order and preventing multiply-add contraction.

NaN/Inf, negative values, signed zero and integer limits are accepted source-domain inputs. Output arithmetic NaNs are compared by classification when needed; every non-NaN float bit is compared exactly. This corpus actually had zero differing arithmetic NaN bit patterns. Tests cover property ASR8 on negative/odd/extreme words, integer-square wrapping at32768/65536/65537 and extreme32-bit values, exact reach/range boundaries and seeded arbitrary float words. No radius clamp or finite-value policy is invented.

Malformed native storage returns-1 before output mutation: alignment, bounded borrowed counts, selected equipment/item indices, AI fallback capacity and output/read-span alias are checked. These are new native boundary rules, outside the original unchecked-invalid-memory parity domain. Storage lifetime and sufficient allocation remain the caller's contract. The host verifies source input rows/radii remain unchanged after valid queries and all guarded failures.

## Source and proof scope

Original equipment and additive-radius cases execute the real ItemInventory predicate/selected-set/item/global-row lookup instructions, actual Character.GetCharAIId fallback and original AI_GetMeleeRadius. Their memory contains source-decoded asset values; the geometry body's ObjectHandle resolution, interaction8, radius and ranged-parameter virtuals are named fixtures so that the two complete geometric bodies execute over controlled IEEE/threshold cases. Full target resolution, interaction fallback, faction/hostility, sight and equipment ownership remain distinct services.

This module therefore supplies genuine decoded field queries and recovered geometric algorithms, without claiming a native room-object search, complete range attack, inventory lifecycle, live attack ownership or full AI/gameplay parity. The parent must bind GetTargetPosition selection and actual CanAttack/interaction branches before calling these pure geometry exports. The source discovery notes separately describe the room-object/filter/heap work still required.
