## Next ownership/dispatch boundaries

No full external OnUpdate, event userdata conversion or nonempty AI-state registry is added here. Source update order remains default collision/pause kernel→flag1 OnUpdate→current-state update name+14→reloaded current-state conditions name+2c. RegisterAIState/ChangeAIState and event-specific native services must be genuine before live dispatch.

Include requires explicit persistent provider lifetime, never the owner’s temporary `advance` services pointer. Its scope VM must match the retained session. Positive source Lua statuses mean AddFile false; negative native scope/provider diagnostics remain failures. A provider must not erase/close the current receiver or its VM while Lua is running. A local shared_ptr held only by the Include callback can become the last reference and close a VM at callback return while outer Lua still executes; an outer ownership lease or explicit receiver-lifetime invariant is necessary. Generic VM busy guards remain intact.
