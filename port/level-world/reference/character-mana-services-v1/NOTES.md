# Character HasMana and UseMana

This unit ports the bounded `Character::HasMana(int)` and `Character::UseMana(int)` caller paths and their two Lua callback wrappers. It borrows one live Character identity, its current `PropertyView`, the byte read from `Character+0x14f0`, and the current Application/DebugSwitches globals. The constructor field observation pins a zero byte store at `Character+0x14f0`; its semantic name and later writers are unresolved. It owns none of them.

## Recovered caller order

Both integer helpers call `GetOnline()` freshly. If the returned object's byte at `+5` is nonzero, they dispatch Character vtable slot `+0x54`, which is `ObjectBase::IsRemotelyUpdated() const`. A remotely updated Character has mana and returns true without reading MP. Otherwise HasMana compares the signed requested amount to the raw cached resolved property 41. It does not recalculate properties.

UseMana repeats the online/remote query independently. Offline and nonremote, it queries Application `IsSavedOptionOn("GOD_MANA")`; if false, it captures the DebugSwitches singleton once, calls that selected object's `load()`, then calls the same object's `GetSwitch("GOD_MANA")`. If that is false, it reads byte `Character+0x14f0` and returns true when nonzero. Its semantic meaning and later writers remain unclaimed. Otherwise it calls HasMana, which performs a second fresh online/remote query. An insufficient MP value returns false. A sufficient value calls `dh2_property_add(view, 41, -amount)`, then calls the captured DebugSwitches object's `load()` and `GetSwitch("isTracingChar_Stats")`, and returns true. The debug result is discarded, but both calls and their effects remain part of the path. A synchronous provider can change the global singleton slot; this caller still uses the captured receiver.

The `Globals::application_singleton` points to the mutable source singleton slot; its value is loaded at the `Application::IsSavedOptionOn` phase. That provider's internal option lookup is not reimplemented here. The selected DebugSwitches runtime is retained across the entire UseMana call, including both load/GetSwitch pairs. The existing DebugSwitches runtime and its borrowed file/save services remain the only switch owner. Property 41 is read from the existing resolved sheet and spent through the maintained raw-property adder; no copied MP store or independent debug map is introduced.

## Lua wrappers and limits

Both original wrappers require a nonempty Value vector, then read element zero, require source type 3, call `getNumber`, convert through `__aeabi_f2iz`, invoke their integer helper and push one boolean. Any additional values are ignored. An empty vector or wrong first type silently produces no result. The new native callbacks preserve that path and use float32 truncation toward zero before the integer assertion domain check. Thus `-0.9f` and negative zero become supported integer zero; a negative converted integer fails closed. The assertion implementation and fatal assert-level behavior are unclaimed. NaN, infinities and out-of-range float conversion are also unsupported.

Online singleton selection, the Character virtual dispatch, Application SavedOption, DebugSwitches internals/filesystem, and Character property object methods are required borrowed providers, not no-op successes. Provider failures stop the adapted call. Existing effects remain: a failure in the final tracing lookup can follow a completed MP debit, which is not rolled back. Direct API output booleans are written only on success. Lua callback failures return `DH2_SCRIPT_REQUIRED_SERVICE_FAILURE` so a required source service is not presented as a successful false value.

The host fixture exercises ordinary offline/online/remote paths, a DebugSwitches singleton replacement during `load()`, wrapper trailing arguments, and negative fractional float conversion. The original ARM gate executes the pinned caller and wrapper instructions while modeling the named external online, virtual, Application, DebugSwitches, and property methods as explicit fixtures. The constructor +0x14f0 evidence is limited to three verified ARM instructions plus a whole-function provenance hash; it is not a new body claim. Other dependency bodies are independently mapped by the manifest and are not new body claims. This work is not wired to the Android renderer or a live Prince owner.
