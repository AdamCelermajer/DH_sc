# Shared delayed-script AI queue

This stage reconstructs the owned `Character::s_concurrentAI` container and the bounded registration/eviction/erase caller behavior. It does **not** reconstruct the complete Character frame, Application construction, controller Kill implementation, or the full AI script unload body.

## Original producer and lifetime

The supplied ELF SHA256 is `36498eb8180ffb74759e6305e9596db999f18583d460f3b8534abcb6022f5e80`. The manifest captures twelve complete functions and their exact byte hashes; the adjacent assembly preserves their source instruction bodies. `Character::s_concurrentAI` is the 24-byte global at `0x9a2944`; `s_cachedCharOIDs` at `0x9a292c` is a different map.

The queue initialization in `_GLOBAL__I_...Character.cpp` (`0x3aaa34`) at `0x3aabf8..0x3aac08` writes count zero, root null, a red header byte, and both extreme pointers to the header. The bounded constructor probe starts at `0x3aabe0`, executes this initialization and the actual registration call at `0x3aac0c`, and stops at `0x3aac10`. That call registers the actual map destructor `0x3a7968` through `__aeabi_atexit` (`0x30e304`). The fixture supplies a DSO handle and observes all three arguments. Padding is not assumed initialized. This is evidence for the queue's actual static producer, not execution of the entire global constructor.

Original nodes are 24 bytes: color at 0, parent/left/right at 4/8/12, signed int32 key at 16, and borrowed Character pointer at 20. Header fields are root/leftmost/rightmost/count at 4/8/12/16. The source map destructor executes its recursive clear helper `0x3a7930`, freeing nodes without deleting Characters, controllers, AIs, or scripts. The native owner has the same logical borrowed lifetime and signed ordering using `std::map`; its allocator/container byte layout is deliberately different.

One queue must be retained for the shared source ownership domain. Creating one per actor would change source eviction behavior. Every `DeferredQueueOwner16` is caller-pinned and nonmoving while referenced by the queue or a callback; `identity` is immutable. Its live `controller` is the Character+0x378 projection. Queue handles and all output storage must remain valid, correctly aligned, and disjoint from borrowed input/container storage. Alignment checks do not establish lifetime for arbitrary dangling pointers. Providers return normally; C++ exceptions/longjmp across the callback are outside the contract.

## Registration and removal

After the actual manager clock query, Character.Update enters the inline registration at `0x3ac460` with the raw 32-bit time key in r0. The oracle supplies that clock word at this boundary. Comparisons are signed; sign wrap does not become unsigned ordering. Existing-key registration overwrites only the mapped Character at `0x3ac56c`, retaining the same node identity. Missing keys execute the actual unique insertion (`0x3aa8b4`), node insertion/allocation (`0x3aa77c`/`0x3aa75c`) and RB balancing (`0x313760`). The bounded probe stops at `0x3abf9c`, before the rest of the Character frame.

`UnLoadScriptProcess(iterator, final)` (`0x3a7b24`) has two distinct paths. An explicit non-header iterator deletes that exact node even if the supplied Character differs from its mapped value. A header/end iterator searches in source order for the **first** mapped Character matching the supplied Character. It writes the found iterator before erasing. Actual RB erase (`0x336004`), node free (`0x708f00`) and count decrement happen before AI unload (`0x3cc9dc`) on the passed Character+0x3c8, with the raw final word retained. No match still invokes AI unload. AI unload is an explicit required callback in this stage; its captured complete body is not silently treated as reconstructed here.

Native tokens model logical node identity using queue/key/generation. Generation zero denotes the source header. Overwriting a key preserves generation; deleting and reinserting it produces a new generation. This metadata is a port safety representation, not an additional game clock. An end-search token becomes stale after its found node is removed. Cross-queue/stale tokens reject before erase.

## Eviction and synchronous callbacks

Character.Update's bounded eviction window is `0x3ac384..0x3ac3f4`. It queries the current Level (service `0x31f594`, word+0x3c), then evicts **once** only when count is strictly greater than 8, or strictly greater than 24 when that word equals 29. It captures the minimum node, loads its mapped Character/controller, executes the genuine `v2Controller::Cmd_Kill(NULL,true)` wrapper (`0x40570c`), reloads the mapped Character from that **same node** after the callback, and calls `UnLoadScriptProcess(iterator,true)`. The controllable virtual+0x58 Kill implementation is a required provider; no successful Kill body is fabricated. The native helper receives the exact already-produced Level word and exposes the same callback order and live mapped-owner reload.

Source-valid synchronous cases include equal-key owner replacement, insertion of a new smaller key, unrelated node removal, and nested eviction during AI unload after the outer erase. The original captured node must remain alive through Kill. Deleting that captured node during Kill and dereferencing it afterward is source undefined behavior; it is **not** part of the differential parity claim. Native code detects captured-node deletion/reinsertion and returns malformed status 1. Destroying the native queue during an active callback returns 2 and retains its owner. These safety cases have separate sanitizer tests, not invented original expected values.

Required-provider failure is explicit: 2 means unavailable, 3 means delivery failure, and prior side effects remain. An unavailable Kill preserves the queue. Unload erases first, so unavailable/failed AI unload retains that erase. There is no rollback or blanket successful default. Callback key metadata describes the observed source node; it is not an extra argument passed to the original AI unload body.

## Additive startup continuation proposal

The frozen startup prefix stops before queue eviction or after acquiring the registration clock. Its single unavailable status does not carry an exact restart point, and replaying it would repeat debug/CanUpdate/state/load services. Therefore it cannot safely be resumed merely by calling it again or supplying a false queue view.

Proposed next interface is a **new** complete pre-controller entry that preserves the frozen API and uses this shared queue at the exact source branches: current-Level query → one eviction → synchronous `LoadNInitScriptProcess(true)` → reloaded source type/online/delayed gates → manager `getRealTime` word → signed queue assignment → one Application stats increment → controller-ready. It should borrow the existing typed startup services plus mandatory queue Kill/AI-unload services and the caller-pinned current Character projection, exposing explicit failures at each reached prefix. Its audit must add ordered startup services to these queue fixtures and retain the existing frozen prefix gold unchanged. Controller Update, isABot, timers, AI, animator, GameObject and the suffix remain separate mandatory downstream work. No frozen startup production source is changed in this handoff.
