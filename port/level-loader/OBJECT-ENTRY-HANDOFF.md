# Original factory entry gates and retained native preparation

`object_entry_v1.hpp/.cpp` now classifies a retained source element using the
original factory registry and checked entry gates. It preserves the whole XML
borrow, all attributes, nested elements, type spelling and missing/empty values.
It does not create an object or choose a gameplay/event/restoration ABI.
Registered types produce `registered_requires_services`, never a claim that
native construction is supported.

Original evidence is `reports/object-factory-dispatch-original.json`: the actual
`GetNewObject` instructions execute 102 dispatch cases (33 registered names,
33 constructor-null cases, 33 case-swapped names and three other unknown names).
The original `Level::_LoadFromXML`/`ObjectManager::LoadFromXML` entry branches
also execute 30 cases for the 15 cached MGP links with two debug-service returns,
plus 13 entry-gate/property-order fixtures. Class constructors, Add, registered
properties, handles, debug services and Attribute lookup are explicit modeled
boundaries. These tests do not execute a full Level::LoadFile or class behavior.

Native host and ASan/UBSan checks pass for all 33 table entries, 69 original
lookup cases and 43 XML entry cases. One extra native-only case reports Level's
missing gametype as unsafe; no null-input strcmp result is fabricated. Each
native fixture also checks source lifetime after XML facade destruction and
preservation of the prior entry after rejected preparation. Android arm64 and
x86_64 library compilation passes. No preview APK or emulator state changed.

## Recovered behavior

- `GetNewObject` lookup is case-sensitive. Its first string argument is gametype,
  its second is name. The source writes the registered type pointer to object
  `+0x20`, then passes the original authored type/name, integer ID and bool flag
  to Add. Shared callbacks do not collapse Module/Block or Character/Player.
- No matching registry entry returns a default/null handle after the debug
  lookup. The caller resolves with false and returns before properties, early
  InitPost, IsGameObject or positioning. All 15 MGP `link` declarations reach
  this branch when supplied to the actual entry point. The modeled debug result
  (true/false) does not change the outcome. Debug-service effects are not proved.
- This resolves the entry-point policy question in the previous initialization
  handoff. It does not prove that every affected cache file/element is reached
  by a particular selected level or that its file-error policy succeeds.
  The 503 MGX link declarations remain separately handled by procedural evidence.
- ObjectManager requires present name and gametype attributes. Empty strings
  remain present. An optional type filter uses exact comparison. Level's wrapper
  excludes precisely `Player` first and otherwise passes no type filter.
- The special name `_prim_PlayerLight` changes the requested ID to `-1` before
  creation. This is a request to the runtime owner, not a native/save ID choice.
- Registered entries call InitProperties, optional SetTemplate, LoadDefaultProperties,
  then LoadOverridesFromXML. A present empty template still calls SetTemplate.
  The raw `_templateName` override remains distinct from the `template` attribute.
- `LevelConfig` alone receives early virtual `+0x1c` InitPost. Slot `+0x20` is
  IsGameObject. Its true branch adds the module translation to the class-owned
  post-property position and calls SetPosition with true. This fixture models
  the class position; it does not prove real property/default conversion.

Original factory constructor-null continuation was tested with assert level
zero. The source may enter assertion/logging behavior at other assert levels;
the native entry classifier does not execute constructors and makes no policy
claim for those failures. The initialization candidate's explicit failed-service
latch remains an adapter choice, not original class rollback.

## Native dispositions

The preparation API returns an explicit disposition with the retained source:

| Disposition | Meaning |
|---|---|
| registered_requires_services | Original type exists; real owner services are still required |
| original_missing_attribute | ObjectManager's present-attribute gate returns |
| original_type_filter | Exact requested type filter does not match |
| original_player_exclusion | Level wrapper's Player gate returns |
| original_unregistered_type | Original lookup returns a null handle; source record remains visible |
| unsafe_level_missing_type | Level would pass null to strcmp; caller policy remains unresolved |

`original_factory_table_v1.inc` is generated by
`tools/generate_original_factory_table.py` from the SHA-bound factory receipt.
Original ARM addresses are metadata and must never be called as native pointers.
The table has all 33 entries and the native test compares every spelling/address.
Preparation success means a classification exists, not an object was loaded.
Malformed/unparsed source, invalid element index or an unsupported Level-route
filter fails preparation without replacing the previous retained entry.

receipt, host/sanitizer receipts, table and compiled library member hashes.
