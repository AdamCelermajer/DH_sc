# Generic source catalog extension — one working batch

SOURCE ONLY. No configure, compile, native case, parser/proof execution, emulator,
fixture expansion or new evidence claim. V67 and Root shared files are unchanged.

`make_generic_catalog_part_v70(scope, services, part, error)` creates one PartV67
for the exact original RoomZone340f74 and TriggerTrap340e7c entries. Append it to
the existing parts vector BEFORE ProductionNonCharacterCatalogV67::create and
return the same resulting common catalog callback to the Character bridge. Do
not bind another dispatcher later. Character/Player, Module/Block and LevelConfig
remain their existing reserved owners. The same property-map pointer is borrowed;
no new registry, manager, World or XML implementation is introduced.

Actual existing owners reused:

- canonical_room_zone_factory_v3.cpp:5–20 constructs real V3 RoomZone/GO11 and
  retains its runtime record. V3 InitPost/InitBounds/InitFinal stay unchanged;
  RoomZone's existing byte87 safety repair remains explicitly modern behavior.
- canonical_auxiliary_families_v16.cpp:13–38 allocates runtime/declaration before
  the unique C1; :44–45 selects exact TriggerTrap. canonical_trigger_trap_v37.cpp
  retains distinct GO15, ZoneEx/Zone fields, unproduced timer3f4 and V37 original
  method boundaries. No TriggerZone/TriggerPlate substitution occurs.

Typed providers lend initialization/position services on the already-produced
receiver. TriggerTrap's existing InitPost39dee0, InitFinal38cd48, Update39eedc
and Dtor39e480 interfaces require real source bodies on that exact V37 graph.
An interface being populated is not evidence that those bodies are bound. V3
RoomZone has no canonical D0 implementation; destroy_room_zone must execute its
actual Zone/base native continuation, preserving a failed prefix for real cleanup.
It is NOT a constructor callback and must not allocate/replace a receiver.

Every reached C1 is admitted to Main's real release journal BEFORE construction.
The journal pins the exact runtime record and source XML. Identity0 records are
incomplete C1 prefixes, not successful destructor receipts. Forward construction
failure is sticky, while release delivery still borrows live actual scope owners.
The actual V37 destruction failure remains V37's original non-replay boundary;
this adapter does not manufacture safe retries of it. Successful native release
is cached so a completed D0 is not replayed. retire via erase_after_source_release
only after release_completed confirms real D0, manager/Room unpublication,
transport retirement and exhausted native/draw aliases. Do not release containing
service owners before draining these journals.

Scope remains weak for actualWorld/Level/manager. Independent services_owner and
Arrays snapshots must neither directly alias nor indirectly capture them. Only
per-delivery pins are strong. Class services capture this independent state plus
weak receiver records; the retained factory never captures containing World.
