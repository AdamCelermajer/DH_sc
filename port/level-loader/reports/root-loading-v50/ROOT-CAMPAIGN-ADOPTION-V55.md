# Root campaign source adoption V55

This is the historical V55 adoption note. Current live extraction and source
connections are recorded in [campaign runtime integration](../campaign-runtime-v61/ROOT-INTEGRATION.md).

The live source routes the main menu's exact selected profile into a fresh
canonical World/GS/Level and ticks its one source loading connection each
frame. It no longer loads `worlds/crypt01.dwld` for Play. This source is **not
compiled or runtime accepted**: the Windows RAM incident has paused compiler,
WSL, test, APK and device work. The installed c6691313 checkpoint still uses
the separately verified Crypt development route.

## Applied source composition

- The reviewed 36-file V50 loader/core dependency migration is applied, with
  uint32 source counters134/138/13c, same GS global/C1 lifecycle and genuine
  fresh-manager producer receipt. It never adopts a populated Crypt registry.
- `renderer_source_candidate_v55.inc` creates a fresh source World from an
  explicit logical row and immutable profile receipt. It shares immutable
  Arrays; it never clones the old World, Character, Script VM, Save or Gear.
- `renderer_source_campaign_v55.inc` retains the bootstrap before its first
  original constructor attempt. The selected LNAM row yields its authored
  basename, such as logical SWAMP row41 -> `001_swamp.mlx`, without `worlds/`.
  Per-difficulty seed/LEPT/LUSP, selected slot and requested difficulty feed
  the actual GS argument cells. A missing row requires the original Settings
  default-row producer; it is not changed to Swamp or Crypt.
- NativeBridge Play consumes after AS dispatch unwinds; subsequent frames
  tick the actual GS/Level source connection before front rendering. First
  errors latch and retain the reached prefix. No phase38/readiness stores or
  fallback gameplay are added. The real unsigned wall dt and >2000ms skip
  are preserved; no pacing or FPS changes are included.
- The same Application owns source COnline byte4/5, source Debug singleton,
  camera/AnimSetManager/Scene roots and typed publication slots for the
  ScriptManager and upcoming startup PlayerManager. COnline's zero byte5 is
  the actual C1 store; positive online branches remain required.
- The source GS flush calls the actual retained AnimSetManager
  `source_flush_v17`, independently of EquipmentPlatform or an existing
  Character. Source camera resource/Debug callbacks retain the actual App
  file/Debug owners, avoiding a first-World lifetime dependency.
- The actual same-context native graphics cleanup is supplied to stage0;
  no global renderer reset/physical reset is substituted. Stage5 borrows the
  existing process `actor_world` through the Application lease and executes
  its original physical load once.
- Stage0 sound now calls the installed V44/V45 root audio binder immediately
  after CleanGlitch setup. It borrows the same actual constructed Application
  sound manager and exact StopAllSounds(500) callback. Pending/missing/failed
  audio construction remains a failure; this is not audible acceptance.
- Stage2 calls real MenuManager Unload(2,1,3) after the original Debug query.
  Progress validates the same Level130/30 cells, looks up Loading and invokes
  its actual checked weak character `onProgress`. Genuine NULL menu lookup is
  allowed. The final38 license/HUD-push branch remains an explicit dependency.
- V52 ScriptManager implementation plus stage51/path dependency headers are
  adopted into the existing native library closure. The source stage8 helper
  borrows the actual registered LevelConfig fields and same global parsed
  command manager, distinct from Lua44. It requires genuine canonical command
  C1 factories before publishing a manager; no opcode placeholders are used.

The scoped candidate borrow contains the same World, Application, completed
Level, aliasing canonical manager, property map and immutable selected profile.
Do not store the complete borrow back into its containing World. Catalog
factory binding is once-only before source XML factories (phase<7), and cannot
resume a failed original prefix. V60 Character and V59 startup PM work consumes
these seams. The App getter never allocates a PM or claims a Character exists.

## Remaining functional dependencies

The first source frames still require the authentic startup PlayerManager and
MenuManager.Update prefix/MenuBase lifecycle. Stage0 sound is wired to the
actual Application manager; its boot/output readiness still needs current
integration validation. Root owns real menu/controller/resource teardown.
Stages4/6 and later bodies, stage7 actual filename/filesystem/parser release,
remaining canonical class constructors, module/platform/conditions/PF hooks,
actual stage8 default LevelConfig/fog/command factories and stage14 whole
player load remain incomplete until their original providers are connected.
GS phase4 positive Debug globals/SetSwitch and final38 license/HUD tail also
remain required. A bound class table is not proof that all maps/mechanics run.

The direct native selected-profile adapter does not claim whole original
NativeStartGame/Application.LoadLevel parity: temporary Save SG_Save writes,
GameCenter/PM global prefix/tail and authentic save/jobs/file initialization
still need their original owners. Fresh source World has no Character,
Save14e8 or Gear until the actual producer executes. Full unload/Continue and
gameplay/death/rewards are separate source continuations; no preemptive ready
flags or saved-equipment substitutions are made.
