# V49 exact filesystem filename policy and remaining format-route gap

The scalar source filename kernel is complete: 231 original ARM comparisons
execute ApplyFilenameHacks34e96c, original basename56c740/rfind56c640, and original
ASCII lowercase34e090. Native C++ matches all cases; ASAN/UBSAN pass. Standard
string storage/substring/append plus strlen/strstr and a working-directory virtual
remain explicit transport endpoints. Existing selected graph, main source,
budget services, CMake and frozen packets were not changed.

**The five alpha texture routes remain unresolved.** All five exact compatibility
keys are absent, and all five diagnostic pvr2_ variants exist with BTEXpvr headers.
Their existence and encoding do not establish an original selection policy.
No GPU/config field choosing pvr2_ has been recovered. The native ELF is identical
to the supplied original APK's library (SHA36498eb8...). Clear original native/DEX
and config strings do not supply that prefix. This is bounded negative evidence,
not a proof that a dynamic policy cannot exist elsewhere.

Important correction to the old V43 synthetic filename fixture: the virtual
endpoint at +0x2c is CFileSystem::getWorkingDirectory, not FileSystemWin32::getRootPath
(vtable address point is the symbol+8). The exact source relocation literal is
16 bytes `ata/3d/textures/`, followed by the original input-prefix restoration.
Do not repair this to the intuitive `data/...` constant, hardcode an empty directory,
or turn q:/iphone stripping into a claim of original filesystem behavior.

Source rules: first case-sensitive working-directory substring match; skip its
length plus one byte; keep that original prefix; test `.tga` substring before lower;
if reached, original basename keeps extension and handles both slash types; use
the exact 16-byte literal, ASCII-lower suffix, then restore unchanged prefix.
Uppercase `.TGA` does not reach basename on that call. Nontexture filenames
preserve path separators/domain/prefix and only source ASCII-lower the suffix.
End-match and embedded-NUL detached inputs are rejected atomically because the
original C-string overread/truncation domain was not established by this proof.

New original_filename_policy_v49.hpp/.cpp includes a synchronous actual-FS-owner
working-directory borrow: it checks the producer twice and rejects changes,
without keeping a detached current-directory cache. Exact CResFactory candidates
remain resource_directory+'/'+full_SImage_path followed by full_SImage_path,
preserving duplicates, case and first-failure order; no format variant is appended.

Main must bind its genuine retained filesystem working-directory, actual mount
lookup and any initialized original CFS ObfuscationMap. 56e064 performs exact map
lookup after source path key formatting; an empty/missing mapping retains the
input. No original mapping for these five names or authentic format-driven map
initialization was recovered. The generic createAndOpenFile sdcard prefix global
with .config/.glsl exclusions is a mount/domain rule, not texture-format selection.
Provider proposal is reference/filesystem-format-routing-v49/filesystem-provider-v49.hpp.proposed;
it deliberately exposes no guessed GPU-format enum or pvr2 fallback.

Reproduction: dh2-prove-filename-routing-v49.py produces the source oracle cases;
dh2-test-filename-policy-v49.py compiles exactly one independent g++ host kernel
with ASAN/UBSAN and compares the fixture plus owner/change/atomicity guards.
No emulator or production renderer/GPU/whole-loader result is claimed.
