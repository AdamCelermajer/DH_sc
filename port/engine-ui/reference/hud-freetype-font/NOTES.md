# Safe packed glyphs for the original HUD

The failed Android candidate25ab5ce4 recorded `unsupported source bitmap format` for genuine Arial HUD text. The recovered resolver maps Arial to the original cache `wqy-zenhei.ttf`. The real FreeType2.3.7 face produces MONO at normal HUD sizes: P,size12,width5,rows8,pitch1,num_grays256; P,size16,width7,rows11,pitch1. The old grayscale-only native wrapper rejected these bitmaps. No font substitution or change to `FT_LOAD_RENDER` is needed.

Original `draw_bitmap0x7d06c4` chooses texture width from pitch and copies width bytes per row without checking pixel_mode. Original uncached FT path at0x7d191c uses load flags4 and directly invokes this copier. That implementation is unsafe for packed rows, so this additive module is a modern memory-safe correction, not original packed-bitmap instruction parity. The actual captured instructions remain in `port/level-world/reference/font-text/freetype-bitmap/reference/original-functions.asm` and `freetype-glyph/reference/original-functions.asm`.

`dh2_freetype_bitmap_alpha` accepts bounded MONO,GRAY,GRAY2,GRAY4 spans and expands MSB-first packed pixels to alpha8. Mode determines bits per pixel; actual MONO may report num_grays256. It preserves grayscale texture padding, zeroes padding, and uses logical pixel width for packed texture padding. It rejects malformed spans before writing output. Its explicit bottom-up span contract uses row0_offset and signed pitch. The face wrapper still rejects a negative FT pitch because its allocation bounds are not available; tested actual glyphs have positive pitch. Other pixel modes remain unsupported.

`HudFreetypeFont` retains original-derived metrics and all FT flags, and owns copied font bytes. `SwfHudFreetypeProvider` retains the existing cache/face/bitmap ownership contract and accepts the same persistent `SwfFontServices`. Construct it with `(services,source_scale,optional_bitmap_probe)`, borrow `borrowed_provider()` for SwfServices.glyphs, and keep the provider and image owners alive until the movie is destroyed. The probe uses services.context and reports each new raster's actual mode,width,rows,pitch,grays and packed_conversion. It is called before image upload. Original frozen font/provider classes, both frozen FT vendor snapshots and GameSWF core were unchanged.

The independent safe conversion corpus passes18,432 optimized ARM64 instruction cases. It covers all256 source bytes, four modes, partial-byte widths, stride padding and positive/negative spans. It is an FT pixel-semantics proof, not original unsafe-copy parity. Sanitized actual-font replay matches all570 prior Fontin GRAY cases byte-for-byte, then checks5,415 real wqy glyphs at sizes8..64 against actual official FT_Bitmap_Convert:380 MONO and5,035 GRAY. Five malformed atomic guards pass. The conversion reference compiles unchanged `src/base/ftbitmap.c` only into the audit; production does not require that unit.

Actual shared+HUD movie replay against an immutable main93 DSO snapshot passes ASan/UBSan/LSan with246 alpha uploads,239 nonempty uploads,1,056 bitmap quads and7 packed uploads. It loads real common_text metadata/string packs/native constants and resolves one native string to `World Map`. The size12 MONO P is authored HUD text, separately from that localization result. Fontin and Arial use genuine original cache font bytes and host fopen/fclose. Debug delivery, language0, no-player, cache path rewrite, texture identities/stencil and480x320 viewport are explicit borrowed test projections. This proves the CPU/font/image-callback path; no GPU, APK or device result is claimed. GameSWF vptr instrumentation remains excluded as in its frozen upstream-backed build.

Production CMake adds only `freetype_bitmap_alpha.cpp`, `hud_freetype_font.cpp`, `swf_hud_freetype_provider.cpp` to the UI target, using existing GameSWF/FT includes and the frozen `freetype237-hud.cmake` backend. Android both-ABI syntax checks pass all six source-target pairs. Source advances still depend on the separately recovered provider-first GameSWF fork correction; this safe raster module does not patch that frozen core.
