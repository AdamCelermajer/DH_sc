# Complete source HUD manager handoff

The native coordinator implements all five complete InfoHUDManager methods in the nine-function source capture at `../hud-player-infos/manager`: Update 41ec00, initCachedChars 41d880, applyOneTimeValues 41d728, SlowUpdate 41de54, and FastUpdate 41e064. The remaining captured functions are string construction and reached RenderFX text/position/AS endpoints; these are identified service boundaries, not falsely counted as reconstructed complete manager methods. The original ELF SHA is 36498eb8180ffb74759e6305e9596db999f18583d460f3b8534abcb6022f5e80. Captures and literal bindings are immutable.

## Behavior and public contract

`dh2_ui_hud_manager_v1(state,entry,services)` exposes Update=0, initialize=1, one_time=2, fast=3, slow=4. Every reached service must return exactly 1. A required delivery failure returns -2 with the already executed prefix retained; malformed borrowed projections return -1. Services are synchronous and may change live state. The source cached target is retained by the caller through every synchronous callback, not owned by this module. All raw pointers supplied by a provider must reference aligned, live projected records and arrays. These interfaces do not make arbitrary foreign addresses readable.

Update rejects a nonnull current Level whose byte+198 is zero, then reloads the manager FX pointer. The byte producer is an explicit caller dependency, not named as an assumed pause flag. On first setup it initializes the actual cache paths, applies one-time joystick/class values, then clears the cached target. A negative slow timer stores 500 and executes SlowUpdate before FastUpdate without querying dt. A nonnegative timer captures its old value, queries Application.GetDt, stores signed 32-bit wrap subtraction, and executes FastUpdate; crossing negative schedules SlowUpdate on the NEXT invocation. This timer is a UI scheduling input, not a second actor elapsed update.

All status/skill/potion/levelup/enemy/ally/death portions are included. Source HP/MP/XP arithmetic comes from the frozen player-values kernel. Potion text precedes status writes. Skill map lookup and usability queries are interleaved in source order. Cooldown frames retain ARM truncation, wrap subtraction and original lack of an upper clamp. Source online traversal retries the same ally cache after a remote player and does not increment the player index for an unready/null-actor player. Ally indices are exactly 0,1,2. Enemy target queries reload three times; a selected third AI query returning null is not replaced by the earlier raw target. Visibility, labels, debug name/network ID versus localized name/level, target-loss clearing and HP frame ordering are preserved.

The original manager constructor initializes its byte+4=false, timer+8=-1, FX+57c=null and 29 caches, but leaves cached target+0 untouched. The logical constructor input must reflect that caller state; the implementation does not claim a source constructor reset that does not exist. The projected initialized field represents the source byte. Cache indices are exactly `(original_offset-0xc)/0x30`.

## Retained native core connection

The sidecar does not own strong AS object handles and cannot rebind after its original owner expires.

The sidecar uses native weak proxies and parent traversal. Full source assert/logger/automatic-refresh modes are outside this fixed constructor domain. A missing weak result is delivered null; only the manager's original null guards accept it.

General retained sprite goto/play uses the existing original instruction-proved timeline kernel, real upstream frame-tag and reverse-tag traversal, copied pending/goto action identities, and required weak-parent advance/sound services.
