# Original typed contribution kernels

The capture manifest identifies six actual routines in the supplied ARM32 ELF SHA256 `36498eb8180ffb74759e6305e9596db999f18583d460f3b8534abcb6022f5e80`: scalar `620134`, node Position `626b4c`, node Scale `6275fc`, quaternion contribution `6130d4`, quaternion interpolation `612d00`, and normalization `35c8f0`. The first three receive unused `this`, contiguous values, weights, signed count and stack output; quaternion receives values/weights/count/output directly. Values have1,3 or4 float components per slot. Quaternion is XYZW.

Scalar/Position/Scale count0 write positive zero. Count1 copies the first value exactly, including signed zero and NaN payload, without reading weights. Larger counts initialize positive zero and perform separate rounded float multiplication/addition in slot order for each component. Zero-weight contributions are multiplied as well, so zero times infinity can create NaN. The producer neither filters negative weights nor normalizes weights. Position and Scale execute independent original routines in the corpus and map to the same native vector3 implementation.

Quaternion count<=0 and all numeric-zero weights produce identity `(0,0,0,1)`. Negative zero is numeric zero; NaN weight is nonzero. The first nonzero contribution is copied without normalization. If its weight equals1, the routine immediately returns and ignores every later contribution. Otherwise accumulated weight starts at that first weight. Each subsequent nonzero contribution adds its weight in float precision, divides its weight by that rounded accumulated sum, and executes actual `612d00` interpolation against the current result. A cancelling sum can produce infinite/NaN ratio. No additional quaternion normalization is performed by the contribution producer; normalization in the close-dot interpolation branch belongs to the recovered interpolation routine itself.

The native exports in `animation_blend.hpp` are `dh2_animation_blend_scalar`, `dh2_animation_blend_vector3`, and `dh2_animation_blend_quaternion`, each `(output,values,weights,int32 count)` returning0 on success and1 on malformed binding before any write. Caller contract: count0..65536, float alignment, nonnull read spans, and disjoint output/read spans. Inputs may alias one another. Count0 needs no input pointers; scalar/vector count1 ignore weights, which may be null. Finite and nonfinite IEEE values are accepted. Inputs remain immutable. Arithmetic NaNs have classification parity; copy branches retain exact bits. Native bounds/alignment/output-overlap rejection is an explicit caller contract, not recovered ARM32 validation. The original quaternion negative-count identity behavior is outside the accepted native count domain; scalar/vector negative counts are not executed as valid inputs.

The original-instruction differential executes5786 cases:1053 scalar,1053 Position,1053 Scale,2627 quaternion. Cases cover empty/count1, ignored null weights, exact signed-zero/NaN copies, first-weight1 early return, zero/negative/nonfinite weights and values, cancellation, slot-order rounding, normalized and nonunit quaternions, and aliasing read inputs. Optimized ARM64 can lower `sqrtf` to `FSQRT`; complete resulting words are still compared. This does not establish historical Android Bionic libm parity.
