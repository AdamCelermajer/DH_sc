# Native source animation registration adapter

`animation_registration.hpp/.cpp` preserves the separate source engine library-occurrence vector and game dictionary-ID map. Source evidence is the32-routine original manifest and actual Prince producer/LoadAnimation probes in `../prince-registration`. Original ELF SHA256 is `36498eb8180ffb74759e6305e9596db999f18583d460f3b8534abcb6022f5e80`.

Every `LoadAnimation` call appends a CCDB occurrence before unique map insertion. Duplicate IDs therefore append while retaining the first map value's resource identity/index. `_UpdateAnimationIndices` traverses that map and scans the library vector for the first matching **first CCDB word**. An aliased resource shared by different dictionary IDs can initially receive different append indices, then map to the same first index after refresh. Native `RegistrationSet` retains exactly these transitions.

Resource identity is a caller-supplied64-bit canonical token, replacing the original cache/control pointer. Player pointers are borrowed and are not used to infer identity. The caller owns loading and stable lifetime. `set_default` models the independently loaded designated DB in AddTemplateAnim; it changes neither vector nor map. The default Player may be a separate load from the appended occurrence, as the source has two loads.

`compiled_inputs()` supplies unique synthetic keys equal to the true engine occurrence indices. This satisfies existing TransformSet's unique-ID contract while preserving158 library entries backed by116 source resources. Resolve game dictionary IDs with `lookup()` for clip selection and keep authored sequence/clip metadata keyed by source IDs. A coordinator must make that bridge explicit; a116-entry deduped compilation is not equivalent.

The bounded caller contract rejects negative dictionary IDs, zero resource identity, null Player and more than1024 occurrences atomically. Default selection rejects null/zero separately. No original invalid-resource loader semantics are claimed. Missing native lookup returns-1; the caller must report missing selection. This module neither loads resources nor compiles/samples poses nor dispatches events/owns clocks.

`animation_registration_differential.py` executes actual original LoadAnimation, database append, unique red-black map insert/lookup, UpdateAnimationIndices and setDefaultAnimationLibrary. File loading supplies identity-preserving resource handles; string-storage, allocation, profiling and clock are explicit services. The map and registration routines are never intercepted. Its42case corpus includes the complete158-request Prince producer, unsorted IDs, duplicate IDs with changing identities, cross-ID resource aliases, empty/single banks and high64-bit migrated identity tokens. Native O2 ARM64 exports execute and match2529 appends/lookups,2120 map entry checks,42 refreshes/default transitions,210 caller guard rejections, with0 mismatches.

`animation_registration.cpp` host test replays that original-derived corpus under ASan/UBSan. It checks every retained Player pointer, synthetic compile key, dictionary entry and index; rejected calls preserve occurrences/map/default pointers. A separate full1024entry fixture proves capacity rejection. Link only tests/animation_registration.cpp and animation_registration.cpp, with `-fsanitize=address,undefined -fno-omit-frame-pointer`; no DSOs/libm wrappers are required. Parent owns CMake wiring.

The full Prince compiler still has a separate component-channel boundary described in `../prince-registration/NOTES.md`; this adapter does not bypass it or claim full native blended playback integration.
