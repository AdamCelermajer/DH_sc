## Done

- GetMemberIDByString family (135 functions): `src/member_ids.cpp`, `include/pydata-accessors/member_names.hpp`.
  - Arrays (68): loop over `m_memberNames[size]`, first match wins, else -1.
  - Structs (67): records `m_dataNames` with a per-class count. The 18 single-name and 8 two-name

    The stride/offset is a layout detail of the original; the port stores names as a plain

## Structs records (`gen_structs.py`, wave 4)

- Generator: `python3 port/decomp-reconstruction/pydata-accessors/gen_structs.py --through N`
  (`--through 1000` selects every eligible class; the output is the same for any N of 550 or more). It
  reads the pseudocode of every queued `Structs::X` destructor (D2, D1, D0), finalize and read through
  `tools/decomp_extract.py --address`, so ledgered functions are included and the output is cumulative.
  Classes are taken in name order with their bases, until the function count reaches N. It writes
  `include/pydata-accessors/structs_records.hpp` and `src/structs_records.cpp` whole, and replaces only
  its own rows (source_file `pydata-accessors/src/structs_records.cpp`) in ledger.csv. `--dry-run` shows
  what was selected and why the other classes were left out.
- Accepted shapes (anything else leaves the class out, and its rows stay queued):
  - D2/D1: optional vtable store, optional `if (field != 0) CustomFree` blocks, base destructor last.
  - D0: own D1, then CustomFree. This is the deleting variant.
  - finalize: optional base finalize call and conditional CustomFree blocks, in listing order.
  - read: optional base read call and `StreamReader::readAs<T>` stores at fixed offsets, in order.
- A class is emitted only if its base is emitted (or is `ScriptCmd`), every base call names an ancestor
  that has the method in its emitted chain, a stored offset is not also freed, and no derived class
  redefines an ancestor offset. Qualified base calls (e.g. `Anim::read` calling `SimpleAnim::read`)
  stay qualified.
- Verification: all 529 functions were checked against the pseudocode for stores (offset and type),
  frees and the D0 shape, with zero mismatches. About 16 functions were hand-checked against the listing,
  covering D2, D1, D0, finalize with and without frees, reads with and without base calls, and
  int16/int32 stores. `structs_records_test` decodes SimpleAnim and Anim reads, checks a short stream,
  runs AnimStep finalize and the deleting destructor.
- Decisions:
  - D2 and D1 share one C++ destructor; both addresses are in its comment and both have ledger rows.
    The vtable store is compiler-generated, and the base destructor runs after the body as in the
    original. The original's `return param_1` is dropped (ABI detail).
  - D0 is the free function `Structs::DeletingDestructor(X*)` (overloaded per class). It calls
    `self->X::~X()` (non-virtual, as in the original) and then `CustomFree(self)`.
  - read and finalize are non-virtual methods. The original's vtable slots +0x8 (finalize) and
    +0xc (read) are not modelled; the Arrays port needs them virtual.
  - Freed words are `void*` (the CustomFree argument). finalize and the destructor do not reset them,
    as in the original.
  - Field names are `m_wN` (word N, offset 4*N) or `m_offN` for unaligned offsets. Comments carry the
    original 32-bit offset. Base fields are not repeated in derived classes.
  - Stored types come from readAs: int32 (`i`), uint32 (`j`), int16 (`s`), float (`f`). `bool` (`b`) is
    uncertain, so a read that stores one is `partial`: CharEffect, ItemPowerEntry, Projectile,
    RepeatableSprite, TriggerPlate.
- Layouts inferred (offsets are the original 32-bit ones):
  - `AIFaction`: int32 at +0x4 and +0x8, root, no-op destructor.
  - `SimpleAnim`: int16 at +0x4 and +0x6. `Anim : SimpleAnim`: int16 at +0x8 and +0xa, read calls SimpleAnim::read.
  - `AnimStep`: freed pointer at +0x24. `AIProps`: freed pointer at +0x2c.
  - `FriendlyNPCProperties : CharacterProperties`: a read thunk to `CharacterProperties::read`, no fields
    of its own (see the thunk section).

## ScriptCmd command classes (`gen_script_cmd.py`, wave 6)

- Generator: `python3 port/decomp-reconstruction/pydata-accessors/gen_script_cmd.py`. `--dry-run` prints
  the accepted classes and the reasons for the others; `--check` compares every emitted body with its
  pseudocode (see Verification). It takes the queued `ScriptCmd` and `Structs::X : ScriptCmd` functions
  through `gen_structs.collect()`, rewrites `include/pydata-accessors/script_cmd.hpp` and
  `src/script_cmd_records.cpp` whole, and replaces only its own ledger rows (source_file
  `pydata-accessors/src/script_cmd_records.cpp`). Rerunning it is idempotent.
- Emitted: `ScriptCmd` (5 functions) and 78 of the 80 command classes, with their destructors (D2, D1,
  D0 as `DeletingDestructor`), finalize and read: 395 ledger rows. 55 of them are thunks: a 4-byte body
  whose `b` target in the ARM listing is `ScriptCmd::finalize` or `ScriptCmd::read`. Thunk targets come
  from the listing only, because Ghidra prints the target's body for a thunk and the shared resolver
  (`gen_structs.thunk_target`) is ambiguous when that body is one readAs call.
- Left out, their rows stay queued and the classes keep their previous members:
  - `PlayEffect`: its destructors call `Structs::Pos3D::D1Ev` on the embedded member at +0xc, and its
    read calls `Pos3D::read`. `Pos3D` is not a class of this category yet.
  - `ExecScript`: its read stores a count at +0x10, then loops `count` times reading ints, the same
    element-loop shape as the blocked Structs classes below.
- Read shapes (`parse_read`, beyond the Structs grammar): a string buffer `V = MemoryHintState(len + 1)`,
  `ptr = V`, `readStringEx(stream, V, len, 0)`, `ptr[len] = 0`; a free `if (ptr != 0) CustomFree()` before
  it; and a guard `if (ptr == 0) { ...; return; }` followed by `CustomFree()`, which the decompiler marks
  as not returning. The guard is emitted as `if (ptr == nullptr) {...; return;}` then `CustomFree(ptr)`,
  the free convention used everywhere else in this category.
- Layout (decisions):
  - `ScriptCmd` has `std::int32_t m_w1` at +0x4 (its read stores it). The derived classes do not repeat
    +0x4: the previous header declared it in 37 classes, and those members were dropped.
  - Words a read stores take the read type (int32, uint32, int16, float). `bool` (`readAs<bool>`) is
    uncertain, so a read that stores one is `partial`: AIEnableTimer, CloseDoor, HideFlash and the other
    reads that store `b` (18 rows).
  - Freed pointers are `void*`. String buffers are `char*` (AIChangeScript +0xc and +0x14, AIDoSkill
    +0x10, and so on).
  - Words the previous header declared that no read or free covers stay `std::uint32_t` (the words the
    constructor zeroes, from the earlier hand-written header). Previously uint32 words that a read stores as int32 (for example
    LockTutorial +0x8) now have the read type.
  - Field names are `m_wN` (word N) as in `structs_records.hpp`. `GetNewScriptCmdDataInstance<T>` and its
    explicit instantiations in `src/script_cmd.cpp` are unchanged, so `script_cmd_test` still passes.
- Stub change: `deps/stream_reader.hpp` gives `MemoryHintState` a default hint of 0. The one-argument
  allocation calls in the pseudocode show no hint, so the default is the port's choice, not a value
  from the listing.
- Verification:
  - `--check` compares 340 non-thunk bodies with their pseudocode, event by event (readAs with its type
    and offset, free, guard, allocation, readString, base call, return): 0 mismatches. Thunks are
    checked by the listing (above).
  - `tests/script_cmd_records_test.cpp` reads ScriptCmd (int32), AIChangeScript (two NUL-terminated
    strings, then `delete`) and AIDoSkill (one string behind the null guard, then `finalize` and
    `delete`) from a byte stream, and checks a short stream. Host and Windows (MinGW under Wine) pass.
- Not done, but measured: the string and guard read shapes above would unlock about 30 more Structs
  functions in `gen_structs.py` (580 in an in-memory experiment, 550 now). They were not ported into that
  generator, because that would change its wave-4 output.

## Thunks: read and finalize forwarders (fixed)

- Defect: 43 `Structs::<Class>::read(IStreamBase*)` functions, all derived from CharacterProperties
  (AssassinProperties, MadrukProperties, SlimeProperties, PlayerProperties, ...), were emitted with a
  224-line body. In the ARM listing each address is one instruction, `b #0x4f2750`, a tail call to
  `Structs::CharacterProperties::read` (0x4f2750). The copied body was that function's body, so every
  child had 224 duplicate int32 fields and read the same words as the base.
- Why it happened: the generator took each queued function's pseudocode as its body. Ghidra prints a
  thunk as its target's body, so the copy looked like the class's own read. The index
  (`recovered/native/decompiled/libDungeonHunter2.so/function-index.jsonl`) marks these functions
  `is_thunk: true` with `body_bytes: 4`; the generator did not look at that. The base 0x4f2750 was not
  in the queue at all: `tools/decomp_categories.py` reserves the `Character` name pattern to the
  live-gameplay session, so the base had no port body and no ledger row.
- Fix in `gen_structs.py`:
  - A thunk is a forwarder. Its target comes from the listing (`b #0x...`). A pseudocode body that is
    one call of a Structs member is also accepted, and must name the same target. The thunk's own body
    is never read.
  - The forwarder is `Base::read(stream)` (or `Base::finalize()`) and nothing else. It has no fields.
    The target's class must be an ancestor with that method emitted, or the class is left out.
  - A non-queued target (the base read 0x4f2750) is added only if an emitted forwarder needs it, and
    only if adding it keeps every class that was emitted without it. `resolve()` checks this.
  - Output: a `// thunk: b 0x..., forwards to X::read` comment above each forwarder, and the ledger
    note `thunk, b 0x...: forwards to X::read`.
- Result:
  - `CharacterProperties::read` (0x4f2750): 224 int32 fields `m_w1`..`m_w224` at +0x4..+0x380, ledger row
    `reconstructed`. The listing has 224 `readAs<int>` calls at this+4 .. this+0x380, in order.
  - The 43 child read thunks are forwarders. Their fields moved to the base.
  - 46 finalize thunks whose emitted bodies were empty copies are forwarders too (for example
    `SwampKingProperties::finalize() { CharacterProperties::finalize(); }`). Same behaviour, no copy.
  - Four read thunks that were left out by the field-overlap check (their copied bodies repeated the
    base's fields) are now forwarders and are emitted: `GameOptionSelect`, `GameOptionSlider` and
    `GameOptionToggle` (forward to `GameOption`), and `SoundEventAutoGen` (forwards to `SoundAutoGen`).
    They are among the other read thunks, so they are called out here for review. The other thunk
    read classes (ItemPower*, ScriptCmd subclasses, the v2 conditions and quest rewards) are still not
    emitted, for the reasons in the Remaining section.
- Verification: the generator rerun is byte-identical. The header and source were checked against an
  independent transform of the committed files (ARM-listing facts, not the generator), diff empty.
  `tests/structs_forwarder_test.cpp` reads one fixed buffer through the base and through four
  forwarders (and through a short stream) and compares all 224 words. Host and Windows (MinGW under
  Wine) builds pass.

## Remaining (871 queued)

Blockers, by cause. None of these has a decided model in these notes, so none is written yet.

- Structs (738 queued). The 100 classes that `gen_structs.py` leaves out ("unparsed function") fail on
  the shapes below, and classes that derive from them are left out too ("base not emitted" 33, "base read
  call unavailable" 13):
  - element-array loops: a destructor or finalize that loops over element pointers and calls each
    element's virtual slot (`do { ... (**(code**)(p + 0x4))() ... } while`, for example `LangSheetList`,
    `Sound`, `SpawnGroup`). All 62 classes whose destructor does not parse have such a loop;
  - reads with a count-driven loop (ExecScript) or a call into another class's read (`v2Condition::read`
    112 bytes, `v2QuestReward::read`), which blocks the v2 reads (`v2IsEventInState`, `v2QuestReward*`);
  - PlayEffect (see the ScriptCmd section).
- Arrays (121 queued: about 70 finalize, 51 read). Each element is a polymorphic record, and the finalize
  and read bodies call element virtual slots (+0x8 finalize, +0xc read, +0x0 D1) at a stride of 0xc or
  0x18. The virtual-slot model is not decided (`vtables-001.json` maps the vtable addresses, but no
  Structs virtual finalize/read exists in the port yet). Blocked by decision; not written.
- PyDataArrays (6). `Load` is 8200 bytes, over the 4000-byte limit, a switch over the pydata file names.
  The constructor is 7852 bytes. The destructor walks an old-STL `std::priv::_Rb_tree` of per-entry
  vectors of function objects and erases the map nodes. registerClassByName (140 bytes) stores a factory
  pointer with `std::map<std::string, ...>::operator[]` after a `gAssertLevel` check. Needs a std-map
  stand-in decision and the Arrays finalize model.
- PyDataConstants (6). The constructor and destructors (72, 88 and 20 bytes) reset an old-STL
  `_Rb_tree` member, and getConstantName (204 bytes) walks the nested tree by hand (it returns the string
  at node +0x24 for the first entry whose int at +0x28 equals the argument, else ""). reloadData (644 bytes) uses DebugSwitches, a 256-byte stack buffer for
  `readString`, and a stack-protector check. Needs the same std-map decision.
