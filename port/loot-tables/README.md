# Reconstructed loot cache reader

`loot.c` validates the complete eight-table `loot_table_pyarray.bin` and exposes
borrowed record spans plus typed item fields. It uses source-owned layouts;
original ARM32 vtables and pointers do not enter these objects. Strings remain
length-bearing byte spans, including embedded NULs. Float fields preserve their
32-bit payloads without conversion.

The caller keeps input bytes alive and immutable. Files over 4 MiB, truncated or
trailing bytes, unreasonable counts, bad indexes and output/input aliases are
rejected without modifying outputs. The owned Lua layer copies validated bytes.

## Original reader evidence

The actual original ARM32 readers consume all **284,104 bytes**, SHA-256
`4dd85c8656d60c38a0c651e999fd18a1ed4d936f7cfdfcec52a1dfb4b568847f`.
The ordered name counts agree for every table:

| Table | Records | Serialized start–end | Original record stride |
| --- | ---: | --- | ---: |
| DropTilePriorityTable | 1 | 0–44 | 12 |
| InventoryTable | 3 | 44–54 | 8 |
| ItemList | 186 | 54–6,486 | 12 |
| ItemTable | 1,322 | 6,486–229,006 | 164 |
| ItemTypeList | 9 | 229,006–229,060 | 12 |
| LootTable | 339 | 229,060–282,872 | 36 |
| MerchantTable | 12 | 282,872–283,108 | 20 |
| NumProbArray | 39 | 283,108–284,104 | 12 |

The [reader trace](../../reports/loot-table-reader-trace.json), generated by
[trace_loot_tables.py](../../tools/trace_loot_tables.py), records every native
scalar, string and nested list destination, original function byte hashes and
execution counts. Virtual reads and bounded zeroed storage/disposal are explicit
models. This trace does not execute inventory operations or gameplay.

All 1,322 portable items match the actual original destinations on host and
compiled source ARM64 in Unicorn. All 589 other records match host record spans;
19 selected other spans also run on source ARM64. See the
[equipment comparison](../equipment-bonuses/differential-validation.json).

## Reproduction and limits

Build and test this reader with [equipment-bonuses/build.py](../equipment-bonuses/build.py).
It implements table boundaries and item decoding. It does not select random
loot, enforce merchant rules, equip items, own an inventory or construct a
Character. Original cache inputs remain external; see [rights](../../RIGHTS.md).
