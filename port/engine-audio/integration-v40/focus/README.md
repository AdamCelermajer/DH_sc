# Staged shared audio focus and output ownership V40

This packet is reviewable source work, not an application integration or audible acceptance. `application-java.patch` changes only MainActivity, FrontAudio and NativeBridge against `captured-source-sha256.json`; `staged/java` contains those exact proposed results and the two new Java helpers. Shared application sources, CMake, V34 and frozen handoffs were not edited. Root must merge its native source/runtime contract and build additions before applying the Java patch.

## One focus owner

`SharedAudioFocusV40` is the sole Android focus requester for the MainActivity title/menu MediaPlayers and native gameplay output. Its injected FrontAudio uses `setFrontDemand` and `canPlay`, and releases only its own demand. Native demand comes from `NativeBridge.audioSourceReadyV40()`, which reads the actual source initialization mailbox. FrontAudio stopping during menu-to-world handoff does not abandon a focus lease needed by native audio. API26 requests use GAME attributes, no delayed gain, and pause on duck/loss; the existing API23 front backend retains a single legacy listener. Native AAudio remains an explicit API26+ requirement.

MainActivity publishes actual onResume/onPause and onWindowFocusChanged state. Both resumed and focused must be true to request focus or play. Construction starts inactive. All focus policy operations occur on the UI thread; denied focus does not create an automatic request loop. A new foreground or complete demand transition permits another request. Old callbacks after close are ignored. CinematicActivity retains its separate existing movie focus owner; the actual MainActivity pause/window loss releases and mutes this owner's audio before that other Activity requests focus. This packet does not change movie playback.

`AudioFocusPolicyV40` is pure Java and has61 executable checks covering a shared front/native lease, transient/permanent loss, deny without retry loops, background/window transitions, teardown and stale callbacks. New Android focus helpers compile with all Java lint warnings fatal. The staged complete application Java set also compiles; only pre-existing deprecated/restricted SDK API warnings are excluded for that complete set.

## Native gate and thread contract

`AudioLifecycleGateV40` accepts one monotonic Activity owner32/sequence24 mailbox. A newer Activity replaces the old owner, stale sequence/owner messages are ignored, and a destroyed owner cannot reopen itself. JNI `audioActivityV40` only publishes flags; it does not open streams, post mixer commands, perform IO, or use GL callbacks.

The root's actual source owner calls `begin_source()` before initialization/replacement and retains that epoch. After `AudioGameplayRuntimeV40::initialize_exact_source` succeeds, the GL producer publishes `publish_source(epoch, runtime.source_data_initialized())`. This is actual data readiness, not World phase, viewport size or an invented game state. Old-epoch publications are rejected. A context rebuild that really replaces this owner must begin a new epoch and complete the close barrier below before touching borrowed mixer/catalog storage. If audio CPU ownership is retained across a purely graphical rebuild, the root must retain the same actual audio owner rather than replacing it from a GL context assumption.

The output callback uses `permitted_for(bound_stream_epoch)`, which reads the complete source epoch/readiness atomic and actual Activity/focus flags. A new epoch or focus/background loss mutes callback output immediately at the next buffer boundary. Muted callbacks advance only the output clock and preserve voice cursors. They do not drain the SPSC command queue. No callback IO, allocation or locks are added.

`AndroidAudioOutputV40` is a new versioned output implementation. Construct/use/destroy it on one dedicated control thread. It resolves AAudio at runtime, opens only while the gate permits actual foreground/focus/data readiness, and makes start/pause idempotent. An epoch change closes the old stream before reopening. Error callbacks only publish inaudible/disconnected atomics; control `recover()` performs close/reopen against the current gate. `snapshot()` is control-thread-only and returns the real AAudio timestamp position/monotonic time/rate plus mixer base and generation. It never exposes AAudioStream pointers to GL. Generation combines source epoch and stream generation.

`AudioControlV40` borrows the parent's mixer, `AudioClockV40` and gate. Its dedicated thread calls `tick` on a bounded control cadence (for example20ms plus shutdown notification). `tick` recovers/applies output and publishes the real clock, or invalidates it when unavailable. `ready_for_current_source()` is a thread-safe source-ready leaf: valid published timestamp, actual output audible atomics and exact applied source epoch must all match. Use it in `AudioGameplaySourcesV40::output_ready`; do not read the runtime's ordinary bool from another thread or a raw stream pointer from GL. Source RNG/load prefixes remain in their original order before this gate.

## Concrete native session owner

`AudioNativeSessionV40` now owns the complete producer runtime and the dedicated control worker, rather than leaving their lifetime to independent globals. Construct it on the actual GL/gameplay producer with the actual manager identity, unchanged source services, a shared lifetime lease covering every provider receiver/World, and `application_audio_gate_v40()`. Initialization is explicitly single-use. It claims the one application session slot, begins its source epoch, loads exactly the generated member/name streams and selected XML on the producer, publishes the actual parsed/bank readiness, and constructs `AudioControlV40` on its worker. Source initialization can finish before the first real driver timestamp; this does not claim output ready.

All positive categories must bind `session.submit_actual_play(actual_play,actual_event_monotonic_ns,error)`. The session preserves original gate/RNG/asset receiver contexts and delegates source commands back to the original context; it wraps the output-ready leaf with a mutex-protected live control pointer and the exact current source epoch. No callback locks are introduced. `runtime_on_producer()` is a borrowed root-only diagnostics, receipt, preload and guarded music-state scope; it must never be bound directly to a positive producer while the session owns output, since that would bypass the session's accepting/teardown lease. Stop new preload/state mutations before requesting closure.

`request_output_close()` is independently callable from UI/native lifecycle code and signals a condition variable; it requires no queued GL task. It disables submissions and source readiness immediately. The producer's `shutdown()` posts its World stop, requests close, waits for a known result with a bounded timeout, joins only after exact close success, supplies the parent's mixer-identity/close-completed/control-joined atomic proof to `finalize_after_output_closed`, and then releases the runtime and provider lease. The worker destroys control on its own thread before completing join.

A failed or throwing close wakes the producer with false while the worker retains the complete control owner asleep on the condition variable. It does not join, free callback storage, repeat close, or permit another session claim. The new output's failed-close state is sticky even if the failure occurred during disconnect recovery, so later shutdown cannot repeat an uncertain AAudio close. A timeout similarly retains the owner until a later producer shutdown observes a definitive result. Destruction with a retained runtime/thread/claim terminates; root must keep a failed session and its provider lease alive. Do not automatically retry session initialization after a failed attempt.

A borrowed exact-read or allocation exception before control construction is caught separately: no output callback has existed, so source readiness is invalidated, the partial runtime is released, and the application session claim is safely cleared. The failed object remains single-use; root may destroy it and explicitly create a new owner with valid providers. A UI close request arriving during source IO cannot be overwritten by a later readiness publication; the request and publication are serialized by the session mutex.

`control_error()` copies the exact worker failure under its mutex for root diagnostics. If an actual library/open/format/start/pause/close failure prevents readiness, the output-ready leaf reports that failure instead of masking it as generic readiness. Tick failure disables subsequent tick attempts; root receives the required failure without a retry loop. It remains possible to request one proper shutdown; a prior failed close cannot be retried.

The root's narrow native wiring is: create one session with actual World/GS providers on the producer; bind its typed transport to every existing positive category; poll/pump its receipts on that same producer; signal `request_output_close` from the independent lifecycle/owner mailbox; execute producer shutdown before World/provider storage is freed; retain any failed session. Add the five new native TUs plus parent runtime dependencies to the eventual application build. The JNI Activity snapshot helpers stay mailbox-only. This packet does not create a World, choose a listener, force phase38, or invent a viewport.

## Close and release barrier

The root is responsible for the following ordered lifetime operations; no queued GL task can be assumed to execute after GLSurfaceView.onPause:

1. On the actual GL/gameplay producer, stop accepting new World submissions and begin/invalidate the source epoch. Keep runtime, bank, mixer and all sample pins alive.
2. Notify the dedicated control thread through its independent mailbox/condition signal. That thread calls `AudioControlV40::shutdown(error)`. It stops future ticks, invalidates clock/readiness and calls AAudio stop/close. Only a successful close publishes `close_succeeded()`.
3. While the control owner is still alive, copy that success into the root's external teardown receipt. Destroy the output/control owner on the same control thread after successful close, then join that thread. A failed close must retain the complete owner and borrowed runtime; do not destroy or automatically retry an uncertain driver close.
4. After the root has both exact close success and completed join, the GL producer may call the parent's `finalize_after_output_closed` with that explicit receipt. GL is then the sole temporary consumer for draining stop commands/rendering a bounded silent block and pumping terminal receipts to release sample pins. Control/Java must never post SPSC mixer commands or drain them while a callback exists.
5. Only then release or replace bank/catalog/mixer/runtime storage and publish a newly initialized source epoch. Clear any borrowed control pointer before destroying its owner. The actual producer lease must exclude submissions while teardown is in progress.

`close_succeeded()` proves driver close only; it is not proof of thread join. The application must record both operations for the exact owner. Output destruction with a live stream or on another thread terminates rather than freeing callback user data unsafely. This invariant is explicit and must be observed by root wiring.

Session fixtures parse the real original three assets and use an explicit borrowed fake control factory, absent from the production API. Build products stay under `.local-inputs/audio-v40-focus` and `.local-inputs/audio-v40-session`. Source hashes accompany receipts.

Real AAudio open/start/pause/recovery/close behavior, Android callback ordering, actual movie transition and audible playback remain unverified. No root APK build, emulator, device, ADB, viewport change or forced World phase was used. This packet does not establish current game sound acceptance.
