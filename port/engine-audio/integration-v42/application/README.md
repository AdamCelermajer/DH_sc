## Lifecycle barrier and limitations

Ordinary background pause updates the one shared focus mailbox and preserves the process manager/voice cursors. If finishing/configuration destruction is already known at onPause, `AudioApplicationLifecycleV42` independently requests native close, queues the actual producer shutdown while GL is still active, and waits at most2seconds before GLSurfaceView pause. A known completed producer shutdown provides the parent's real output close/join/drain barrier before unpublishing manager/provider state. A timeout or required failure retains the owner and logs the exact pending barrier.

onDestroy can follow an already paused producer, so its hook requests close independently and never assumes a queued task ran or frees storage. If destruction was not known before producer pause, the retained owner requires an explicit old-producer shutdown before any different-thread replacement. That seam is recorded rather than presented as solved. No fake consumer-thread transfer or finished barrier is manufactured.
