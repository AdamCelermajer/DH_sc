# Borrowed equipment requirements and refresh services

Source: AdamCelermajer/DH_sc, commit `791e961b12233100b303038c961666834f4beb9d`, `port/level-world/player_equipment_queries_v1.cpp` and `player_equipment_render_owner_v1.cpp`. `import-manifest.json` pins the exact source inputs. The query gold subset and disassembly retain only `Character::INV_DoesMeetRequirements` at `0x3a4930`; no cache/APK bytes are imported.

The five requirements read item words 29–33 against cached character fields 19, 149, 150, 151, 152 with signed arithmetic shift by eight. Fresh online and remotely-updated queries precede item lookup; online remote characters and null items pass through the source branch. Class requirement word 34 is not added. Queries do not grant or unlock anything.

The adapter borrows the existing `FreshInventoryOwnedV4`, its actual item/equipment slots and PropertyState, the caller's exact `PropertyView` with current buff-group bindings, immutable class/power tables, and live hook descriptor. `PlayerGearEffectsV5` remains the sole gear/class/vitals calculation. V4 remains the sole inventory and random service. There is no inventory, property, save, visual, localization, timer, frame or VM owner here.

Equip/unequip/swap retain the source mutation prefix, then gear properties, recursive requirement pruning and recalculation, Skin, and HP/MP validation. A required provider rejection keeps the reached source prefix. Auto-equip retains the existing V4 Character AutoEquip ordering and does not infer a later requirement check. Skin re-reads the caller's live VisualObject field. Public destructive adapter reentry from providers is rejected; V4 retains its own callback mutation guards.

Native integration requires genuine world queries, renderer/Scene/resource attachment validation, Skin/Debug providers and item lifetime observations. `required.observe_storage` must forget presentation entries and other item projections before V4 destroys an item; it never synthesizes storage or decides source deletion policy. V4's explicit destroy/merge/erase paths deliver that observation. The adapter validates the live binding before every direct bool effect and every storage delivery, including direct calls using `services()`. A missing/detached binding or failed real retirement at V4's void observation throws `EquipmentLifecycleFailureV1` before deletion. Direct V4 callers must catch it; adapter mutation methods translate it to false/error. The reached quantity/slot/insert prefix persists, and the actual incoming item remains alive. A required retirement provider must throw if it cannot complete; the adapter wraps that delivery failure in the same typed exception. It never silently invents successful cleanup.

Failed split/create temporary ownership prefixes and final whole-inventory teardown also need presentation retirement on their actual lifetime exits before native binding; this adapter does not invent a destructor notification that V4 does not deliver. All borrowed contexts/fields/tables must remain alive. The actual caller must detach/rebind visuals before destroying the Scene, and retire the adapter before destroying the inventory or PropertyView. Source temporary lifetime exits that do not deliver V4 observations remain caller obligations.

Text/localization, notifications, powered-item continuation, HUD/icon updates, native inventory construction/save binding, actual resource-backed drawing and target combat remain separate caller obligations. Host fixture hooks explicitly simulate attachment, world, text and visual deliveries; they do not prove rendering or native gameplay.
