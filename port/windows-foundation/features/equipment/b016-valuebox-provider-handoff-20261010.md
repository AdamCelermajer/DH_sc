# B016 ValueBox source provider handoff — 2026-10-10

## Finding and source evidence

The source supplies `ValueBox/value` from the selected item’s `ItemTransmuteValueString`. In the recovered SWF action trace, `sprite456` frame 0 function `displaySelectedItemInfos` begins at `0x1c865`; it reads the current list row’s `ItemID`, calls `NativeInvGetItemDetails` with that ID at `0x1c8f8`, and then assigns the returned string to `menu_InventorySheetDetails/btn_GAMEPLAYMENUS_TRANSMUTE2/ValueBox/value` at `0x1cb6e–0x1cb84`. This is a static selected-item text refresh, so the field itself has no animation timing dependency. Its other sibling fields remain separate.

The native callback is IDA `NativeInvGetItemDetails` at `0x44ca5c`, as recorded in the existing [B016 equipment audit](b016-equipment-text-art-audit-20261010.md). It resolves the actual player and inventory item, then derives `ItemTransmuteValue` using the item instance's value, current resolved property 197, and `CharacterDesign.TransmuteMultiplier`; it sends the integer through the source StringManager/Item formatter as `ItemTransmuteValueString`. The recovered caller implementation in `port/engine-ui/character_menu_queries_owner_v1.cpp::item_details` uses the same property and multiplier, and `character_menu_item_actions_v1.cpp::character_menu_transmute_value_v1` preserves the source signed fixed-point wrap and minimum value. The amount must not be inferred from the localized `Value` label.

## Change and caller API

`RuntimeEquipmentTextProviderV1::transmute_value(selected, raw_property_197, source_multiplier, packet, error)` now returns a `RuntimeEquipmentTransmuteValuePacketV1` containing the current selected IDs, source item value, raw property 197, source multiplier, fixed-point transmute value, and source-formatted amount. It rejects a missing/stale current inventory selection and definitions outside the approved unpowered policy. The caller can assign `packet.formatted_value` to `DetailBindings::transmute_value`; the property and multiplier inputs must be read from the same current source context. This supplies the equipment-owned provider API; main/Details callback wiring and a visual capture remain integration work.

Expected focused observable behavior: with the selected original `Longsword01` row, the real CombatSession player's property 197, and the real design `TransmuteMultiplier`, ValueBox receives the formatted original transmute amount. A stale selection or unsupported generated item produces no amount and returns an error. The adapter does not alter the existing three field transforms or label/button projection.
