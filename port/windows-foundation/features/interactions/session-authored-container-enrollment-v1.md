- **Visual evidence:** reuse the retained source-backed BRES evidence documented in `session-authored-destructible-bind-v1.md` and the interaction integration report. - **Logic evidence:** the original handoff `reference/openable-container-v1/eligibility-source.asm` identifies `GameObject::MeetCondition` at `0x38ab60` (literal true) and `GameObject::CheckSpawnProbability` at `0x38bd64`; the latter reaches source byte5/network/owner/RNG leaves and failure hide/Delete/Mark prefix. `session_source_object_admission_v1.cpp` stages those effects and only publishes the candidate/mints `SessionContainerPriorAdmissionV1` after the accepted source sentinel `cached270 == -2`. The urn's original `Container::Interact` (`0x3a0b38`) and derived Destroyed/marker/drop sequence are recorded in `session-authored-destructible-bind-v1.md`; the current corresponding callers are `session_destructible_interaction_v1.cpp` and `session_admitted_destructible_v1.cpp`.

Candidate visual/model and the seven-byte OBJS component remain explicit source-built inputs.
- **Expected behavior:** for each decoded current-Level container declaration, source admission runs against its exact unpublished `WorldObject`; rejection publishes neither object nor visual/callback state. Acceptance produces a receipt tied to the same Session lease, ObjectId, definition name and `data_desc`, then initializes the matching modern openable/destructible behavior over that same WorldObject, retained visual, scoped Session RNG and existing drop/store owners. It does not create a native ObjectBase graph or infer admission from current world membership.
- **Uncertainties / provider gaps:** the available modern APIs do not construct source candidates from MGP/MVP/DataConnection rows or provide production Level candidate order, live online byte5/network/owner fields, object-specific constructor/probability fields, online channel1 RNG, or the original Level current-quest/audio/physical/script/stat/trophy owners. These remain typed required caller inputs. Source game-data mapping must build the exact model/transform/state and row validators must verify the model against the original table. Native Level OBJS room tuple import remains separate. Source `moth_spawn_container` reaches `_Summon`, which is unavailable here; no summon behavior is invented.

## Implementation and verification

`session_authored_container_enrollment_v1.{hpp,cpp}` adds `enroll_session_authored_container_v1`. It validates exact decoded declaration identity and candidate position before admission. The Openable branch delegates to the existing all-or-nothing `admit_and_bind_session_openable_v1`; the Destructible branch preflights the unique original row, admits once, forwards the exact receipt to `SessionAdmittedDestructibleV1::bind`, and rolls back only its newly published object/visual if post-admission binding fails under the same Session lease. Both branches return typed admission and interaction owners. Probability rejection returns a successful result with `admitted=false` and no owner.

The focused test extends `run_session_container_live_visual_integration_tests.ps1` with a second actual decoded `Swamp_Normal_Chest` declaration and the actual decoded urn. A misplaced chest candidate fails before RNG with no WorldObject or retained visual. Its corrected source position is admitted, enrolled, interacted with, and its authored opened marker publishes through the existing same-Session RNG/store path. The urn's existing negative receipt/provider checks run first; the isolated fixture then reconstructs its exact decoded candidate and exercises the new enrollment branch through its source `opened` marker into the same store. The runner also verifies silent state4 save/restore behavior and stale binding rejection. Strict Windows C++17 compile and native link/run passed with isolated diagnostic RNG seed 2 (needed to make the urn's source-selected row publish a concrete record after the extra source admission draw). Production provider integration and normal executable/visual verification remain with the integration lead.

## Main callsite handoff

For every decoded current-Level container declaration, the level/enrollment owner should build the source-mapped `WorldObject` and `SessionSourceObjectAdmissionRequestV1` from that exact `ActorDefinition`, then call `enroll_session_authored_container_v1` with the current `SessionContainerRetainedVisualV1`, existing same-session drop owner, and the real Openable or Destructible table/policy/service bundles. Pass exact `data_id_ec`, `network_id108`, `probability274`, optional online owner, byte5 callback, and a synchronous loan from the canonical RNG owner. On `result.admission.admitted == false`, skip interaction registration. On acceptance, retain the result owner alongside the current-Level definition/provider lifetimes and route source input/animation events to it; recreate it after GameSave/Session rebind. Do not call the lower-level `init_post` path after admission. Main/CMake/core integration was not changed in this feature pass.
