## Current host path and guard

The portable host's pause confirmation sets `returnToFrontend` at `main.cpp:2114–2124`. At `main.cpp:2230–2250`, before leaving gameplay it calls `RuntimeSkillCastCoordinatorV1::checkpoint_v1` and `CombatSession::validate_lifecycle_checkpoint`. If both are quiescent, it saves a live `GameSave` only when the controlled Session player is alive, updates `CharacterState` from the snapshot, then writes the profile. A failed checkpoint skips both writes but still leaves the gameplay loop. The return route reconstructs menu launch options and continues at `main.cpp:3007–3011`. This is a modern portability guard: source GoToMainMenu itself contains no cast coordinator check.

The new helper uses the current real owners: the same `CombatSession`, its lease/update serial, the actual `RuntimeSkillCastCoordinatorV1`, and the existing `capture_game_save`, `save_game`, and `save_character` providers. It stages current Session health/resource into a local profile copy, writes the live world snapshot first for a living player, then writes the profile, publishing the in-memory profile only after success. For a dead player it leaves the last world checkpoint byte-identical and writes the current zero-HP profile. Each file writer is individually atomic; the two-file sequence is not an atomic cross-file transaction, matching the host's existing prefix ordering.

## Expected behavior and caller contract

After the player confirms Yes, the main loop must call `request_v1` before latching or executing the frontend route. If it rejects because a source cast/cooldown or Session lifecycle is unpersisted, retain the current gameplay/pause owner and both save files; allow the source action to reach Post/cooldown quiescence, then require a fresh Yes request. If admitted, synchronously call `commit_v1` in the same Session update boundary before setting `returnToFrontend`. Only a successful commit permits normal teardown/reconstruction into `menu_MainMenu`; a failed save leaves the current Session and frontend route in place. No callback or second scheduler is introduced. Main owns the actual route switch and Session teardown, and must keep the same live `CharacterState`, paths, coordinator, and Session for the synchronous commit.
