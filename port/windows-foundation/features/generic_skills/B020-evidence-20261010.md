This is direct evidence that the selected-row admission gate has since been corrected in that candidate; the two captures are from different runs/builds, so the older mismatch is not evidence of a current failure.

**Recovered logic.** The authored `sprite496` caller in `port/engine-ui/reference/character-menu-flow-v1/authored-actions.txt` (`presetAllSkills`, `0x20b2d`) queries each class-list position through `NativeGetSkillDetails`, copies the returned `SkillLevel` into both rank counters, applies disabled state from `SkillAssignable` and rank, and sets `Lock.visible = !SkillUnlocked`. A rank-zero blank icon suppresses both Lock and Grey. The selected-row handler (`0x20e9a–0x210a1`) calls `NativeSkillsTrainSkill(true, position, player 0)` and assigns that result to Add Skill visibility.

`NativeGetSkillDetails` in `port/engine-ui/hud_initialization_v1.cpp:57` reads the selected source row, same-player level and rank, and exact SkillTable row. Its lock branch is `level < RequiredLevel`; it returns the localized unlock-at-level text and leaves Next Level empty. The source SkillTable has no separate `Available` field. `SkillAssignable` decodes from scalar word 11 (`port/game-data/skill_tables.cpp`); word 18 is the separate `Type` field. Training admission is a separate native test-only path, not an inference from the lock icon.

**Current implementation and provider.** `RuntimeSkillsMenuV1::append` projects Lock from same-state `CharacterState::stats.level >= signed RequiredLevel`, Grey from rank-zero plus nonblank source icon, and disabled state from source `SkillAssignable` plus rank. The normal `main.cpp` constructor binds selected-row admission to `probe_skill_training_in_session_v1`, after checking exact state/list/table identity. The release path repeats the non-mutating probe before the mutating same-Session trainer. The normal dynamic-details provider reads the same Session's resolved properties and actual source level/rank rules. This preserves the source's distinct visual unlock, assignability, rank, and training gates.

A selected row exposes Upgrade Skill only when the source test-only training kernel accepts the same row/state; rejected or unknown probes do not mutate rank or points. A trainable row still requires the native point, rank/level, and difficulty-cap gates.
