## Logic evidence

- Fresh-profile mapping: `features/frontend/creation/creation_adapter.cpp` maps `KnightPlayerBase`, `RoguePlayerBase`, and `MagePlayerBase` to actual CharacterTable FaeryList rows 1, 3, and 2. `runtime_creation_persistence_v1.cpp` checks CharacterTable `fields[29] == "FaeryList"`, reads the resolved source field, requires it to equal the selected profile's authored row, and stores that same row in `CharacterState::source_faery_list_id`. Fresh save construction initializes all three `current_faery` values and all 15 saved state/level pairs to zero. The existing source-backed test iterates all three actual source-created profile records.
- The actual Faery table cache has named lists `DEFAULT`, `Knight`, `Mage`, `Rogue`; lists 1, 2, and 3 all have rows `[1,13,14,15,7]`. Row 1 is `Celest`, with `SpellScript=faerie_celest`, so every fresh class-specific profile's selected slot 0 resolves to the actual Celest script. No Hotty fallback is valid. The `DEFAULT` list instead has rows `[2,4,5,6,3]`; row 3 is `Fake_Hotty` with an empty SpellScript. The actual playable Hotty is row 7 (`Hotty`, `faerie_hotty`) in the class-specific lists.
- The original `Character::GetCharFaery`/`CharAI::SetSkillsAndSpells` source path resolves that profile list, then loads each nonempty Faery SpellScript row into `m_spellScripts`; it does not read saved Faery unlocked state. `CharAI::AI_IsSpellUsable` (0x003d80b4) rejects only while using a skill/casting, when its script process is unloaded, when the selected spell script is null, or when that script's `OnSkillCheck` returns false. `CharAISkillScript::OnSkillCheck_Usable` (0x003da9dc) invokes `SetSkill` and then `OnSkillCheck`. `AI_BeginSpell` (0x003d81c0) routes a usable current script into `SM_SetCastState(current_slot)`. SWF `NativeHUDSpell` (0x0043cabc) calls the selected player's controller `Cmd_BeginCast` then `Cmd_EndCast`. Thus Save state zero is displayed locked by the Faery menu but does not itself block the authored Celest spell check.
- Exact authored Lua source: `.local-inputs/character-skill-session-v2/cache/data/scripts/skills/faerie_celest.luac`. `OnSkillUpdate_` reads current saved Faery level, caps to 1, computes base mana 10/20 plus `MulFixed(ToFixed(.2), player level)` (the recovered ToFixed implementation truncates .2 to 0 before shifting) and defaults `Faery_Cooldown` to 5000 ms when the source Int is zero. It also calls `CheckFaeries` for the passive resistance buff; that helper is distinct from cast admission.
- `OnSkillCheck_` returns `!HasSpellCooldown() && HasMana(mana_cost)`. `OnPreSkill_` configures Character=Enemy, Object=AttackableOnly, Sort=NoSort; runs `TargetListSearch(600/800)`; then debits mana, sets spell cooldown, and unconditionally plays `Celest_Level_1_Player`. It chooses small/medium/big lightning sound by target count and plays `StaticBallKilled` for an empty list. `OnSkill_` does nothing on an empty list; otherwise sets `SnS_Level`, applies `Spell_Lightning_1 + skill_level`, and loops the retained targets. A Character receives two consecutive `SpellCombatRoll(target)` calls, then an unconditional `Celest_Level_1_Main`. A GameObject receives one roll and target FX only when that roll returns positive. `OnPostSkill_` is empty.
- Event routing: the Cast animation state is source state 7. Authored `do_spell` event 40 (`0x28`) is the Celest `OnSkill_` boundary; focus event 32 invokes OnPreSkill and blur event 33 invokes OnPostSkill. The modern coordinator has the retained state7/`do_spell` guard, but its current Faery arm and target-use implementation are Hotty-specific; a script-kind Celest arm must call the same guarded event path, not Warrior state6/`do_skill`.
- `Character::F_SpellAttack` (0x003b3004) calls `_F_CalculateResult` with `mask | 0x1005554A`, category -1, the active Faery row's `SpellType`, and direct amount 0. `_SpellCombatRoll` (0x003b92a4) resolves the current Faery row each call, invokes F_SpellAttack, then F_ApplyResult, and returns the result's base damage. The two Character calls are unconditional at Lua level; they are not a single doubled damage request.

## Implementation and verification status

`celest_cast_v1.cpp` resolves the same-profile current Faery row and implements the source OnPre prefix: source-known state and exact script validation, authored rank cap and mana cost, source target-list/range validation, same-world mana debit, and 5000 ms cooldown. It deliberately does not use the UI unlock state as a cast gate. `celest_source_use_v1.cpp` applies two separate same-session `SpellCombatRoll` occurrences to each current Character target in retained NoSort order, then makes the Main FX call. When the first roll kills a target, the second occurrence uses root's `CombatSession::resolve_source_result_only`; its full `OriginalMeleeResolution` is retained separately in `CelestDeadTargetCalculationV1`, consumes same-session RNG exactly once, and does not apply another health/injury/death result. The Session's non-veto formula-resolution observer still receives that calculation.

Focused C++17 syntax validation passed for both Celest translation units with the local LLVM MinGW compiler. The isolated connected runner `run_hotty_session_cast_v1_tests.ps1` passed after the runner privately staged and SHA-256 verified the actual `prince_spell_channeling.bdae` needed by Mage `CharAnimTable.Spells[0]` (`1350178E7A87B8868FB6E4D34ACFCE79E27A77674058AA09DDD8625BB6F596EC`).
