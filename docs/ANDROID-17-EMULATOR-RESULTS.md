# Android 17 emulator results — 2026-10-02

The primary current-platform test used official Android 17/API 37 Google APIs x86_64 system images in separate Pixel 9 phone AVDs. No physical phone or Fold7 device was used. Both AVDs were given 4 GB RAM. The project-local SDK installation supplied Android Emulator 37.2.12, platform tools, build tools and NDK r29. See [the test plan](ANDROID-17-EMULATOR-PLAN.md) for the APK routes and source references.

## APK checks

The emulator-only signed Test 7 guest (SHA-256 `aa0628e277b7bc17aaa2273a257c3c624af52c525cdb9e606779cea42a85142a`) has `armeabi-v7a` native libraries and target SDK 24. `adb install` on each AVD returned `INSTALL_FAILED_NO_MATCHING_ABIS` with native-library extraction result `-113`. Thus its Android 9 menu behavior cannot be replayed directly on these Android 17 images.

The published Test 5 wrapper (SHA-256 `e6b81ec649e25bb32c6ec7f3f477d5ef1c2a79b7af43b7ca7643518c5f5e1b8d`) has `arm64-v8a` host libraries and target SDK 35. It installed on both AVDs with `adb install --abi arm64-v8a`, and `dumpsys package` reported `primaryCpuAbi=arm64-v8a`. On the 16 KiB image, Launch Game displayed: `This translation runtime currently requires 4096-byte memory pages. This phone reports 16384.` This is an explicit guard in the wrapper's Java source, before guest engine startup.

On the 4 KiB image, Launch Game started the plugin path, then Android's native loader reported `libnativeinterface.so is for EM_AARCH64 (183) instead of EM_X86_64 (62)` and threw `UnsatisfiedLinkError`. This happened before cache access or gameplay. Installing with `--abi arm64-v8a` did not make that plugin process accept a directly loaded AArch64 proxy. The error also occurred in the older Android 11 x86_64 diagnostic AVD. The cache was not imported for these published Test 5 wrapper checks.

## Later self-contained Test 7 package

A locally signed ARM64 package was built from the pinned Test 7 guest and exact 433,189,197-byte complete cache ZIP. Its APK SHA-256 is `85494d96aeb982025c984fadfa005b04b140b60b0e6cf96a5f90cca52e4a7c32` (446,949,980 bytes). Its APK v3 signature, ZIP CRCs and 16 KiB alignment checks passed. The game/cache inputs and generated APK remain outside Git; the build source is under `compatibility/work/fold7-build/`.

With clean app data, this package installed via `adb install --abi arm64-v8a` and unpacked its bundled cache on both Android 17 images. The launcher reported `Ready. Cache available`; 6,834 files, including one generated options file, occupied about 663 MiB of emulator storage. Launching the game still stopped at the 16 KiB page-size guard on the API 37.2 image and at the ARM64 proxy namespace mismatch on the API 37.0 x86_64 image. The complete cache is packaged and provisioned; gameplay remains unverified.

## Updated Test 7 namespace and ARM32 sysroot build

A later local Test 7 wrapper fixed the translated plugin's native-library namespace search path and bundled ARM32 sysroot aliases required by the API 37.0 emulator. Its signed APK SHA-256 is `26a5460eae8f3adb43ad8e6886a77afd08d024bfed26bbe3120324ab8269ee65` (448,470,789 bytes). It passed signature, ZIP uniqueness/CRC and alignment checks. This is a separate build from the `85494d96…` package above. The build recipe and pinned inputs are in [`STANDALONE-TEST7.md`](../compatibility/work/fold7-build/STANDALONE-TEST7.md).

On a fresh, unrooted API 37.0 x86_64 emulator with 4,096-byte pages, this APK installed with the ARM64 ABI, provisioned the bundled cache and started the original native engine. Logcat confirmed the bridged proxy, guest JNI runtime, 32 bound engine natives, Storm and shader processing. Screenshots showed the opening cinematic and Dungeon Hunter title/loading spinner. After about 272 seconds, the emulator's ARM64-to-x86_64 translation layer aborted while allocating executable translation code (`berberis::MmapImplOrDie` / `CodePool::Add`). The menu and gameplay did not appear in this Test 7 run. The 16,384-byte-page AVD remained blocked by the wrapper's page-size guard.

## Test 9 model-path and display diagnostic

The later Test 8 guest replaced one failed save-job worker branch with an existing synchronous path. Its Android 17 wrapper passed the previous translation abort and accepted a saved character at the title, then failed while reopening the prince model through a duplicated cache-root path. Test 9 adds a narrow Storm file-open retry for that exact wrapper path. The Test 9 guest and wrapper inputs are pinned in [`STANDALONE-TEST9-PATH.md`](../compatibility/work/fold7-build/STANDALONE-TEST9-PATH.md).

The clean signed Test 9 wrapper is 448,470,858 bytes, SHA-256 `5f6b31b8988231df0dc9987f656347aae940b462baed91d8e9cadb2de6eaa143`. On a fresh API 37.0 4 KiB emulator install, it unpacked the verified cache and wrote its matching completion marker. It ran the original cinematic and engine, then logged `DH2FileGuard recovered repeated root` and successfully reopened the formerly fatal prince model. On this wide emulator screen, the default viewport clipped the Start button; enabling the wrapper's **Fit game to 16:9** option produced a complete 1920×1080 character menu. Start Game and Single Player touches were accepted; loading completed and rendered a saved 3D level with the prince, an enemy, HUD and controls. A joystick drag moved the prince several tiles and shifted the camera while the guest remained alive. Pause responded, returning to the main menu updated the visible last-save time, and that timestamp persisted after a force-stop/relaunch. However, the menu cropped again after that restart even though the saved fit option was still true and the game logged a 1920×1080 surface. Enabling **Keep graphics context during cinematics** as well showed the full menu on one subsequent relaunch, without proving repeatability. Attack damage and longer-session stability remain unverified; menu layout across launches is unresolved.

## Test 10 landscape sizing and clean gameplay check

The Test 9 crop came from the original guest calling `nativeSetPhone(1080,2009)` from portrait display metrics before it created a fitted 1920×1080 landscape surface. Correcting only the later GL viewport left the menu cropped. [Test 10](../compatibility/work/fold7-build/STANDALONE-TEST10-VIEWPORT.md) changes the initial size when the wrapper's 16:9 fit is on, then restores the fitted viewport after each surface resize. Fit is enabled by default on a clean install. The unsigned guest APK, rebuilt reproducibly from the pinned Test 9 guest, has SHA-256 `57cefd15cba47116a98fa96e406ba8d8a4ef90fb0e82185802a8f09210ba2b7e`.

The final signed Test 10 wrapper has SHA-256 `02ba96298aa2639e1bd3c3a34f0b54447756d85aed9e8ed85b3d53bf726964aa` (448,470,858 bytes). It passed signature, ZIP-entry CRC, and 16 KiB APK alignment checks. A clean uninstall/install on the 4 KiB Android 17 emulator imported the complete verified cache, showed the full-width character menu, accepted Start Game → Single Player, and loaded a saved Swamps 3D level. Three attack-button taps were followed by the nearby moth and its health bar disappearing while the process remained alive. A joystick swipe visibly moved the player and camera. Screenshots of the clean menu, before/after attack, and movement are described in the Test 10 source document and retained in the task outputs.

The same exact final APK later opened pause, returned through Main Menu confirmation, and displayed an updated last-save time (`02.10. 02:03`). After force-stop/cold relaunch, the full saved-character menu still showed that timestamp. Start Game → Single Player reentered the saved Swamps 3D level, and a joystick swipe again moved the player and camera with the guest process alive. The nearby enemy respawned on reentry, so this verifies a checkpoint return rather than exact combat-state restoration. An earlier signed Test 10 candidate independently kept the Start button visible through two force-stop/cold-relaunch cycles without graphics-context preservation. This is a bounded save-return and cold-reentry check; full save contents/quest persistence, level transitions, longer sessions, physical ARM64 devices, and other page configurations remain unverified.

## Test 11 saved English preference and 4 KiB gameplay

The signed Test 11 compatibility APK (448,474,954 bytes, SHA-256 `5eab6ee211bf711b2041b1da1392cb7b94a727ed1f3faa8226f044d02fb7919c`) uses the pinned Test 10 guest/cache inputs and wrapper version code 14. It was installed as an in-place upgrade over Test 10 on the 4 KiB AVD, preserving the earlier checkpoint. The wrapper backed up the recognized 294-byte settings file exactly and changed only the Language field from 2 to 0; in this fixture only byte 207 differed. It reported `English preference: UPDATED`.

The exact Test 11 APK displayed the saved-character menu and loading tips in English. Start Game → Single Player entered **The Boglands – Ancient Prison**. Joystick input moved the player/camera; two attack taps were followed by a nearby Bog Moth and its health bar disappearing. Pause → Main Menu → Yes changed the visible save time from 02:03 to 04:03. After force-stop/cold launch of this same APK, the wrapper reported `ALREADY_ENGLISH`; the English menu retained 04:03, loaded the saved level again and accepted another joystick swipe with visible movement. The process remained alive. See the [Test 11 source and build record](../compatibility/work/fold7-build/STANDALONE-TEST11-LANGUAGE.md). This is a bounded emulator result, not a clean-install Test 11 result, full save/quest validation or physical-device compatibility.

## Test 11 strict 16 KiB English gameplay

The separate strict Test 11 APK (448,474,954 bytes, SHA-256 `d688b2a9f4da0c387ea1ddb0448d9de95dd3e00cdac224fca1b1a6e01fa2898e`) was signed, 16 KiB ZIP-aligned, and installed as a version 14 upgrade over the saved strict Test 10 app on the API 37.2 AVD. Its first launch made an exact backup of the known settings file, changed only byte 207 to select English, and displayed the English saved-character menu. Start Game → Single Player loaded **The Boglands – Ancient Prison**, and joystick input visibly moved the player/camera while the process remained alive. Pause → Main Menu → Yes returned to an English menu and changed the visible last-save time from 02:11 to 04:21. After force-stop/cold relaunch of the exact installed Test 11 APK, the wrapper reported `ALREADY_ENGLISH`, the English saved-character menu retained `10/02 04:21`, and the native `PlayerLastSave` log agreed. Start Game → Single Player reentered the saved 3D level; the HUD appeared and joystick input visibly moved the player/camera again while the guest process remained alive. The captured guest log had no Scudo abort, fatal exception, signal 6 or strict origin-refusal marker. Startup and level loading each took several minutes. See the [source-only strict rebuild recipe](../compatibility/16k-port/TEST11-STRICT-REBUILD.md). This is an experimental emulator result, not a general 16 KiB compatibility claim.

## Reconstructed source runtime check

An independent x86_64 executable built from the reconstructed PVRTC decoder and BRES/material readers ran on the 16 KiB API 37.2 AVD. Synthetic PVRTC1 2bpp/4bpp and material/effect/sampler checks passed. The owner-supplied 1024×1024 atlas texture and 16,856-byte candle BRES also passed, with on-device SHA-256 values matching the host inputs. The executable's four load segments are 16 KiB aligned; it exited with code zero. See [`port/android-smoke/runtime-validation.json`](../port/android-smoke/runtime-validation.json) and its [reproduction steps](../port/android-smoke/README.md). This validates isolated new source components on current Android, not the original engine or a game scene.

The later [static scene draw bridge](../port/scene-draw/README.md) combined checked world matrices, mesh primitives and material IDs into 11,311 draw descriptors across the complete cache. Its separate x86_64 command-line smoke check ran on the 16 KiB API 37.2 AVD, read an owner-supplied candle BRES, returned two draws/four triangles and exited zero with matching input hashes. ARM64 and x86_64 libraries were built with 16 KiB-aligned load segments. The source Android asset renderer subsequently integrated checked static draw commands. Its new exact APK (184,864 bytes, SHA-256 `ce7963e3fc2d117c07ec88ccccca88e350589f19397401a4029b44c5d7b247c0`) installed on the 4 KiB API 37.0 AVD. It loaded the owner's candle BRES, reported two draws/eight vertices/twelve indices, decoded a matching 1024×1024 PVRTC texture, and displayed the crypt background and candle flame together with the process alive. See [`port/android-app/scene-runtime-validation.json`](../port/android-app/scene-runtime-validation.json). This new APK was not run on 16 KiB or ARM64, and a static imported scene is not gameplay.

The later rotatable 3D source viewer APK (184,864 bytes, SHA-256 `bafa791956c50cd58f19d947df416ece7c29f2113b6cd4c8b13589979f970d99`) was installed on both the API 37.0 4 KiB and API 37.2 16 KiB AVDs; pulled installed APK bytes matched the build output on both. It imported the owner's `void_maze.bdae` (77 checked static commands, 3,140 vertices and 4,695 indices), decoded `env_voidmaze.tga` to 256×256 pixels, and visibly displayed textured stone maze geometry on each. A touch drag rotated the view; each process stayed alive. The candle scene also rendered on this same APK during the 4 KiB check. See [`port/android-app/scene-3d-runtime-validation.json`](../port/android-app/scene-3d-runtime-validation.json). The projection, camera and common texture application are diagnostic choices; there is no gameplay, animation or level streaming. ARM64 runtime was not tested.

## Experimental 16 KiB compatibility work

The standard Test 10 wrapper still guards against 16 KiB pages. The first isolated translator build passed guest linker/JNI/engine startup but aborted during graphics startup with a Scudo corrupted-chunk error after repeated 4 KiB-aligned `madvise` requests reached the 16 KiB kernel. A later unsafe broad-zeroing diagnostic reached a saved level; it was not kept as a deliverable. The [strict follow-up](../compatibility/16k-port/README.md) tracks guest mapping origin and zeroes only proven private-anonymous guest pages for `MADV_DONTNEED`. Its 35 focused component checks passed on the 16 KiB emulator. The signed Test 10/strict-bridge APK (SHA-256 `80ff275679368ab0141aa445654c033d5619b3f77fb37e3beaf52c6c894e0f90`) reached a full-width interactive title and character menu. Its first run was interrupted by an external replacement of the installed APK. On a separate uninterrupted rerun, the same strict package loaded a saved Swamps 3D level, a joystick swipe visibly moved the player and camera, pause opened, and Main Menu → Yes returned to the character menu with an updated last-save timestamp. The guest process remained alive. Screenshots of movement, pause and saved menu are retained in the task outputs.

An additional check installed that exact strict APK again on the 16 KiB emulator (`versionCode=13`, `primaryCpuAbi=arm64-v8a`) and force-stopped it during its opening sequence. A cold relaunch loaded the ARM64 proxy and all three guest libraries without crashing. After `LoadingStep_LoadBackground 2` and `In Intialize...111...`, the splash spinner and busy guest GL thread persisted for over two minutes. A second cold run with **Keep graphics context during cinematics** enabled retained the EGL surface and showed the same slow loading. Earlier successful 16 KiB logs revealed that this phase can take roughly four to five minutes before shader work appears. The second cold run did advance to shader processing, reached `menu_splash` about five minutes after the marker, accepted a title tap, and displayed the full saved-character menu with the previously saved `PlayerLastSave = 02.10. 02:11`. A further cold run with the default graphics setting also visibly reached the full saved-character menu with that same save time and accepted Start Game → Single Player, then loaded the saved Swamps 3D level to 100%, displayed the HUD, and moved the player/camera after a joystick swipe with the guest process alive. Thus the two-minute observation was premature: the checkpoint metadata and bounded gameplay return survived process restart. Long sessions, complete save semantics and real ARM64 16 KiB behavior remain unverified. The unrelated ABI crash initially observed during this check came from an older Test 6 package accidentally installed on this emulator, not the strict Test 10 build. The strict source guide records its code-level blockers.

The verified Android 17 result includes source-built textured rendering on the 16 KiB image and short interactive original-game combat/movement on the 4 KiB image. It is not full game completion, broad device compatibility, or a completed ARM64 source port. The original ARM32 engine remains in the compatibility APK. See [the page-size assessment](ANDROID-17-PAGE-SIZE-ASSESSMENT.md) for the memory model and unresolved integration work.
