# Canonical runtime owners: first source handoff

This is a partial callable-source handoff for the generic loader's receiver adapters. It does **not** prove complete construction, eligibility, animation, restoration or loading of all 50 Characters and five OpenableContainers in SWAMP.

`CanonicalObjectManagerV1` owns the actual signed-key map and retained receiver leases. `CanonicalObjectFactoryAttemptV1` preserves the original construction/Add/property/template/default/XML-override/LevelConfig-early-InitPost/position-offset sequence and the reached prefix on failure. Source IDs and shared handles are borrowed from one receiver; XML/module occurrence numbers are diagnostic only.

`RetainedCharacterActorV1` extracts the sole script, FSM, controller, animation and runtime owners behind the current renderer's Monster receiver. It pins the world context and exposes its same shared handle, type and room. This extraction is not yet the complete source Character InitPost coordinator or a migration of every existing renderer instance.

`OpenableContainerOwnerV1` reads the actual original 68-row table and implements the source chest state, animation-event, key, world-drop, script and sound call sequence. `openable_container_interaction_v2` adds the outer unlock, hosted event and achievement sequence. World drops require the original drop/spawn receiver and the same loot RNG; direct inventory insertion is not that implementation.

`CharacterCollisionLifecycleV1` and `native_physical_filter_v1` now connect the player joystick's genuine Stop/CharAI-event3f callback to its actual physical filter and navigation obstacle. This runtime path has been tested in the visible5554 game; NPCs should delegate their existing physical filter owner rather than create a second one.

Remaining receiver work: shared PropertyMap descriptors over the actual mutable base/class fields; complete class constructors and InitPost/condition ordering; retained visual/timeline/physical bindings; world ItemObject creation/drop lifecycle; failed-candidate cleanup and restoration/commit. Do not accept provider absence as successful initialization or force authored conditions true.

Current evidence: strict Android compilation and linking for ARM64 and x86-64; separately executed Android native factory/Add fixtures and chest state/outer interaction fixtures under `port/level-world/reports/android-native-owner-tests`. Those fixture results prove the declared service compositions, not production class construction or whole-level acceptance. Original constructor and property declaration captures are under `port/level-world/reference/canonical-object-factory-v1`.

The loader remains responsible for adapting the retained XML/module context described in its `OWNER-CONTEXT-REQUIREMENTS.md`, keeping candidate and committed worlds separate and verifying all nine SWAMP modules with eligibility reported separately. Its recovered map inspection route remains distinct from the canonical class runtime.
