# Canonical OpenableContainer receiver handoff

`port/level-world/canonical_openable_container_v1.hpp/.cpp` composes one retained
`CanonicalGameObjectBaseOwnerV1` with the caller's sole `actor::RuntimeState`.
The factory must retain the returned receiver lease and use `canonical(lease)`
and `properties()`; it must not create another GameObject field projection.
Factory class-name assignment writes the same `class_name20` exposed to the
PropertyMap. Actual source GO_ID is 7; catalog index 25 is a different value.

The derived constructor stores source byte28=1, static84=0, bytef8=2. Source
pointers100/104 borrow two actual owned `ContainerNetStructV1` graphs. Each
declares the original three members in masks 1, 16, 32 order, retains the source
metadata defaults, and has an empty tree header whose left/right point to its
own sentinel. These are native semantic owners, not foreign ARM vtables or a
network transport implementation. Serialization, incoming merge and network
dispatch remain required services when their original branches are reached.

Evidence: `reference/openable-container-v1/net-struct-constructor-source.asm`
and `net-base-source.asm` capture Container ctor39ff58, NetStruct ctor8138f4,
DeclareMember81324c and PopulateOutgoing3a0110. Fresh native member value storage
starts at zero; this fixture does not claim allocator-residue equivalence for
the source ctor's conditional SetChanged call on prior nonzero storage.

Strict Android ARM64 C++17 syntax with `-Wall -Wextra -Werror` passed for owner
and `tests/canonical_openable_container_v1.cpp`. The fixture checks same handle,
runtime, class-name and property aliases, actual constructor fields/member
graphs, and an explicit required-service failure from unbound InitPost. Root
performs the executable Android validation; this document does not claim its
runtime result in advance.

Actual resource audit additionally supplies
`tests/openable_container_visual_cache_v1.cpp`, which takes the directory of
the three exact chest BRES resources extracted under
`reference/openable-container-v1/cache`. Resource provenance is recorded in
`chest-visual-cache-hashes.json`. The test uses the complete original Scene and
existing source marker resolver; unsupported marker topology is a failure.
It reports actual marker bounds and scale for the next PODecor binding.

No factory scene, physical body or timeline event is generated by the canonical
constructor. Generic visual construction is root-owned. The chest animation
adapter preserves original base SetCallbacks474d10 (`bx lr`) and does not
synthesize `opened` or completion events. Same-world loot creation uses the
existing LootCreationV8 and DropAwardV8 pool path rather than Gear insertion.
