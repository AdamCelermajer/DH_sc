# armdiff sweep, 2026-10-16 (verification owner V)

Every ledger row with status `reconstructed` that armdiff can run, against the original `libDungeonHunter2.so` (SHA-256 `36498eb8...`),
on the working tree of 2026-10-16 (about 19,600 ledger rows; other waves kept editing it, so the row counts differ by a few between the
two runs). The ARM32 side was rebuilt first (NDK clang, `armv7a-linux-androideabi21`, ARM mode, soft-float, `-O1`); 48 cases per function,
extended while coverage grows, seed 1. Files in this directory: the per-category CSVs (run 1 `<category>.csv`, run 2 `<category>-with-imports.csv`),
`all-summary.csv` and `all-summary-with-imports.csv`, `triage-sweep-2026-10-16.csv` (one line per mismatch of run 2, with the class and the first
difference), `callee-recon-sample.csv` (part 3). `tools/trackb/armdiff/README.md` has a short "Changes of 2026-10-16" section.

"of which <= 8 bytes" counts matches of functions of 8 bytes or less (`bx lr`, a constant return, a single store: a wrong reconstruction can pass them
too), "match, real bodies" the others, as TRACK-B.md decision 11 asks. "excluded" is every selected row the run did not execute. In run 1, 15,281 of the
16,329 are rows whose original body makes calls (out of scope of `--no-call-only`); in run 2, 14,045 are call shapes `internal` or `indirect` (they need
`--shape any`). The rest of run 2, by cause: "no definition of ..." 902 rows (template instances the reconstruction does not emit under the original's mangled name: `IMaterialParameters` 258,

(every case inconclusive) 69, 61 rows that call `fprintf` (no model), 78 rows of sources with no ARM32 build.

game-world units); they are excluded, not mismatches.

At the start of this task run 1 had 364 mismatches (2,819 matches, 1,961 of 8 bytes or less) and run 2 had 693; after the fixes below they have 323 and 630,
and 58 of the 364 run-1 rows match now (the counts include rows other waves added meanwhile).

## Triage of the 625 distinct mismatching addresses of run 2 (630 rows; the 323 of run 1 are a subset)

Every mismatch was re-run with `-v` (all cases, not only the first), classified by rule, and each rule was checked against the disassembly of at least one
member. `triage-sweep-2026-10-16.csv` has the class, the number of mismatching cases and the first difference for each row.

| verdict | class | rows | meaning |
|---|---|---:|---|
| harness artefact | A-void-return | 89 | the original leaves an unspecified r0 (it returns nothing, or a leftover argument); the reconstruction returns a constant (`IAnimationTrackEx` defaults, `CVirtualEx::getBlendedValue/getAddedValue`, ...) |
| | A-fault-order | 99 | every valid case is equal; only the faulting address on a null pointer differs (order of the accesses, or a fault inside a modelled `memset`/`memcpy` against an inlined store) |
| | A-uninit-table | 67 | `Structs::GetMemberIDByString<T>`: the original name tables are filled by static initialisers, which armdiff does not run |
| | A-static-local | 49 | function-local statics (`getInstance`, guard variables): each image has its own |
| | A-vtable-prefix | 23 | constructors with a VTT or virtual base: GCC and clang lay out the vtable group differently, so the stored vptr values differ |
| | A-abstract-D1 | 21 | clang emits a trap for the complete-object destructor of an abstract class; the original is `bx lr` |
| | A-abi-align | 14 | the binary aligns the double of `gameswf::as_value` to 4 (the value is 12 bytes); the ARM32 build aligns it to 8, which moves every member after an `as_object` by 12 |
| | A-clone | 11 | GCC clones with a folded argument (`Random::GetRandom` .clone.N): armdiff calls them with the base signature |
| | A-bool | 9 | clang assumes a `bool` byte is 0 or 1 (`cmp #1`, `and #1`); the buffers hold other values outside the typed region; the original tests `!= 0` |
| | A-image-pointer, A-abi, A-sret-abi, A-garbage, A-oob-index | 12 | returns an address of its own image; `char` passed zero-extended where the original expects sign extension; hidden result pointer; null or assert paths; index past a table |
| STL layout | C-stl | 113 | the offset difference is the size difference of STLport and libc++ members before it (`std::string` 24/12, `std::wstring` 72/12, `std::map` 24/12, `std::list` 8/12, `std::vector<bool>` 20/12). 53 are proven by `stl_expected_delta()` on the compiled layout (class and member in the CSV note); the others by a class-level rule (`ObjectBase`, `GameObject`, `ISceneNode`, `IGUIElement`, `SimpleTypeProperty`, `NetStruct`, `CMessage`) |
| intended deviation | B-representation, B-benign-init, B-safety-guard | 62 | documented in the source or the header: a vector instead of raw arrays (`GLXPlayerUserFriend`, `CVertexStreams`, `SBlitJob`), members the original leaves unwritten that the reconstruction zeroes, bounds and null guards the original lacks |
| unresolved | U-unresolved | 56 | cause not established |

Unresolved by category: core-platform 1, game-world 8, glitch-core-io 6, glitch-scene-collada-gui 18, glitch-video 9, net-session-online 7, net-transport 2, vendor-gameswf 4, vox-audio 1. They are float functions with a single deviating case
(`getInverse`, `transformPlane`, `intersectsWithLine_impl_1d`, `getLowestRoot`, `ConvertFloatToShort`, `matrix::transform`: NaN or negative-zero edges; the same kind of
error was found and fixed in `PDBox::within` and `getRotationDegrees`, see below), objects whose layout is wrong behind a member the STL table cannot size
(`PlayerManager`, `PlayerInfo`, `CMaterial`, `CImage`, `CLobbyParameterAndQuery`, the `CColladaDatabase` tables), and fault-only differences on garbage state. None of them
is classified as a reconstruction error, so none is demoted.

## Reconstruction errors found and fixed (decision 11: a layout error is fixed once, at the base)

- `core-platform` TouchScreenBase: the slot record is 0x30 bytes with `mark_` as its trailing word (slot 0 starts at the vptr), the event queue is a `std::vector`
  (queue indices at +0x1a0/+0x1a4), and `hasTouch` lacked the `mark_ == 0` test of the original (a wrong body). 8 rows.
- `game`: GSInit (missing word at +0x0c, 2 rows), `EventManager` (word at +0x04), `ObjectManager` (the map was declared before the list: member order).
- `glitch-core-io`: `IReadFile` is 12 bytes in the original, and `CMemoryReadFile`, `CReadFile`, `CLimitReadFile`, `StreamBuffer` start their members at +0x0c (4 rows directly);
  `CAttributes` lacked the words at +0x48..+0x54 (so `CSceneManager` and everything embedding it were short); `IAttribute::getMatrix` did not set the identity flag.
- `pydata-accessors`: nine `Structs::*Ref`/`Item` records declared a second `m_w1` that `ItemBase` already has, so `sizeof` was 0xa8 against 0xa4 (`ItemInstance::GetItem`, `GetIconName`).
- `net-transport`: `CMutex`/`CSemaphore` keep their counter at +0x04; `CSocketAbstract::can_open_` is at +0x09 (it was in the derived class at +0x0b);
  `Connection` word at +0x0c; `NetStruct` member order and size (byte at +0x108, the map before `enabled_`); `StreamBuffer::size(int)`, `seek`, `seekWrite` read the
  size member, not the virtual (3 rows); `DataPacketLobby` positions are `int` (signed compares, 4 rows); `NetBitStream::WriteBit/ReadBit` conditions as in the listing (2 rows).
- `net-session-online`: `CMessage` member order and a word at +0x44, `CMatching` words at +0x04, +0x18, +0x20, `GameCenter` member order.
- `vendor-gameswf` `render_handler_glitch`: the driver `SRenderState` is 0x24 bytes at +0x14; seven duplicate members after it removed (7 rows).
- `glitch-video`: `SShadowRenderState` bytes +0x05..+0x07, `IDataInfo` is 16 bytes (3 rows).
- `glitch-scene-collada-gui`: `CBatchMesh` kept two extra words that are the end and capacity of the vector at +0x2c (5 rows);
  `IParticleEmitter/IParticleAffector::deserializeAttributes` return 0, not the index (2 rows).
- `vox-audio`: `VoxNativeSubDecoder` members in offset order, the `RandomGroup` list sentinel is 8 bytes, `WaveChunk` 16-bit fields (6 rows).

Bodies that were wrong because Hex-Rays prints doubles rounded to about 10 digits and shows `x >= a` for the listing's `!(x < a)`: `vector2d<float>::getAngle` (returns a double;
the 180/90/270 early returns that Hex-Rays drops; 180/pi = 0x404ca5dc1a63c1f8), `vector3d::rotateXY/YZ/XZBy` (pi/180 = 0x3f91df46a2529d39) and `getHorizontalAngle`,
`PSRandom::Rand` (divisor 2147483647.0, not 2147483650.0), `PDBlob::PDBlob` (all float: 1e-12f, 0.39894228f), `CMatrix4::setRotationRadians` (products in double),
`CMatrix4::getRotationDegrees` (`!(|cos| > 1e-8)`: a NaN pitch takes the gimbal branch), `PDBox::within` (rejects on `<` and `>`, so NaN is inside). The truncated pi in `PDomain.cpp` and
`driver_callback_spatial.cpp` was replaced too. Any body with such a constant or comparison is worth an armdiff run.

No row was demoted: every real error found had a clear local fix, and the 56 unresolved rows are not triaged to an error. No ledger part was written
(`ledger.d/ov-*.csv` does not exist). `check_tu.sh` is OK on every touched source and on up to four includers of each touched header (68 translation units).

## Part 3: `--callee recon`

`run.py --shape any --callee recon` binds every call that leaves the translation unit to the reconstruction; it already existed. Sample: 200 rows of shape `internal`
(original size at most 600 bytes), a seeded `random.sample` of a pool of 9,219 rows (`callee-recon-sample.csv`): 21 match, 29 mismatch, 150 excluded.
96 of the excluded are "too few comparable cases": with garbage inputs the callee dereferences objects that do not exist, so every case is inconclusive. The binding works for functions
whose callees are accessors and helpers; functions that walk object graphs need fixture objects (a per-callee policy table), which is the open work.

## Tool changes

`cases.py`: the typed fill descends into fixed arrays (`T[N]`, `std::array<T,N>`). `run.py`: the STL size table (wstring 72/12, map and set 24/12 with the `pad_` rule, `vector<bool>` 20/12).
`build_arm.py`: `DH2_ARMDIFF_OUT` and `DH2_ARMDIFF_PACK` (a `-fpack-struct=4` build was tried because the binary aligns the `as_value` double to 4; it lost matches, 2,701 against 2,863,
and is off by default). Header-unit results are rebuilt only by a run that builds: after editing a shared header run `--shape default` without `--no-build`.
