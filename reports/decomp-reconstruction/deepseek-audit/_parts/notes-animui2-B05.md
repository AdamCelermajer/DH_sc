## Summary

- Rows audited: 25 of 25 (game-anim 4, game-ui 21). Verdicts: 25 clean, 0 findings, 0 unreadable.
- Findings by severity: high 0, medium 0, low 0.
- Rows not judged: none.
- Documented deviations seen and NOT reported (ledger `notes`, so by rule not bugs):
  * 0x36820c and 0x435ae8: the override is void while the original returns a float/int (callback result / 1 on the early exits). No caller reads it.
  * 0x7aa0ec: the original returns whatever r0 holds; the port returns 0.
  * 0x7aadf8: the original steps past the end of the request string when the last segment matches without ending the path; the port ends the entry's try there.
  * 0x421e48: 64-name stack instead of the original 38 (the original has no bound check).
  * 0x477a80 / 0x477cd4: Hex-Rays shows AnchorBase() with no arguments in C1; the assembly passes the object and the type, as the port does.
  * 0x476b4c / 0x476ddc: the BlendedAnimSetController.cpp:69 assert is a comment.
- One difference deliberately not reported: 0x453974 RenderIconType returns early for an icon type outside 0..17, where the original prints the assert and then indexes out of bounds (undefined behaviour in the original; the same convention is documented for DuplicateIcon in the same class). No gameplay effect on any valid icon type.
- Method notes: the queue's recon_span was stale for some rows; every function was re-located by its `// 0x<addr>` comment and the CURRENT lines are cited in the row notes above. The `lead=const:...` hints for these rows are all struct offsets, array indices, allocation sizes or float bit patterns (e.g. 0x476b4c const:208 = operator new size, 0x4187a0 const:21..17 = the position array indices, 0x454a08 const:90,89,88 = the GameObject position words, 0x435ae8 const:4414184 = 1/128), not values the bodies must contain.
