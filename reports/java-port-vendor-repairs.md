# Vendor Java reconstruction repairs

The editable Java trees `port/android-java/java/com/kddi` and `port/android-java/java/com/samsungapps` were repaired against the original APK's smali and raw JADX export. The unchanged recovery artifacts remain the authoritative bytecode evidence. These repairs affect 53 Java source files relative to the normal JADX export used to stage the editable port.

Compilation alone is not a proof of behavioral equivalence. This audit records source fixes with identifiable bytecode evidence; it does not claim that legacy account or billing services work on current Android.

## Verification

1. The 85 staged vendor Java files compile with JDK 17 (`--release 17`), Android API 35's `android.jar`, and its optional `org.apache.http.legacy.jar`. Deprecated API and unchecked-operation warnings remain. For isolated vendor compilation, a scratch-only dependency defining the real Gameloft `Tracker.f = "A"` compile-time constant was used; that dependency stub is not in the repository and is not part of any delivered source or build.
2. `tools/tests/VendorBase64RecoveryTest.java` compiles and runs on a plain JDK 17 with only the recovered Base64 and its recovered base class. It compares 16,384 deterministic randomized vectors against `java.util.Base64`: all 16 combinations of padding, wrapping, CRLF and URL-alphabet flags, for lengths 0 through 1023. It also checks encode/decode byte-range overloads and rejection of seven malformed-padding inputs. This test caught the read-before-increment decompiler defect and passes after the smali-backed repair.
3. As supplementary validation of the parent agent's Gameloft billing codec repairs, `tools/tests/GameloftBase64RecoveryTest.java` also passes: RFC-style known vectors, explicit standard/web-safe alphabet checks, 3,072 deterministic randomized padded/unpadded encode/decode cases across lengths 0 through 1023, byte-range decoding, and six malformed-input rejection cases. This test compiles with only the recovered Gameloft Base64 and its recovered checked exception class, without Android dependencies.
4. Standalone test instructions are embedded at the top of the Java test source. No Android mock, network dependency, payment backend, or external account is required for that test.

## Remaining limits

The vendor libraries depend on historical KDDI authentication services, Samsung Apps billing protocols, private device data, and deprecated Android APIs. Those service integrations have not been exercised on a physical modern Android device. The XML parser reconstruction is bytecode-reviewed and compile-checked but has not been runtime-tested against a historical billing server. Host Base64 vectors validate only the recovered codec; they do not establish full-game or whole-library equivalence.
